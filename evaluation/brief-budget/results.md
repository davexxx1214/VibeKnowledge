# 第三项：有限预算优先保留行为约束

日期：2026-09-05。结论：在这批既有简报中，同预算能返回更多约束/测试事实；默认预算正文略少。但这不是完整 Agent 任务准确率或省 token 的新证明。

## 实现

仅调整 `featureBriefQuery.ts` 的简报取舍顺序，并补充生成/查询说明：

1. 保留首条限制和入口的优先位置。
2. 先尝试约束、测试、功能、依赖各一条，再按这些类别轮流补充；框架背景最后尝试。同类别保持作者顺序，不按关键词猜测风险等级。
3. 每条事实的原文、certainty 和完整证据一起保留或省略，不截断事实，不改写结论。生成规范补充“拆开独立行为，但不拆掉前提、限定或证据”，并要求同类中影响修改决策的事实靠前。
4. 继续报告未展示的类别，另外给出 `Unshown constraint/test facts: N/M`，包括只展示了该类别一部分的情况。没有自动生成遗漏事实的语义标题，以免未经核查地再次概括。

默认简报预算仍为 1800，最小值仍为 600。CLI 与 MCP 共用实现，不增加 schema 字段、筛选参数、会话状态或新节点。索引匹配、新鲜度检查、方法级 `context` 均未改。生成说明有更新，但本轮没有重新生成简报或测试作者行为；测量仅隔离查询算法。

## 对照设计

修改前冻结当前实现、卡片/引用文件哈希和全部输出。使用八份留存简报：VibeKnowledge 两份、Yuxi 前端五份、上轮合成 Shelf 样例一份。共 82 条事实，其中约束 22、测试 6、功能 24、依赖 23、框架 7。

每份简报分别使用 600、900、1200、1800、2400、12000 六档预算，共 48 个配对查询；每档均保留全部八份。比较完整“事实 + certainty + 证据”块，而不是只搜关键词。token 为 `o200k_base` 正文计数，与程序的近似预算算法不同。

这些是已使用过的开发快照，不是新验证集。Yuxi 只是复用样例数据，没有恢复此前回退的 Yuxi-inspired 排序/筛选方法。旧评测产物与评分未被刷新。卡片语义真伪未重新评分，哈希一致不能证明其中每条断言正确。

## 全部预算结果

每行都是八份简报之和。“约束/测试”是返回的完整事实数量，不是覆盖率或准确率。

| 预算 | 约束/测试：前 → 后（共 28 条） | 正文 token：前 → 后 | 正文变化 | 新展示 / 不再展示的事实 |
| --- | ---: | ---: | ---: | ---: |
| 600 | 2 → 11 | 3,433 → 3,433 | 0.0% | 9 / 10 |
| 900 | 8 → 12 | 5,393 → 5,139 | -4.7% | 4 / 9 |
| 1200 | 13 → 20 | 7,007 → 6,808 | -2.8% | 8 / 9 |
| **1800（默认）** | **23 → 26** | **9,874 → 9,815** | **-0.6%** | **6 / 5** |
| 2400 | 26 → 27 | 11,261 → 11,253 | -0.1% | 1 / 1 |
| 12000 | 28 → 28 | 11,633 → 11,633 | 0.0% | 0 / 0 |

默认预算下，新增 3 条约束、2 条功能和 1 条依赖，替换掉 5 条框架事实；三份简报的约束/测试数量增加，另五份持平。600 预算下八份都增加约束/测试，代价是少显示 3 条功能和 7 条依赖；依赖类事实总数由 7 降到 0。**因此不建议把 600 当成理解功能的完整简报。** 摘要和首个入口仍保留，但不能替代已省略的事实。

在这 48 个配对中，没有失去原先已展示的约束/测试事实，但其他类别确有取舍。充分预算下，82 条原事实和证据全部保留；输出顺序改变，正文 token 总数相同。

在六档采样预算中，让全部约束/测试出现的首个预算，六份简报下降一档，Copilot 与图谱可视化两份持平。这只是离散检索代理指标，不是精确最低预算；尤其图谱可视化的 2400–12000 区间未做二分搜索，也没有测再次查询与上下文重放成本。

## 能与不能证明的收益

- 可以证明：该默认取舍策略把更多预算用在已有约束和测试说明上，特别是避免低预算只看到正常功能和实现背景。
- 不能证明：Agent 最终答案更准确、理解整体更全面、完成修改更快，或累计模型用量减少。此轮没有下游任务 A/B，也未计入新增生成指导、必要源码复查或补读框架信息的成本。
- 分类本身有限：入口、权限或关键前提也可能写在 capability/dependency 中。不能把所有 constraint 自动等同于最高风险，更不能把所有 framework 当成无关内容。旧简报的错误不会被重新排序修复。
- 更短正文可能来自整块装不下而省略，并不一定意味着信息压缩更好。保留当前默认 1800；看到相关类别或部分约束/测试省略时，仍需增大预算或定向查源码。

- 根项目 `npm run check`：36 个文件、269 项测试通过；编译通过；lint 61 条现存警告、零错误。
- MCP 构建通过；12 个文件、143 项测试通过。
