## 1. Visualization

### Command, data and page interaction

The contributed **Knowledge: Visualize Graph** command is also a navigation action on the Knowledge Graph Explorer. Its extension-host handler calls `GraphView.createOrShow(context.extensionUri)` and catches opening failures with an error notification (`package.json:57-59`, `package.json:243-246`, `src/extension.ts:642-652`). Activation injects the knowledge and structural services (`src/extension.ts:242-243`). `GraphView` creates one script-enabled, retained-when-hidden panel. An existing panel is revealed and sent graph data; its HTML is replaced only when the translated title differs. Disposal clears the singleton (`src/ui/webview/graphView.ts:157-203`). The browser initializes its D3 graph on `load`, sends `ready`, and the host responds with the current performance preference and graph data (`src/ui/webview/graphView.ts:205-222`, `src/ui/webview/graphView.ts:1205-1208`).

Ordinary views come from `KnowledgeGraphService.getGroups()` with entity observations, not its deduplicated aggregate snapshot. Framework/module/feature groups deliberately preserve repeated symbols in separate views. Their upstream curated data is the Agent sidecar `.vscode/.knowledge/agent-graph.json`, not the raw structural graph (`src/ui/webview/graphView.ts:456-490`, `src/services/knowledgeGraphService.ts:147-173`, `src/services/agentGraph/agentGraphService.ts:87-118`). The browser sorts groups by order and then name, builds buttons showing kind and entity/relation counts, and renders only the selected group. A received group list retains the selected key if present, otherwise selects its first group. A click saves the key through `vscode.setState` and renders that group (`src/ui/webview/graphView.ts:1372-1399`, `src/ui/webview/graphView.ts:1423-1462`). Thus replacing group data is not just updating labels: it can choose a different view and reconstruct its SVG/physics.

The advanced control separately offers Boundary, Community and File levels; clicking its button sends `requestStructuralOverview` with the chosen level (`src/ui/webview/graphView.ts:1101-1106`, `src/ui/webview/graphView.ts:2091-2095`, `src/ui/webview/graphView.ts:2173`). The host reads `StructuralGraphService`, aggregates at most 80 nodes, converts the result to a display group, and sends `structuralGroup`. The client removes prior `__structural_` groups, appends and selects the new one, and displays its counts (`src/ui/webview/graphView.ts:324-338`, `src/ui/webview/graphView.ts:446-454`, `src/ui/webview/graphView.ts:1287-1298`, `src/ui/webview/graphView.ts:1401-1413`). This is a temporary additional view, not a replacement written to curated groups.

Node and relationship interactions depend on retaining their distinct identities and provenance:

- Hover highlights adjacent nodes/edges and displays entity observations. Ordinary double-click navigates to the curated entity; Shift-double-click, or its context menu when a structural key exists, requests structural neighbors. Aggregate double-click requests its raw slice; structural-node double-click navigates by structural key (`src/ui/webview/graphView.ts:1729-1796`).
- Neighbor expansion uses both directions at depth 1, deduplicates relations and caps the slice at 80 entities/120 relations, filtering edges to retained endpoints. Aggregate expansion uses its selected files, file identity or boundary matching, then applies the same caps (`src/ui/webview/graphView.ts:365-439`).
- A relation with `structuralPath` supports drilldown; the host matches those hop identities against current raw relations. Tooltips expose relation origin, confidence and source evidence (`src/ui/webview/graphView.ts:340-359`, `src/ui/webview/graphView.ts:1599-1611`, `src/ui/webview/graphWebviewClientScript.ts:8-36`). Aggregation excludes within-group edges and keeps at most eight sample relations per aggregate edge; the displayed count therefore does not promise that drilling into that edge shows every counted relation (`resources/skills/vibeknowledge-dependency-graph/scripts/structural-analysis.mjs:416-427`, `src/ui/webview/graphView.ts:549-559`).

### Responsiveness, animation and retained state

The performance setting defaults to `low`, accepts `low`/`high`, and has machine scope (`package.json:325-338`). Selection immediately changes the body class and rerenders the current group, disables the selector, and posts `setPerformanceMode`. The host validates the value, writes the global preference, and always sends back the actual configured mode. Settings changes also send it. A failed save reports an error and the reply restores the actual mode/re-enables the selector; changing mode does not request a different graph dataset (`src/ui/webview/graphView.ts:150-154`, `src/ui/webview/graphView.ts:300-321`, `src/ui/webview/graphView.ts:1283-1285`, `src/ui/webview/graphView.ts:2077-2084`, `src/ui/webview/graphView.ts:2176-2182`).

Low mode stops D3's automatic simulation and explicitly computes short animation-frame batches. Each batch yields after approximately 6 ms of tick work; the layout completes on cooling, 120 ticks or 600 ms accumulated compute time. Because `tick()` does not emit D3 tick/end events, the helper explicitly renders each batch and calls completion to fit/save. These are cooperative limits, not a hard bound on one expensive tick or a total wall-clock deadline (`src/ui/webview/graphPerformanceScript.ts:46-88`, `src/ui/webview/graphView.ts:1931-1939`). Low-mode drag stops settling, moves just the selected node and redraws its affected geometry without restarting physics. High-mode drag reheats physics; both release fixed coordinates and save the layout (`src/ui/webview/graphPerformanceScript.ts:91-118`, `src/ui/webview/graphView.ts:1950-1959`).

High mode retains force animation, particles, relation flow and glow, while low mode disables those visual effects and CSS transitions. Hover and fit are immediate in low mode versus animated in high mode (`src/ui/webview/graphView.ts:1080-1086`, `src/ui/webview/graphView.ts:1591-1594`, `src/ui/webview/graphView.ts:1617-1656`, `src/ui/webview/graphView.ts:1721-1732`, `src/ui/webview/graphView.ts:2073-2074`). High does not necessarily restart an already settled cached simulation: cached settling state and alpha influence whether it starts (`src/ui/webview/graphView.ts:1556-1578`).

| Transition | Source-backed behavior and persistence boundary |
| --- | --- |
| Switch group or performance mode | Before removing old geometry, rendering stops old work and saves its layout. The new group restores positions and zoom/pan transform if its cache signature matches; otherwise its transform resets. Cache entries include alpha, settled and auto-fit state. The saved closure captures the old group's data and simulation, preventing its geometry from being stored under the newly selected group (`src/ui/webview/graphView.ts:1480-1493`, `src/ui/webview/graphView.ts:1552-1579`). |
| Return to a cached group | Cache keys are group-specific; validity depends on sorted node IDs and source/target/verb edge topology, not prose. It stores only x/y positions, transform and settling state—not source/evidence objects, velocities or permanent pins. Default limits are eight groups and 2,000 total nodes; oversized/nonfinite layouts are rejected and least-recently-used entries evicted. Restoration is consequently conditional, not durable storage (`src/ui/webview/graphPerformanceScript.ts:7-43`). |
| Hide then show the existing page | Retained context keeps JS/cache/groups. `visibilitychange` pauses particles and static work, stops simulation, interrupts SVG transitions, clears fit/resize timers and saves geometry. Showing resumes unfinished low settling, or high simulation only while alpha exceeds its minimum, and resumes eligible particles (`src/ui/webview/graphView.ts:175-176`, `src/ui/webview/graphView.ts:1234-1270`). |
| Invoke the command on an existing panel | The panel is reused, but the command also sends ordinary graph data. That preserves a valid ordinary key/cache, yet replaces a temporary structural group with the curated group set; its missing selected key falls back to the first ordinary group. Merely showing a hidden tab is therefore not equivalent to invoking the command again (`src/ui/webview/graphView.ts:157-165`, `src/ui/webview/graphView.ts:1287-1294`, `src/ui/webview/graphView.ts:1372-1410`). The page's Refresh button has the same data-replacement consequence (`src/ui/webview/graphView.ts:219-222`, `src/ui/webview/graphView.ts:2086-2089`). |
| Replace HTML, close, or reopen after disposal | Every new document constructs a new in-memory cache and reads only `selectedGroupKey` from Webview state. Only that key is explicitly written to Webview state; performance lives separately in global configuration. Title-driven HTML replacement loses document-local geometry/temporary groups, although a supplied Webview state key can be reused if present in new data. Closing clears the singleton; there is no application-level geometry persistence in these paths. Inference: do not promise selected-view restoration across a disposed panel/editor restart from these mechanisms alone (`src/ui/webview/graphView.ts:161-203`, `src/ui/webview/graphView.ts:1138-1150`, `src/ui/webview/graphView.ts:1453-1454`). |
| Receive no groups | The page stops simulation/layout/particles, clears the cache and geometry, sets the in-memory key to null and shows empty state. This branch does not itself overwrite Webview state with null (`src/ui/webview/graphView.ts:1378-1393`). |

Auto-fit is another part of “remembering the view”: user zoom/pan and drag disable automatic fitting, while unfinished layout stores its remaining auto-fit intent. Low completion fits once; high schedules a one-second fit only while permitted/visible. Resize is debounced, changes the center force, then fits directly in low mode or reheats visible high simulation. Hiding clears the high-mode fit timer without explicitly recreating that timer on show—an integration boundary worth preserving or deliberately redefining (`src/ui/webview/graphView.ts:1210-1230`, `src/ui/webview/graphView.ts:1254-1268`, `src/ui/webview/graphView.ts:1360-1367`, `src/ui/webview/graphView.ts:1933-1957`). Unloading stops work and clears timers (`src/ui/webview/graphView.ts:1272-1278`).

### Correctness boundaries and existing tests

The host/page protocol, D3 SVG/force/zoom behavior, embedded performance helper and tooltip helper, localization, and the two graph services form the immediate change surface. D3 is loaded from extension-local `dist/d3.min.js` under a nonce-based CSP, rather than fetched by the page; the manifest's D3 and VS Code versions are declared ranges, not runtime measurements (`src/ui/webview/graphView.ts:718-754`, `src/ui/webview/graphView.ts:1137-1141`, `src/ui/webview/graphView.ts:1566-1573`, `package.json:26-29`, `package.json:479-482`). Replacing simulation or cache behavior must preserve cancellation of old callbacks, correct per-group identity, fresh evidence alongside reused coordinates, unfinished settling, user-controlled transforms and zero-size fit guards (`src/ui/webview/graphView.ts:2053-2074`).

Failure states are distinct: absent/unreadable/invalid Agent sidecar data becomes an empty snapshot, with no generation-error field on the graph-data message; structural read/unavailable-service errors produce a status message plus VS Code warning, leaving existing graph data in place; render exceptions stop work and expose a dedicated error panel (`src/services/agentGraph/agentGraphService.ts:232-260`, `src/ui/webview/graphView.ts:263-274`, `src/ui/webview/graphView.ts:324-338`, `src/ui/webview/graphView.ts:450-454`, `src/ui/webview/graphView.ts:1296-1298`, `src/ui/webview/graphView.ts:1465-1476`). Ordinary source navigation uses the first workspace folder and excludes external entities (`src/ui/webview/graphView.ts:648-683`). The music action is a related selection consumer: the page sends its selected group key, but the host resolves only curated groups and falls back to their first group. A structural selection is therefore not necessarily the group whose music opens in Strudel (`src/ui/webview/graphView.ts:279-297`, `src/ui/webview/graphView.ts:2115-2119`, `src/ui/webview/graphView.ts:253-258`).

Existing tests map to these risks as follows; these are inspected assertions, not tests run or measured browser coverage:

- `src/ui/webview/graphView.test.ts:57-109` checks manifest default/scope, localized choices and compilable inline JavaScript; global save and reopening; no HTML replacement on ordinary reveal; Settings synchronization, failed-save reply and invalid-mode rejection. Its panel and VS Code APIs are mocked, so it does not demonstrate actual transform/selection restoration or visible selector rollback in a browser.
- `src/ui/webview/graphPerformanceScript.test.ts:49-103` executes the shipped helper string with mocked frames/simulation to check batching, all stop conditions, hidden pause/resume, replacement cancellation and failure cleanup. `:105-140` covers prose reuse/topology invalidation, LRU/node caps and pending alpha/auto-fit retention; `:142-165` covers low/high drag differences. These directly protect helper invariants, but not the surrounding D3/DOM lifecycle wiring.
- `src/services/knowledgeGraphService.test.ts:60-100` protects independent groups containing repeated symbols and group-specific entity resolution. `src/ui/webview/graphWebviewClientScript.test.ts:30-38` checks tooltip provenance/evidence line ranges and structural-path affordance text, not execution of drilldown/navigation.
- `src/services/structuralGraph/structuralAnalysis.test.ts:15-39` checks source-backed impact/path results; `:60-75` checks community suggestions and bounded/truncated aggregation. These test the structural algorithms, not the host's 80/120 caps, temporary-group replacement or error-status protocol.

Consequential gaps in the inspected tests are real-browser group/zoom restoration, rapid switching while still settling, full visibility/unload particle/CSS/timer cleanup, title-induced document replacement, advanced level/drilldown messages and source jumps, structural-view loss on command reveal/Refresh, and behavior on genuinely large/slow graph rendering. The helper tests are useful evidence but cannot establish those end-to-end contracts.

## 2. Instructions

### Command and output contract

**Knowledge: Generate Copilot Instructions** is contributed as `knowledge.generateCopilotInstructions`; the extension handler logs, awaits `EntityCommands.generateCopilotInstructions()` and has an outer error notification (`package.json:85-89`, `src/extension.ts:679-689`). There is no project/content picker in the handler. It targets `workspaceFolders[0]`, reports a localized no-workspace error and returns if absent. Within its try block it gathers graph data, calls the generation service, and offers Open file or Show in folder after completion (`src/ui/commands/entityCommands.ts:1255-1285`).

The service creates `.github` recursively when absent, builds text, writes `<first workspace>/.github/copilot-instructions.md` as UTF-8 using synchronous Node `fs`, then returns its path. Its async signature does not make that filesystem work nonblocking. An existing file is overwritten: there is no existence check for the target file, merge, confirmation, backup, temporary-file swap or rollback (`src/services/aiIntegrationService.ts:71-82`). A failed write can therefore leave filesystem effects, including the newly created directory or a partially/truncated target; successful completion means the write returned, not that Copilot accepted or used the document.

The success action opens/shows the returned document or executes `revealFileInOS`; dismissing the notification performs neither. These actions share the generation try/catch. Consequently a document-open/reveal failure can report “Failed to generate” after the file has already been written, without deleting it (`src/ui/commands/entityCommands.ts:1269-1284`). There is also a concrete presentation mismatch: the caller passes `.github/<basename>` into a success formatter that itself adds `.github/`, in both languages. The toast consequently repeats that directory, but the actual returned/opened path is correct (`src/ui/commands/entityCommands.ts:1271`, `src/i18n/en.ts:291-297`, `src/i18n/zh.ts:292-298`). Errors caught in `EntityCommands` are not rethrown; the extension's outer catch handles errors that escape that layer (`src/extension.ts:680-687`).

### What actually influences the content

The active output is a fixed English **VibeKnowledge Agent Instructions** routing document, not a project summary. `generateCopilotInstructions` names its optional argument `_graphData` and never reads it; `buildCopilotInstructionsContent()` supplies a fixed English locale and title to `buildAgentKnowledgeRouterContent()`, whose body is a literal list joined with newlines (`src/services/aiIntegrationService.ts:71-81`, `src/services/aiIntegrationService.ts:404-447`).

| Apparent input/dependency | Actual effect in this path |
| --- | --- |
| Workspace root | Chooses the destination; it is not interpolated into the router. No workspace name, package metadata, timestamp or project-specific entity appears in the active builder (`src/services/aiIntegrationService.ts:71-81`, `src/services/aiIntegrationService.ts:404-447`). |
| Entities, relations, observations, `sourceType` | `getGraphData()` reads the knowledge snapshot and queries observations for every entity, returning all these fields. The snapshot deduplicates normalized entity identities, remaps/deduplicates relations and excludes missing/self endpoints. None of the assembled data affects Copilot text (`src/ui/commands/entityCommands.ts:43-63`, `src/services/knowledgeGraphService.ts:67-118`, `src/services/aiIntegrationService.ts:18-23`, `src/services/aiIntegrationService.ts:71-78`). Inference: snapshot/observation errors can still prevent UI generation, and gathering may cost work, despite being semantically unnecessary for today's output. |
| Entity/relation/observation services and dependency analyzer | `EntityCommands` supplies these services; `AIIntegrationService` constructs `DependencyAnalyzer`. Its constructor only stores references, and the active router invokes none of their analysis/data methods (`src/ui/commands/entityCommands.ts:23-39`, `src/services/aiIntegrationService.ts:42-51`, `src/services/dependencyAnalyzer.ts:49-53`, `src/services/aiIntegrationService.ts:404-447`). |

Their presence/imports do not make current Copilot output project-specific. |
| MCP and generated group files | They are names/paths in emitted text, not dependencies called or checked during generation (`src/services/aiIntegrationService.ts:432-447`). |

The generated file is intended to guide a downstream assistant: for architecture, unfamiliar/cross-file code, dependencies and impact, prefer a focused VibeKnowledge `query_graph` call with a suitable `tokenBudget`; expand with `get_entity`, `get_neighbors` or `shortest_path`; request evidence only for relationship auditing. If MCP is unavailable/unhelpful, use `.vscode/.knowledge/agent-context/index.md` and one best-matching group. Do not load the full `knowledge-graph.md` audit report by default; skip the graph for small known-file tasks; verify current source before edits/tests; never directly edit `graph.sqlite` (`src/services/aiIntegrationService.ts:432-447`). The generator itself does not query MCP, install/configure it, generate or verify the index/groups, analyze the project, edit a database, invoke an AI model, or activate Copilot. Those are downstream guidance or external prerequisites, not consequences of this write.

### Shared paths and failure implications

`generateCursorRules()` writes `.cursorrules` using the same router body, with its locale/title specialization (`src/services/aiIntegrationService.ts:58-63`, `src/services/aiIntegrationService.ts:101-109`). A change in the shared router affects both products; project-specific behavior introduced only in the Copilot wrapper would have a different scope. Reusing the dormant long-form methods would materially change the compact query-first contract rather than merely exposing data already used.

**Generate All AI Configs** has its own UI handler, gathers one snapshot and enters a non-cancellable progress notification. It calls Cursor first, then Copilot, then offers either file for viewing. It does not call the service's convenience `generateAllAIConfigs` method; that separate programmatic API independently implements the same order and returns both paths (`src/ui/commands/entityCommands.ts:1290-1334`, `src/services/aiIntegrationService.ts:89-96`). Both are sequential and nontransactional: Cursor failure prevents Copilot; Copilot failure leaves the earlier Cursor write; later document-view failure leaves both files. Neither failure path restores old content.

A further upstream consumer is **Switch AI Scenario**: after changing a selected scenario it offers regeneration, and Generate executes `knowledge.generateAllAIConfigs` (`src/commands/scenarioCommands.ts:50-81`). Source-derived consequence: accepting that prompt rewrites the same compact routers for the current locale; changing the scenario does not currently personalize Copilot or inject its template. This path matters when deciding how new project-specific inputs should be shared, even though it is not part of the active content builder.

### Tests and consequential gaps

`src/services/aiIntegrationService.test.ts:68-98` creates a temporary workspace containing an `ai-template.md` marker, generates Copilot instructions without graph data and reads the result. It asserts MCP/group-index guidance, neighbor/path/evidence guidance and audit-report avoidance, and rejects the template marker, Tech Stack, Dependency Details and Total Entities. The service uses empty mocked service objects (`:42-47`), supporting the current service API's ability to generate without querying those objects. The neighboring Cursor test asserts compact query-first behavior and omission of its template marker/graph headings (`:100-119`). These tests protect content routing and indirectly exercise creation/write/read on a clean destination; they do not assert full exact content, the exact destination path, or equivalence under differing nonempty graphs.

The Node runtime extraction tests (`src/services/aiIntegrationService.test.ts:121-162`) directly exercise a private tech-stack helper. They protect that helper's distinction between runtime declarations and `@types/node`; they are not evidence that Copilot generation analyzes package metadata.

Targeted test searches found these service content tests but no tests naming the UI/bulk/scenario generation flows. Important unestablished contracts include overwrite behavior with existing user instructions, mkdir/write/permission failures and partial effects, no-workspace and multi-root selection, unused graph-data invariance versus UI snapshot failure, fixed Copilot language across locales, user completion actions and their failures, duplicate success-path formatting, sequential partial success in both bulk APIs, and scenario regeneration's lack of personalization. The tests also do not establish actual Copilot discovery/consumption or availability of the referenced MCP/index/groups. All tests here were inspected only; no tests/builds or generation were run.
