## 1. Visualization

### Command, host, and page

Implementation: `knowledge.visualizeGraph` is contributed in `package.json:57` and the knowledge view's menu at `package.json:244`. Its extension callback calls `GraphView.createOrShow(context.extensionUri)` and reports synchronous opening failures (`src/extension.ts:643`). Activation injects the knowledge and structural graph services (`src/extension.ts:242`). This is a singleton panel: an existing panel is revealed; an unchanged translated title causes a data message, not an HTML replacement. A changed title causes `_update()` to replace the document. New panels enable scripts and retain context while hidden; disposal clears the singleton and disposes listeners (`src/ui/webview/graphView.ts:139`, `src/ui/webview/graphView.ts:157`, `src/ui/webview/graphView.ts:186`).

The browser loads packaged D3 from `dist/d3.min.js`, with a nonce-bearing CSP/script, and embeds the performance and tooltip helpers. D3 is therefore a runtime dependency, not merely a development dependency (`src/ui/webview/graphView.ts:718`, `src/ui/webview/graphView.ts:751`, `src/ui/webview/graphView.ts:1137`; packaging copy: `esbuild.js:12`). On window load the page initializes SVG/zoom, then posts `ready`; the host replies with the effective performance setting and `graphData`. Toolbar Refresh posts `refresh`, which sends the ordinary group data again (`src/ui/webview/graphView.ts:205`, `src/ui/webview/graphView.ts:263`, `src/ui/webview/graphView.ts:1205`, `src/ui/webview/graphView.ts:2086`). This account concerns those page interactions, not background source refresh.

### Ordinary and advanced views

Ordinary groups come from `KnowledgeGraphService.getGroups()`, which maps agent groups independently. Repeated symbols across framework/module/feature groups are intentionally retained, unlike the deduplicated aggregate used elsewhere (`src/services/knowledgeGraphService.ts:147`). The host maps entities, observations, provenance, descriptions, structural keys, relation confidence/evidence, and structural paths into view models; an unavailable knowledge service produces an empty group list (`src/ui/webview/graphView.ts:456`). The page sorts by order then name, builds sidebar buttons, selects the saved key if still present or the first group otherwise, and renders only that group. Selection updates `vscode.setState({ selectedGroupKey })` and the active button. An empty list stops work, clears the geometry cache, removes drawing contents, and shows the empty state (`src/ui/webview/graphView.ts:1372`, `src/ui/webview/graphView.ts:1423`, `src/ui/webview/graphView.ts:1449`).

The advanced toolbar action reads the aggregation-level selector and posts `requestStructuralOverview`; it does not replace the ordinary service's groups. The host reads the structural graph and calls `aggregateStructuralGraph` with a limit of 80. Its response is a synthetic group, with aggregate IDs, member files, relation counts, and paths back to raw relations (`src/ui/webview/graphView.ts:2091`, `src/ui/webview/graphView.ts:324`, `src/ui/webview/graphView.ts:518`). `upsertStructuralGroup` removes previous keys beginning `__structural_`, appends the new group to the ordinary groups, selects it, and displays status. Thus there is one currently listed advanced result, not a structural-navigation history. Ordinary `graphData` replaces the entire list, so toolbar Refresh or invoking the command to reveal an existing panel drops that advanced result and falls back to an ordinary group if its structural key was selected (`src/ui/webview/graphView.ts:1287`, `src/ui/webview/graphView.ts:1372`, `src/ui/webview/graphView.ts:1401`).

Interaction branches matter:

- Double-clicking a relation or its label requests its nonempty structural path; the host matches source, target, verb **and source location**, then renders matching raw entities/relations. This is not an arbitrary traversal reconstructed from only endpoint names (`src/ui/webview/graphView.ts:1601`, `src/ui/webview/graphView.ts:1686`, `src/ui/webview/graphView.ts:340`, `src/ui/webview/graphView.ts:627`). A stale nonempty path with no current matches produces an empty slice, not necessarily an error.
- An aggregate node double-click requests its raw members. A raw structural node double-click opens its source. A curated node normally opens its source, while Shift-double-click or right-click with a structural key requests structural neighbors (`src/ui/webview/graphView.ts:1761`). Neighbor analysis uses both directions, depth one, deduplicates relations, caps at 120 relations/80 entities, and filters edges to included endpoints. Aggregate drill-down selects member files or its level/path fallback and caps at 80 entities/120 internal relations (`src/ui/webview/graphView.ts:365`, `src/ui/webview/graphView.ts:407`). Raw slice keys are timestamp-based, so repeating a drill-down is not a stable group-cache lookup (`src/ui/webview/graphView.ts:576`).
- Source navigation uses the first workspace folder and converts one-based source ranges to editor ranges. Ordinary external entities show an informational message; unresolved/external structural entities return without opening. File-opening failures have separate ordinary error and structural-warning paths (`src/ui/webview/graphView.ts:647`, `src/ui/webview/graphView.ts:687`).

### Performance selector and remembered state

The setting is `knowledgeGraph.visualization.performanceMode`, machine-scoped, default `low`, with `low`/`high` choices (`package.json:325`). The page applies a selection immediately, disables the selector, and sends `setPerformanceMode`; the host validates the value, writes it globally, then always sends the effective value back. A failed write shows an error and that reply rolls the optimistic UI back; a Settings change also sends the effective value. Receiving the reply reenables the selector. A mode change rerenders the selected group through the same cache-preserving path, not a different graph-data path (`src/ui/webview/graphView.ts:150`, `src/ui/webview/graphView.ts:300`, `src/ui/webview/graphView.ts:1283`, `src/ui/webview/graphView.ts:2077`, `src/ui/webview/graphView.ts:2176`).

Low mode still computes a force layout; it does not simply skip layout. It stops the automatic simulation and manually ticks in requestAnimationFrame batches, explicitly redraws after each batch, yields after roughly 6 ms, and finishes on cooling, 120 ticks, or 600 ms accumulated compute time. Completion forces alpha to zero. Those are cooperative budgets: one expensive tick cannot be preempted, and hidden time is not included in accumulated compute time (`src/ui/webview/graphPerformanceScript.ts:46`). Low-mode dragging stops layout and moves/redraws the dragged node directly without restarting physics; high mode reheats the simulation and temporarily fixes the dragged node (`src/ui/webview/graphPerformanceScript.ts:91`; connection to geometry/save callbacks: `src/ui/webview/graphView.ts:1950`).

High mode uses automatic D3 simulation while unsettled, animated agent dashes, particles, glow, label halos/shadows, and transitions. The particle loop is single and throttled to approximately 30 fps; it can continue after physics settles. Low mode creates no particles and removes the costly decorative effects. A cached settled graph does not automatically reheat merely because high mode was chosen (`src/ui/webview/graphView.ts:1080`, `src/ui/webview/graphView.ts:1572`, `src/ui/webview/graphView.ts:1588`, `src/ui/webview/graphView.ts:1613`, `src/ui/webview/graphView.ts:1668`, `src/ui/webview/graphView.ts:1727`, `src/ui/webview/graphView.ts:1810`).

The persistence boundaries are distinct:

| Event/state | Current behavior and consequence |
| --- | --- |
| Switch groups or rerender for a mode change | Rendering stops the previous work, saves its layout, then restores matching geometry for the new group. Fresh entities/relations are copied each render; the cache contains positions, zoom transform, settled flag, alpha, and auto-fit flag, **not** evidence/source objects. It does not preserve velocity or permanent drag pins (`src/ui/webview/graphView.ts:1479`, `src/ui/webview/graphView.ts:1552`, `src/ui/webview/graphPerformanceScript.ts:24`). |
| Cache validity and eviction | Group key plus sorted node IDs and endpoint/verb topology determine reuse. Prose/evidence changes do not invalidate geometry; topology changes do. The LRU cache defaults to 8 groups/2,000 total nodes, rejects oversized edge/node sets and nonfinite positions, and can evict a previously visited view (`src/ui/webview/graphPerformanceScript.ts:8`). |
| Reveal the existing panel with the command | The same document/cache survives when its title matches, but ordinary data is resent. An ordinary selection survives if its key remains; the advanced result does not. A title-triggered HTML replacement recreates the in-memory cache; the page only asks webview state for the selected key (`src/ui/webview/graphView.ts:157`, `src/ui/webview/graphView.ts:1138`, `src/ui/webview/graphView.ts:1372`). |
| Close/dispose and create a new panel | Disposal clears `currentPanel`; construction makes a new cache. Only the performance preference has explicit global persistence. No host-side carry-over/serializer for selected group or geometry is implemented in this lifecycle; a new panel cannot rely on the old webview's key and normally selects the first ordinary group. This differs from hiding the retained page (`src/ui/webview/graphView.ts:169`, `src/ui/webview/graphView.ts:186`, `src/ui/webview/graphView.ts:300`, `src/ui/webview/graphView.ts:1141`). |
| Hide/show the retained page | Hiding pauses particles without losing their resume callback, pauses static layout, stops physics, interrupts transitions, clears fit/resize timers, and saves geometry. Showing resumes unfinished low layout, or high physics only while alpha is above its minimum, and resumes eligible particles. Unload instead cancels work permanently (`src/ui/webview/graphView.ts:1234`, `src/ui/webview/graphView.ts:1254`). |

Auto-fit is part of view state, not just decoration. User zoom/pan and dragging disable automatic fit; low-layout completion fits once if allowed, whereas high mode schedules it after one second. Manual Fit is immediate in low mode and a 750 ms transition in high mode, clamped to the zoom bounds and guarded against zero dimensions. Resize is debounced 120 ms: low mode fits regardless of the saved auto-fit flag; high mode reheats visible physics. Inference from the callbacks: hiding before the high-mode fit timer fires cancels that fit, and merely showing the page does not reschedule it (`src/ui/webview/graphView.ts:1210`, `src/ui/webview/graphView.ts:1254`, `src/ui/webview/graphView.ts:1360`, `src/ui/webview/graphView.ts:1933`, `src/ui/webview/graphView.ts:1957`, `src/ui/webview/graphView.ts:2053`).

### Correctness boundaries and existing tests

Changes must preserve independent group membership and endpoint integrity, fresh metadata with cached geometry, bounded caching, unfinished-layout continuation, user camera intent, and cancellation of replaced/hidden work. They must also preserve the different structural/source navigation messages and the global-setting acknowledgment/rollback protocol. Structural failures are caught, returned as `structuralError`, shown as a warning/status, and hide loading without replacing the old graph. Synchronous render errors and static-layout failures stop work and show a dedicated error state. This is not a universal exception boundary: `initGraph()` executes before `ready` outside `selectGraphGroup`'s catch, and high-mode tick/particle callbacks are not wrapped by that catch. Inference: missing D3 or such asynchronous failures can bypass the normal render-error UI (`src/ui/webview/graphView.ts:450`, `src/ui/webview/graphView.ts:1205`, `src/ui/webview/graphView.ts:1296`, `src/ui/webview/graphView.ts:1449`, `src/ui/webview/graphView.ts:1632`, `src/ui/webview/graphView.ts:1920`; static failure catch: `src/ui/webview/graphPerformanceScript.ts:71`).

Existing coverage maps to these risks as follows; these are inspected tests, not test results from this task:

## 2. Instructions

### Command and destination contract

Implementation: the UI contribution is `Knowledge: Generate Copilot Instructions` / `knowledge.generateCopilotInstructions` (`package.json:86`). The registered async callback awaits `EntityCommands.generateCopilotInstructions()` and catches otherwise escaping errors (`src/extension.ts:680`). Activation constructs `EntityCommands` with entity, relation, observation, and knowledge-graph services; the command class constructs `AIIntegrationService` from the first three (`src/extension.ts:245`, `src/ui/commands/entityCommands.ts:23`).

The command chooses `workspaceFolders[0]`, not the active editor's folder and not a user-selected output root. With no workspace it reports the localized error and returns. Otherwise it calls `getGraphData()`, then passes the first root's filesystem path and that data to the service. There is no save dialog, project questionnaire, model call, or overwrite confirmation in this path (`src/ui/commands/entityCommands.ts:1255`). `getGraphData()` obtains the unified snapshot and gathers each entity's observations into `{ entityId, entityName, content }`; the result has entities, relations, observations, and the fixed source type `knowledge` (`src/ui/commands/entityCommands.ts:42`; interface: `src/services/aiIntegrationService.ts:18`).

The service ensures `<root>/.github` exists using recursive `mkdirSync`, builds the content, writes UTF-8 directly to `<root>/.github/copilot-instructions.md` using `writeFileSync`, and returns that path (`src/services/aiIntegrationService.ts:71`). If the destination exists, the direct write replaces its contents: no merge with custom instructions, prompt, backup, atomic temporary-file swap, or rollback appears here. The `existsSync` check is for the directory, not a safeguard for the destination file. Inference from this sequence: permission/path failures reject the async method, a newly created `.github` can remain after a later failure, and a failed write has no transactional protection for the old file.

After successful writing, the command offers Open file or Show in folder. Open uses `openTextDocument` then `showTextDocument`; Show uses `revealFileInOS` with the returned path. Dismissing the notification leaves the file written. The same command-level try/catch includes data collection, writing, notification, and the optional open/reveal step, converting failures to a localized error without rethrowing them (`src/ui/commands/entityCommands.ts:1262`). Therefore a graph-collection failure can prevent generation before writing, while an open/reveal failure can produce an error **after** the file was already generated. The outer extension catch is a fallback for errors escaping this handler, not a second normal error report (`src/extension.ts:680`).

A current presentation defect is separate from the actual destination: the command passes `.github/` plus the basename into `translations.success`, but both English and Chinese success functions prepend `.github/` again. The notification consequently describes `.github/.github/copilot-instructions.md`; the actual write/open path has only one `.github` (`src/ui/commands/entityCommands.ts:1271`, `src/i18n/en.ts:293`, `src/i18n/zh.ts:294`).

### Actual versus apparent inputs

The live Copilot builder is `buildCopilotInstructionsContent()`, which calls `buildAgentKnowledgeRouterContent('en', '# VibeKnowledge Agent Instructions')`. It returns a joined array of fixed lines. The public method names its optional argument `_graphData` and never uses it (`src/services/aiIntegrationService.ts:71`, `src/services/aiIntegrationService.ts:404`). Consequently:

- Workspace root affects the destination, not the text. Workspace name, graph entities/relations/observations/source type, dependency statistics, package/runtime/framework information, custom AI template/current scenario, timestamps, and relation-display limits do **not** customize the current Copilot output. Copilot content is English regardless of UI locale; localization still affects command notifications (`src/services/aiIntegrationService.ts:404`, `src/services/aiIntegrationService.ts:411`; notifications: `src/ui/commands/entityCommands.ts:1269`).
- The knowledge graph remains an **operational** dependency of the UI command because it is collected before the ignored argument is passed. It is not a **content** dependency. Empty graph data is not rejected, and calling the service directly does not require a workspace entry in the VS Code API or populated entity services (`src/ui/commands/entityCommands.ts:42`, `src/ui/commands/entityCommands.ts:1263`, `src/services/aiIntegrationService.ts:71`).
- `AIIntegrationService` stores entity/relation/observation services and constructs `DependencyAnalyzer`, whose constructor just stores the two services. That construction does not run dependency analysis (`src/services/aiIntegrationService.ts:43`, `src/services/dependencyAnalyzer.ts:49`). The class still contains older detailed Chinese/English Cursor builders that read workspace name, graph/service data, stats and tech stack, plus scenario-template and configuration helpers. They are not called by the current public Cursor dispatcher or Copilot builder (`src/services/aiIntegrationService.ts:101`, `src/services/aiIntegrationService.ts:114`, `src/services/aiIntegrationService.ts:259`, `src/services/aiIntegrationService.ts:404`). In particular, the dormant scenario helper reads `ScenarioManager` and the dormant relation limit reads `knowledgeGraph.aiConfig.maxRelationsDisplay`; finding those dependencies in the class is not evidence that today's generated file uses them (`src/services/aiIntegrationService.ts:691`, `src/services/aiIntegrationService.ts:718`).

### Shared generation and intended use

The generated file is a compact instruction router for a future coding assistant, not a project summary. Its English lines tell that assistant to use focused MCP `query_graph` for architecture/unfamiliar/cross-file/dependency/impact tasks; expand with `get_entity`, `get_neighbors`, or `shortest_path`; request evidence only for auditing; fall back to the agent-context index and one matching group; avoid loading the full audit report by default; skip graph navigation for small known-file tasks; verify behavior in current source; and never edit `graph.sqlite` directly (`src/services/aiIntegrationService.ts:433`).

Those are **instructions written into a file**, not actions executed by the generator. The generator does not call MCP, query an LLM, test MCP availability, read the suggested context files, refresh the graph, edit SQLite, run verification, install/configure Copilot, or guarantee the consumer will obey. Its live service work is directory creation plus writing the fixed content; the UI additionally collects graph data and can open/reveal the result (`src/services/aiIntegrationService.ts:71`, `src/services/aiIntegrationService.ts:404`, `src/ui/commands/entityCommands.ts:1255`). Intended use is evident from the contributed command, standard destination, and generated text; actual downstream Copilot loading/behavior is not established by these implementation tests.

Cursor generation writes `<root>/.cursorrules` and uses the **same router builder**, but its dispatcher selects Chinese only when `getLocale() === 'zh'`, otherwise English, with a Cursor-specific heading. It too ignores `_graphData` (`src/services/aiIntegrationService.ts:58`, `src/services/aiIntegrationService.ts:101`). A change in the shared router therefore affects Cursor as well as Copilot; a Copilot-only change at its dispatcher need not do so.

There are two all-config orchestration paths. The service's `generateAllAIConfigs` calls Cursor then Copilot and returns both paths. The UI's similarly named command does **not** call that wrapper: it collects graph data once and separately awaits the same two service generators under non-cancellable progress, then offers either file for viewing (`src/services/aiIntegrationService.ts:89`, `src/ui/commands/entityCommands.ts:1290`). Both share the same underlying writers/builders and execute sequentially. Inference: Cursor failure prevents Copilot generation; Copilot failure leaves the already-written Cursor file in place. The UI reports failure and skips the all-success notification, but performs no rollback. A failure opening a selected generated file likewise does not undo either output (`src/ui/commands/entityCommands.ts:1306`, `src/ui/commands/entityCommands.ts:1317`).
