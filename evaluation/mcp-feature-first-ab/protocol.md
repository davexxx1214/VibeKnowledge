# Feature-first MCP versus source-only: prospective replication

Frozen before candidate runs. Three fresh matched A/B pairs complete the same
two published feature-analysis tasks as Skill r3 and the released MCP trial.
A reads source; B may additionally use the current feature-first MCP. All
candidates have no inherited conversation and identical inherited model/effort.
Record actual model metadata. Do not reuse any previous A or B answer.

Reuse the exact selected source, structural graph, three condensed groups and
two independently authored r3 feature briefs from the previous MCP fixture.
Verify hashes before copying. The analyzed source predates the 0.5.0 release
manifest bump; this is not a complete clean clone or a new held-out repository.
The runtime is the current uncommitted feature-first MCP candidate, identified
by source/build/dependency hashes rather than just its unchanged version string.
Do not regenerate or tune briefs, graphs, product code, tasks or rubric after
seeing answers. No RAG, internet, model calls inside MCP, source mutation or
test/build execution by candidates. Artifacts remain read-only.

The common observer returns numbered reads/searches with an 18,000-character
cap. B calls the real MCP SDK stdio server, not Skill CLI or mocked handlers.
One discovery returns all actual tool definitions, including find_features,
get_feature_brief and get_task_context; discovery text and query failures count.
Source verification is unrestricted within the snapshot. B follows the existing
Skill method: a relevant feature brief first, targeted source/context expansion
only for missing evidence. It may skip unnecessary calls.

Each MCP invocation starts a process. This is NOT a native editor automatic
discovery/caching or persistent-latency benchmark. Costs include bridge wrappers.
Freeze Node, rg and installed runtime dependencies before all runs; verify again
afterward. Serialize pairs, with near-concurrent A/B agents within each pair.
Use predeclared alternating dispatch order A/B, B/A, A/B. Duration is descriptive,
not a controlled hardware-performance result.

Each dispatch includes the complete common task document and only its arm and
isolated workspace. No bootstrap read of parent evaluation files is needed.
Save the public dispatch text before launching. No grading rubric, earlier
reports, expected savings or conclusions are passed to candidates. Each pair
is scored by its own fresh grader on anonymized reports, source, the unchanged
r3 rubric and previously published interpretation notes, without metrics/mapping.

The unchanged efficiency gate requires no critical-coverage loss and no extra
major false claims in any pair, >=15% reduction in median observer text AND
actual delivered public tool text, and >=10% reduction in median uncached input
plus output. The quality gate requires >=20% fewer missed critical facts,
strict improvement in >=2 pairs, no extra major false claims and <=25% median
uncached-input-plus-output increase. Independent arm medians define changes.
Report failed gates and all runs; do not retry poor/high-cost answers.
Infrastructure aborts are preserved separately, not merged with completed usage.

Count tokenizer o200k_base text, numeric model input/output/cache telemetry,
failed/repeated reads, per-task source/query counts, delivery truncation and
independent per-item quality. Do not add observer counts to delivered counts:
these are two measurements of the same interaction. Archive only public task
artifacts and numeric telemetry, never private reasoning/system content.
Audit public tool-call scope and bind observer emissions to returned text.

This tests warm reuse. Historical authoring of these two briefs cost 90,480
uncached-input-plus-output tokens; extraction, curation, installation and
refresh are additional, not free and not consumed task context. New setup and
grading costs are evaluation overhead, reported separately where available.
There is no new known-file control, real code-change task, native MCP/Skill
transport isolation, statistical-significance or universal/billing claim.
The two old trials remain unchanged; do not subtract their percentages as a
causal comparison.
