## 1. Visualization

### Command, data and page selection

Implementation: `Knowledge: Visualize Graph` is contributed as `knowledge.visualizeGraph`, including a graph-explorer title action (`package.json:57`, `package.json:244`). Its extension-host handler calls `GraphView.createOrShow(context.extensionUri)` and reports synchronous opening failures (`src/extension.ts:642`). Activation injects both KnowledgeGraphService and StructuralGraphService into GraphView (`src/extension.ts:242`). The view is a singleton, script-enabled webview with `retainContextWhenHidden: true`; an existing panel is revealed and sent graph data without replacing its HTML, except when its translated title changed (`src/ui/webview/graphView.ts:157`). The browser initializes D3 on `load` and posts `ready`; the host responds with the actual performance preference and graph data (`src/ui/webview/graphView.ts:1205`, `src/ui/webview/graphView.ts:205`).

Implementation: ordinary data is built from `KnowledgeGraphService.getGroups()` plus entity observations, not the service's deduplicated aggregate snapshot. Independent framework/module/feature groups can therefore contain the same symbol with group-specific IDs. The underlying curated source is `agent-graph.json`, not raw structural JSON (`src/ui/webview/graphView.ts:456`, `src/services/knowledgeGraphService.ts:147`, `src/services/agentGraph/agentGraphService.ts:87`). Browser groups sort by `order`, then name; sidebar buttons show kind and entity/relation counts, and only the selected group is rendered. An existing selected key wins if still present, otherwise the first group wins (`src/ui/webview/graphView.ts:1372`, `src/ui/webview/graphView.ts:1423`). Selection updates the active button and VS Code webview state before rendering (`src/ui/webview/graphView.ts:1449`).

Implementation: the advanced selector offers Boundary, Community and File, and its button sends `requestStructuralOverview` with that level (`src/ui/webview/graphView.ts:1101`, `src/ui/webview/graphView.ts:2091`). The host reads StructuralGraphService on demand, aggregates with a limit of 80 nodes, converts the result to a display group and sends `structuralGroup`. Missing service/read/analysis failures produce both browser status and a VS Code warning (`src/ui/webview/graphView.ts:324`, `src/ui/webview/graphView.ts:446`; structural-file validation/missing-file behavior: `src/services/structuralGraph/structuralGraphService.ts:63`, `src/services/structuralGraph/structuralGraphService.ts:101`). The client removes prior `__structural_` groups, adds and selects the new one. Merely switching to an ordinary group leaves this temporary group available, but any ordinary `graphData` response replaces the entire group array, so revealing an existing panel or using page Refresh can remove it and fall back to the first ordinary group (`src/ui/webview/graphView.ts:1401`, `src/ui/webview/graphView.ts:1287`, `src/ui/webview/graphView.ts:1372`, `src/ui/webview/graphView.ts:2086`).

Implementation: hover highlights neighbors; ordinary node double-click navigates to source. Curated nodes with structural keys support Shift-double-click and right-click for neighbors; aggregate double-click requests raw structure; structural-node double-click uses structural source navigation. A relationship with `structuralPath` supports double-click drilldown; tooltip provenance/confidence/evidence must survive presentation changes (`src/ui/webview/graphView.ts:1599`, `src/ui/webview/graphView.ts:1729`, `src/ui/webview/graphView.ts:1791`, `src/ui/webview/graphWebviewClientScript.ts:8`). Neighbor requests use depth one in both directions, deduplicate relations, cap at 120 relations/80 entities, and filter dangling endpoints. Aggregate drilldown likewise caps 80 entities/120 internal relations and uses selected files when available (`src/ui/webview/graphView.ts:365`, `src/ui/webview/graphView.ts:407`). Aggregate overview edges exclude within-group relationships and store at most eight raw samples: drilling an aggregate relationship is not a complete enumeration of its displayed count (`resources/skills/vibeknowledge-dependency-graph/scripts/structural-analysis.mjs:416`, `src/ui/webview/graphView.ts:549`). Path drilldown matches stored relationship identities against the current structural graph; a nonempty but stale path can consequently produce an empty slice rather than an explicit stale-path error (inference from `src/ui/webview/graphView.ts:340`).

### Performance and view memory

Implementation: the machine-scoped setting defaults to `low`; only `low`/`high` are accepted by the host (`package.json:325`, `src/ui/webview/graphView.ts:300`). A selector change immediately applies locally, disables the control, and sends `setPerformanceMode`. The host writes VS Code Global configuration, reports write errors, and always resends the actual stored mode; receiving it applies/rolls back the page and reenables the selector. Settings changes also resend the preference (`src/ui/webview/graphView.ts:2176`, `src/ui/webview/graphView.ts:309`, `src/ui/webview/graphView.ts:1283`, `src/ui/webview/graphView.ts:150`). Changing mode rerenders the selected group; it does not request different graph data (`src/ui/webview/graphView.ts:2077`).

Implementation: low mode stops normal D3 scheduling, manually ticks layout in animation-frame batches and explicitly updates geometry because D3 manual ticks do not emit tick/end. Each batch targets approximately six milliseconds; the run stops on cooling, 120 ticks, or 600 milliseconds of accumulated compute time. It yields between batches and routes errors to the render-error path (`src/ui/webview/graphPerformanceScript.ts:46`). These are cooperative budgets, not a guarantee that one costly tick or render fits six milliseconds. Low-mode drag stops layout, moves just the node, redraws its incident geometry, and saves on release without reheating physics; high-mode drag restarts physics with an alpha target (`src/ui/webview/graphPerformanceScript.ts:91`, `src/ui/webview/graphView.ts:1823`, `src/ui/webview/graphView.ts:1950`). High mode enables particles, flow/glow and interactive forces; low mode removes those effects and CSS animations/transitions (`src/ui/webview/graphView.ts:1585`, `src/ui/webview/graphView.ts:1617`, `src/ui/webview/graphView.ts:1721`, `src/ui/webview/graphView.ts:1080`).

| Event/state | What survives and what changes |
| --- | --- |
| Ordinary group switch or mode change | Before replacing geometry, the page stops old layout/particles/simulation and saves its layout closure. A valid cache entry restores positions, pan/zoom transform, alpha, settled status and auto-fit intent. The closure captures the old group's key, so saving after the selected key changes still stores the old layout correctly (`src/ui/webview/graphView.ts:1479`, `src/ui/webview/graphView.ts:1556`). |
| Cache limits | Memory-only LRU defaults to eight groups/2,000 total nodes; oversized groups, excessive links or nonfinite positions are not cached. Validity depends on node IDs and edge source/target/verb topology, not descriptions/evidence. Geometry is copied, never source/evidence objects (`src/ui/webview/graphPerformanceScript.ts:7`). |
| Reveal an existing panel | The retained document/cache survives when HTML is not regenerated, but the host resends ordinary groups; the selected key must still exist. A temporary structural selection therefore is not reliably preserved across a command-driven reveal (`src/ui/webview/graphView.ts:157`, `src/ui/webview/graphView.ts:1396`). |
| HTML replacement / close and new panel | The page reads only `selectedGroupKey` from webview state; the layout cache is newly constructed. Closing disposes the singleton; a later command creates a new panel. There is no durable layout serialization in this path. The globally saved performance preference survives a fresh panel; full closed-panel/group/layout restoration is not implemented here (`src/ui/webview/graphView.ts:186`, `src/ui/webview/graphView.ts:199`, `src/ui/webview/graphView.ts:1138`, `src/ui/webview/graphView.ts:1454`). |
| Page becomes hidden | Visibility handling pauses static work and particles, stops simulation, interrupts transitions, clears fit/resize timers and saves geometry. On return it resumes unfinished low-mode work, reheats high mode only if alpha remains above its minimum, and resumes particles; unloading stops work/timers (`src/ui/webview/graphView.ts:1254`). |
| Empty ordinary data | Clears in-memory selection, geometry/cache and active work, then shows the empty state. It does not call `setState` to clear the previously saved key in that branch (`src/ui/webview/graphView.ts:1378`). |

Implementation: user zoom/pan or drag disables pending automatic fit. New low layouts fit when complete; high layouts schedule fit after one second. Fit is immediate in low mode versus a 750 ms transition in high mode (`src/ui/webview/graphView.ts:1360`, `src/ui/webview/graphView.ts:1933`, `src/ui/webview/graphView.ts:1957`, `src/ui/webview/graphView.ts:2053`). Resize is debounced 120 ms: low mode refits, high mode updates center/restarts with alpha 0.15 while visible (`src/ui/webview/graphView.ts:1210`). Thus “remember the view” already has exceptions: low-mode resize may replace a user's transform; hiding cancels a pending high-mode fit without explicitly rescheduling it on visibility return. Also, low-to-high preserves a settled cached layout instead of necessarily reheating it (inferences from `src/ui/webview/graphView.ts:1254`, `src/ui/webview/graphView.ts:1572`, `src/ui/webview/graphView.ts:1940`).

EntityCommands selects `workspaceFolders[0]`, reports a localized no-workspace error and returns if absent; it does not ask which workspace, active file, graph group or scenario to use (`src/ui/commands/entityCommands.ts:1255`).

Implementation: EntityCommands constructs AIIntegrationService with entity, relation and observation services. ### Builder, destination and completion/failure behavior

Implementation: `generateCopilotInstructions` creates `.github` recursively if absent, calls `buildCopilotInstructionsContent()`, synchronously writes UTF-8 to `.github/copilot-instructions.md`, then returns that path (`src/services/aiIntegrationService.ts:71`). The builder delegates to `buildAgentKnowledgeRouterContent('en', title)`, which joins a fixed string array with newlines (`src/services/aiIntegrationService.ts:404`, `src/services/aiIntegrationService.ts:411`). There is no model call, project analysis, prompt, network operation or graph query in this active content-generation chain.

Implementation: there is no destination existence check, merge, append, backup or overwrite confirmation. The normal write replaces existing instructions, including user-authored content. Filesystem exceptions reject the async service call; there is no service-level recovery/rollback (`src/services/aiIntegrationService.ts:71`). Consequently a directory may already have been created before failure, and a failed direct write is not a guarantee that old file bytes were preserved (inference from the nontransactional synchronous-write sequence).

Implementation: after a successful write, the command shows a localized success message naming `.github/copilot-instructions.md` and offers Open File or Show in Folder. These respectively call `openTextDocument`/`showTextDocument` or `revealFileInOS`; dismissing the message leaves the file written with no follow-up action. The same catch covers graph gathering, generation and those post-success UI actions, reporting a localized generation error (`src/ui/commands/entityCommands.ts:1262`). An open/reveal error can therefore be reported after the file was successfully written; the command does not undo it or return a structured success/failure result (`src/ui/commands/entityCommands.ts:1276`). The extension's outer catch is a fallback for errors escaping this inner handler (`src/extension.ts:684`).

### Shared consumers and intended use

Implementation: Generate All AI Configs collects graph data once and uses a non-cancellable notification progress workflow to generate `.cursorrules` first and Copilot instructions second, then offers either file for viewing. It directly calls the two service methods rather than the service's separate `generateAllAIConfigs()` convenience API, which also performs that sequence (`src/ui/commands/entityCommands.ts:1290`, `src/services/aiIntegrationService.ts:89`). These are sequential, not transactional: Copilot failure leaves an already-written Cursor file, and later viewing failure leaves both outputs. Catching an error does not revert either (`src/services/aiIntegrationService.ts:58`, `src/ui/commands/entityCommands.ts:1306`, `src/ui/commands/entityCommands.ts:1332`).

Implementation: Cursor's active builder shares the compact router, selecting Chinese only for locale `zh` and otherwise English, with a Cursor-specific title (`src/services/aiIntegrationService.ts:101`). Changing shared router logic can affect both products; changing the Copilot wrapper alone need not change Cursor. Another UI consumer is Switch AI Scenario: after a different scenario is selected and switched, choosing Generate executes `knowledge.generateAllAIConfigs` (`src/commands/scenarioCommands.ts:50`). Inference: this can rewrite the same compact outputs without incorporating the selected scenario, since neither active builder calls the scenario-template helper.

Implementation/intended contract of the generated file: it is repository-level guidance for a future coding assistant to use the knowledge graph as an on-demand dependency navigator. It instructs architecture/unfamiliar/cross-file/dependency/impact tasks to start with focused `query_graph` and a suitable token budget; expand with `get_entity`, `get_neighbors`, or `shortest_path`; request evidence only when auditing relationships (`src/services/aiIntegrationService.ts:432`). If MCP is unavailable/unhelpful, it points to `.vscode/.knowledge/agent-context/index.md` and only the best-matching group view. It discourages default loading of the complete `knowledge-graph.md` audit report, permits known-file small tasks to skip graph lookup, requires current-source verification, and forbids direct `graph.sqlite` edits (`src/services/aiIntegrationService.ts:439`).

These are instructions written into text, not actions performed by the generator. It does not configure/install MCP, run the named tools, generate/validate the context index or group files, refresh a graph, enforce later source verification, or establish whether Copilot actually discovers/follows the file (`src/services/aiIntegrationService.ts:71`, `src/services/aiIntegrationService.ts:404`). A successful write is not evidence those external prerequisites work.
