# Feature-first MCP A/B：描述性结果与未通过原因

日期：2026-09-05（Asia/Hong_Kong；原始记录使用 UTC）。

本轮完成三组新的独立 A/B，共六次 Agent 运行。MCP 组的实际工具文本中位数少
**23.8%**，未缓存输入加输出少 **16.7%**。但第二组 MCP 报告出现了源码组没有的
重大事实错误；此外，派发时向双方提供了包含 A/B 两段方法说明的完整公共任务文档，
不满足审前要求的“共同任务 + 仅本臂方法”隔离。因此不能把本轮宣布为严格通过的、
质量不下降的效率提升。保留全部结果，不重跑不利答案，也不修改原定门槛。

## 测了什么

- A：只读源码；B：只读相同源码，并可通过当前开发版 MCP 查询已有功能简报和图谱。
- 两个任务按相同顺序执行：图谱可视化的状态/性能/生命周期；Copilot Instructions
  的输入、生成、共享依赖、覆盖/失败及测试边界。不是两个真实代码修改任务。
- 三组各用两个无继承历史的候选，实际模型均为 `gpt-5.6-sol`、`xhigh`。
  顺序为 A/B、B/A、A/B；同组近同时运行，每组完成后才进入下一组。
- 每组由另一个无历史的 Agent 盲评 X/Y 报告，不提供分组映射或 token 指标。
  使用原有 17 个关键项、3 个补充项和 0/0.5/1 规则，重大错误单独记录。
- 源码是以前保留的 VibeKnowledge 选取快照，清单版本为 0.4.0；不是本轮新选的
  held-out 工程。两份简报、结构数据原样复用，不根据本轮答案修改。
- MCP 运行时清单为 0.5.0，加本地尚未发布的 feature-first 接口，候选 SHA-256 为
  `a5f2e2730c22d694acce43aa3a1573a4e16e533e1ee45ec6f08526fe3582f768`。
  Skill 本体和查询算法没有在本轮修改。Node 为 26.8.1。

MCP 调用经过 SDK 的 initialize、tools/list、tools/call 和 stdio，不是直接调用
handler 的 mock。但它由统一观察器桥接，每次调用新建进程，并非编辑器原生工具发现、
自动 schema 注入/缓存或持久连接延迟测试。详细方法见 [protocol](protocol.md)。

| 指标 | A：只读源码 | B：功能简报 MCP | 减少 |
| --- | ---: | ---: | ---: |

| 实际交付的公开工具文本，含外层包装 | 60,033 | 45,717 | 23.8% |
| 未缓存输入 | 73,668 | 59,817 | 18.8% |
| 输出 | 10,359 | 9,822 | 5.2% |

模型输入、输出及缓存来自各候选的数字遥测。未缓存指标不是账单金额，不能把
16.7% 写成所有模型 token 或费用都少 16.7%。时间包含并发竞争、工具及调度，
仅作描述，本轮没有显示中位数加速。

## 质量与门槛

| 组 | 关键项 A / B（满分 17） | 补充项 A / B（满分 3） | 重大错误 A / B |
| --- | ---: | ---: | ---: |
| 1 | 16.5 / 16.5 | 3 / 3 | 0 / 0 |
| 2 | 16.5 / 16.5 | 3 / 3 | 0 / 1 |
| 3 | 16 / 16.5 | 3 / 3 | 0 / 0 |

六份报告都漏掉了无工作区激活时提前注册 warning 占位命令的路径，只解释了正常
命令方法内部的 guard。第三组 A 还漏掉卸载页面时独立的清理入口。关键项覆盖两组
持平、一组 B 高 0.5 分，不能概括为双方完整正确。各组逐项证据见
[第一组](pair-1/grades.md)、[第二组](pair-2/grades.md)、[第三组](pair-3/grades.md)。

第二组 MCP 报告把当前 Cursor 生成内容描述为会按当前 locale 选择中英文。
实际源码 `src/i18n/i18nService.ts:126,148` 返回 `zh-CN` / `en-US`，而
`src/services/aiIntegrationService.ts:101` 的 writer 比较的是 `locale === 'zh'`，
因此该分支不会产生报告所述的语言效果。这个错误按预先固定的评分解释单独记录，
不改变共享 builder 正确覆盖项的分数，也不重复扣分。

评分严重程度也有不一致：第三组评分员把同类 Cursor locale 措辞问题列为局部事实
纠正，未计为重大错误。每组一个独立评分员不足以确定严重程度的一致性。本报告保留
原始判断，不事后挑选有利评分或统一降级；应把重大错误计数理解为本轮各自评分员的
裁定，而不是已经完成一致性复核的绝对事实标签。

值得注意的是，原有简报也用了 “localized Cursor rules” 的概括，且未列出
无工作区激活时的占位命令分支。哈希匹配只能说明引用文件未变化，不能保证简报
语义正确或依赖边界完整。简报可能强化了错误概括，但本试验没有隔离因果因素，
不能断定错误由 MCP、简报或少读源码中的哪一个单独导致。简报及答案保持原样，
没有在评分后修补。本轮因此提供了需要核查的质量风险，不是准确率提高的证据。

预设效率门槛同时要求每组关键覆盖不降、每组没有额外重大错误、工具文本减少至少
15%、未缓存输入加输出减少至少 10%。数值降幅达到要求，但“无额外重大错误”不满足；
独立范围审计的总体前置条件也未通过。不能绕过前置检查让 `summarize.cjs` 放行。
已实际执行冻结的汇总命令，它以 exit 1 拒绝生成 `summary.json`，见
[拒绝记录](summary-blocked.json)。
质量门槛同样不能通过：关键项加权缺失分从 A 的 2 降到 B 的 1.5，少了 25%，但只有
1 组严格改善，未达到至少 2 组，且仍有额外重大错误的裁定。因此这里记录的是数值与
失败条件，不是通过审计后的正式成功汇总。

## 实际读取路径与成本

三个 B 都发现了一次完整工具列表，再分别对两个功能调用 `find_features` 和
`get_feature_brief`：每个 B 共 4 次业务查询。**没有调用 `get_task_context`、
邻居、路径或结构分析**，也没有 RAG/resource 调用。功能发现加简报每个 B 返回
3,275 个观察器文本 token，完整工具发现另占 2,831。

| --- | ---: | ---: | ---: |
| 1 / 可视化 | 20 / 16 | 6 / 4 | 36,443 / 25,529 |
| 1 / Instructions | 19 / 11 | 4 / 3 | 19,897 / 12,063 |
| 2 / 可视化 | 17 / 19 | 6 / 3 | 32,379 / 26,331 |
| 2 / Instructions | 12 / 13 | 4 / 4 | 16,396 / 13,322 |

读取次数不等于不同文件数；第二组 B 读取次数更多，但分段更小。各阶段没有完全相同
参数的重复读取；这不排除范围重叠。第一组 B 有 2 次失败搜索，成本全部保留。第三组
A 有 1 次观察器内部 18,000 字符截断，保留截断后的实际文本；没有外层截断标记。
总计 253 条观察输出均匹配到了实际公开工具交付。见 [details.json](details.json)

两份简报历史生成另耗 **90,480 个未缓存输入加输出 token**、328.1 秒，本轮复用不
再次生成。提取、整理、安装、刷新及本轮评测编排/评分成本不包含在候选任务中，未
完整计量。因此不能宣称首次使用、整体评测或所有准备成本摊销后节省。参见
[原始简报生成记录](../query-skill/context/r3/generation/GENERATION.md)。

## 实验隔离偏差与审计

准备的六份派发正文均包含 `Arm A:` 和 `Arm B:` 两段，再由前缀指定实际执行臂。
我在执行时未落实 [审前独立 review](harness-review.md) 要求的“只给自己的方法段”。
额外方法说明本身占上下文，也可能影响行为，无法事后扣掉几个 token 就修正。
这项偏差保留披露，不改任务、门槛，不补跑有利答案。

公开调用与文件完整性检查应与这一设计问题区分：全部源文件/制品/运行时/依赖/工具
哈希已复验，没有发现候选越界读取、运行源码或修改源文件；完整 MCP 发现与交付也
已核查。总体审计仍不因此变为通过，详见 [独立范围审计](scope-audit.md)。

实际派发记录的正文持久化为 opaque payload。已保存公开工具调用中的任务名、
无历史参数、顺序、时间和 payload hash，但不能独立解密证明其明文与预写正文
完全一致。预写正文是主代理记录，不冒充独立证明。没有导出私有推理或系统消息。

## 能得出的结论

当前 MCP 能执行原 Skill 的功能优先查询，已有简报在这两项已知功能分析中减少了
交付文本和未缓存模型用量，但本轮不能证明它在质量不下降的前提下可靠省 token。
先核实简报中的可达分支和跨文件返回值/条件契约，比增加更多节点或接口更有针对性。
这只是从失误提出的后续方向，本轮未实施，也没有验证其收益。

没有同步 Skill 臂，不能用本轮 23.8% 减去历史 Skill 的 24.4% 比较传输优劣。
也没有新仓库、小型已知文件负对照、真实编码/测试、同等人工文档对照、统计显著性
或评分员间一致性验证。三个重复仍是两个已公布任务，不是六个独立任务样本。
高 rubric 覆盖不代表行为完全正确。旧 MCP、Skill 和 Yuxi 负面试验全部保留。

本轮仅增加评测记录及文档，没有根据结果修改产品、Skill、简报、任务或 rubric，
也未提交或推送 Git。计量/聚合的 8 个合成回归测试与评测脚本语法检查通过；它们
不是产品端到端测试。
