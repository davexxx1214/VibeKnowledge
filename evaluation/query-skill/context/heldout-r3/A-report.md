# Description overrides and MCP setup

Static source analysis of this workspace only. Locations below are repository-relative `path:line` citations. **Facts** describe inspected implementation; **inferences** identify consequences or risks, not reproduced failures. No tests, builds, installations, or source mutations were performed.

## 1. Descriptions

### Edit/reset → persistence → effective graph

**Facts.** Tree context menus expose edit and Agent-only reset (`package.json:200`); CodeLens invokes edit with the entity ID (`src/providers/codeLensProvider.ts:42`). The command accepts a string ID, an entity, or a tree item containing an entity. Edit resolves that ID against the current graph, otherwise offers a picker; cancellation is `undefined`, so an empty string is a valid edit. Reset has no picker and returns silently without a resolvable Agent entity (`src/ui/commands/entityCommands.ts:225`, `:242`, `:268`, `:279`).

`KnowledgeGraphService.updateDescription/resetGeneratedDescription` resolve the current entity and delegate to `AgentGraphService` (`src/services/knowledgeGraphService.ts:261`). That service writes/deletes the override by **entity key**, then invalidates and reloads its snapshot (`src/services/agentGraph/agentGraphService.ts:143`). The override store upserts `(agent_key, description, updated_at)` or deletes a row and calls `DatabaseService.save()` (`src/services/agentGraph/agentEntityOverrideService.ts:47`, `:61`). The database is SQL.js in memory, initially loaded from `<workspace>/.vscode/.knowledge/graph.sqlite`; save exports and directly rewrites that file (`src/services/database.ts:17`, `:37`, `:121`, `:165`). This path does not edit the generated manifest or legacy `entities.description` rows.

During snapshot construction, every group occurrence looks up its key. A defined override—including `''`—wins over generated prose; metadata retains `generatedDescription` and identifies `descriptionSource` as manual/Agent (`src/services/agentGraph/agentGraphService.ts:537`). Reset removes the override and therefore reveals **the latest generated description for each group**, not the generated text that existed when editing began. Regeneration/reset behavior is explicitly asserted in `src/services/agentGraph/agentGraphService.test.ts:393`.

### Scope and identity

**Facts.** The extension creates one database and graph service for `workspaceFolders[0]`, and watches that folder's manifest (`src/extension.ts:49`, `:57`, `:175`, `:265`). Overrides are workspace-local, not per editor, group, or generation. Group-specific IDs hash `group.key + entity.key`, but persistence uses the entity key alone (`src/services/agentGraph/agentGraphService.ts:153`, `:545`). The aggregate de-duplicates repeated identities, whereas visualization groups retain occurrences; entity lookup also searches those groups (`src/services/knowledgeGraphService.ts:67`, `:152`, `:192`).

Lookup prefers an exact stored key; otherwise it accepts exactly one matching normalized identity (`src/services/agentGraph/agentEntityOverrideService.ts:22`, `:78`). Identity normalization changes path separators, repeated slashes, and leading `./`, but preserves symbol/file case, Unicode, and punctuation (`resources/skills/vibeknowledge-dependency-graph/scripts/canonicalize-entity-key.mjs:34`). A semantic rename or file move is not an automatic migration.

**Inference.** In a multi-root window, editor providers can misassociate another folder's same relative path with the first folder's graph: they relativize against the document's owning folder, while their shared graph remains first-folder-scoped (`src/providers/hoverProvider.ts:101`; `src/providers/codeLensProvider.ts:58`; `src/extension.ts:57`, `:295`).

### Invalidation and consumers

**Facts.** Agent snapshots are cached by manifest `mtimeMs:size`, not database version. `refresh()` clears this signature and reloads (`src/services/agentGraph/agentGraphService.ts:108`, `:232`). Both edit/reset command wrappers refresh the tree, open graph panel, and CodeLens after the handler returns—even on normal cancellation/no-op; an exception bypasses those calls and reaches the error message (`src/extension.ts:548`). Manifest create/change/delete events run the same refresh sequence (`src/extension.ts:265`).

| Consumer | How the new effective description becomes visible |
| --- | --- |
| Tree and tree search | Tree refresh reloads the graph and fires its event; entity tooltips and filtering read effective prose (`src/providers/treeDataProvider.ts:70`, `:172`, `:336`). |
| Open graph panel | `GraphView.refresh()` sends new graph data; group models take `entity.description` from the unified graph (`src/ui/webview/graphView.ts:124`, `:456`). |
| CodeLens | Refresh fires its change event; lenses reread entities and compact descriptions, falling back to the name for blank text (`src/providers/codeLensProvider.ts:28`, `:73`; `src/providers/knowledgeCodeLensModel.ts:32`, `:50`). |
| Hover, details, exports, AI graph input | Hover queries on demand; details rebuild output on command; exports and AI graph input fetch the unified graph (`src/providers/hoverProvider.ts:25`; `src/ui/commands/entityCommands.ts:42`, `:326`; `src/services/exportService.ts:684`). Previously rendered output/export files are not subscribed consumers. |
| MCP graph queries/search | Each query fetches the SQLite override map and applies it before description filtering or constructing a query engine (`packages/mcp-server/src/mergedGraph.ts:27`, `:110`; `packages/mcp-server/src/tools/registerGraphQueryTools.ts:251`; `packages/mcp-server/src/agentGraphStore.ts:342`). The manifest is reread on each store load; exact/unique identity matching and empty overrides are preserved (`packages/mcp-server/src/agentGraphStore.ts:416`, `:564`). |
| Standalone query CLI | Opens SQLite read-only, reads overrides, closes it, then feeds effective entities to queries/search (`packages/mcp-server/src/queryCli.ts:47`, `:107`, `:129`). |

### Important failure boundaries

- **Fact/inference—save is not transactional publication.** The SQL mutation precedes file save, with no rollback in the override methods; a write failure throws before graph refresh (`src/services/agentGraph/agentEntityOverrideService.ts:47`; `src/services/database.ts:165`). Thus memory may contain the edit while disk does not, and direct file rewriting can leave damaged disk content after an interrupted write. A later UI refresh can reveal an unpersisted in-memory edit. External database writes are not reloaded by graph refresh: SQL.js is loaded during initialization, while graph refresh rereads only the manifest (`src/services/database.ts:37`; `src/services/agentGraph/agentGraphService.ts:108`, `:248`).
- **Fact/inference—MCP freshness is not a proven cross-process guarantee.** MCP requests reread override rows, but `GraphDatabase` holds one read-only native SQLite connection, opened at startup (`packages/mcp-server/src/database.ts:114`, `:379`; `packages/mcp-server/src/index.ts:13`). There is no reopen here coordinated with the extension's whole-file rewrites. Concurrent-read/cache safety cannot be established from these source paths alone; the CLI's fresh open avoids relying on that long-lived connection.
- **Fact/inference—alias edits can leave old overrides behind.** Set upserts the exact new spelling; delete removes only an exact row or a unique fallback (`src/services/agentGraph/agentEntityOverrideService.ts:47`, `:61`, `:98`). If an old key's override is inherited after a portable spelling change, editing the new spelling creates a second row. Resetting the new row can then reveal the old fallback instead of generated prose. Multiple identity-equivalent rows disable fallback, and exact occurrences can show different values. Existing portable-key/reset tests do not exercise this edit-after-spelling-change sequence (`src/services/agentGraph/agentEntityOverrideService.test.ts:8`).
- **Fact/inference—invalid or changing generation.** Missing manifests yield an empty snapshot; malformed manifests or override-read exceptions clear the snapshot and retain an error, rather than preserving the previous valid graph (`src/services/agentGraph/agentGraphService.ts:232`). IDs can disappear while an input box is open; edit checks a null update, but reset unconditionally announces success after calling a service that can return null (`src/ui/commands/entityCommands.ts:252`, `:268`). Stable-key changes can strand stored prose; unchanged manifest size/mtime needs explicit refresh to bypass the cache.
- **Fact—blank text and timestamps are intentional distinctions.** Blank overrides suppress generated text; the tree labels them empty, while hover/details omit blank descriptions and CodeLens uses the name (`src/providers/treeDataProvider.ts:75`; `src/providers/hoverProvider.ts:42`; `src/ui/commands/entityCommands.ts:338`). Effective entity timestamps still come from generation time, and merged MCP overview reports Agent generation time, not edit time (`src/services/agentGraph/agentGraphService.ts:541`, `:562`; `packages/mcp-server/src/mergedGraph.ts:74`). **Inference:** those timestamps cannot serve as override-invalidation tokens.

## 2. MCP setup

### UI → target → isolated installation

**Facts.** Activation registers real setup/settings commands before the no-workspace return and database initialization (`src/extension.ts:36`). `knowledge.setupMcp` and the settings menu's install action share `install()` (`src/commands/mcpSetupCommands.ts:100`). A per-registration `selecting/active` guard prevents simultaneous runs; an untrusted workspace is rejected; disposal aborts an active run (`src/commands/mcpSetupCommands.ts:9`, `:15`).

The machine-scoped `knowledgeGraph.mcp.workspacePath` takes precedence. If blank, the picker includes local open folders and an option to browse another single local folder; cancellation exits. UI requires an absolute path. Client `auto` detects Cursor from the app name, otherwise uses VS Code; the preview targets `.cursor/mcp.json` or `.vscode/mcp.json` (`src/commands/mcpSetupCommands.ts:23`; `package.json:288`). Unlike the graph UI, MCP setup is not restricted to the first open folder. A modal confirms downloads, writes, backup, and missing-database initialization. Only after acceptance is the chosen workspace saved globally; then progress/cancellation is attached (`src/commands/mcpSetupCommands.ts:43`).

`setupMcp` checks the 10–120-second integer audit setting, resolves the workspace through `realpath`, requires a directory, reads existing config, and validates its JSONC shape **before executing processes/downloads** (`src/services/mcpSetupService.ts:148`). Installation uses `<globalStorage>/mcp`, not the business project; its bundle comes from `<extension>/dist/mcp-server` (`src/commands/mcpSetupCommands.ts:64`). The build pipeline emits portable Node-targeted JS and copies package/lock/config/helper assets, not an installed dependency tree (`scripts/build-mcp-runtime.cjs:18`; `tests/mcpRuntimeBundle.test.ts:11`).

### Runtime checks and child-process chain

**Facts.** Setup runs the configured external Node with `-p` to discover its version, executable, ABI, platform, and architecture. The version gate accepts stable Node `>=26.1.0 <27`, rejecting prereleases. All subsequent commands and final client config use the discovered executable, not extension-host Electron (`src/services/mcpSetupService.ts:98`, `:162`). npm must be an absolute configured `npm-cli.js` or a file found relative to real Node; npm major versions below 11 are rejected. Child PATH prepends the selected Node directory while preserving inherited environment (`src/services/mcpSetupService.ts:91`, `:104`, `:166`).

Each attempt creates a unique directory with a prefix hashing lockfile plus Node/runtime platform details, copies the bundle, and executes this gated chain (`src/services/mcpSetupService.ts:171`):

1. Selected Node + npm CLI: `ci --omit=dev --audit --ignore-scripts`. Windows supplies an explicit `cmd.exe` script-shell option, but lifecycle scripts remain disabled (`src/services/mcpSetupService.ts:179`; `packages/mcp-server/.npmrc:1`). SQLite dependency is `better-sqlite3` 13, whose packaged N-API prebuild design avoids installation-time compilation (`packages/mcp-server/package.json:44`; `packages/mcp-server/tests/nativeRuntime.test.ts:9`).
2. Selected Node + `audit-dependencies.cjs` + npm CLI, with the requested timeout in a child-only environment (`src/services/mcpSetupService.ts:187`).
3. Initialize `graph.sqlite` **only if missing**, using extension SQL.js and closing/saving afterward; an existing database is not replaced by this callback (`src/commands/mcpSetupCommands.ts:73`; `src/services/database.ts:184`).
4. Selected Node + `health-check.mjs <workspace>`, with a 45-second process deadline; only successful completion permits config publication (`src/services/mcpSetupService.ts:197`).

**Inspection limit.** The build references `packages/mcp-server/scripts/health-check.mjs` (`scripts/build-mcp-runtime.cjs:35`), but that source file is absent in this checkout (observer read returned ENOENT; filename search found no helper). Thus the call site proves a mandatory health-check exit-status gate, not which SQLite/protocol/tool assertions the helper actually performs. Packaging also depends on that missing input; a fresh build would need it. Tests use a fake helper/runner for setup sequencing (`tests/mcpSetup.test.ts:63`, `:73`, `:82`), so they do not fill this gap.

`runProcess` uses argument arrays, `shell:false`, hidden Windows processes, piped stdout/stderr, bounded captured output, and redacted logs. Nonzero exits include a bounded output tail; spawn errors reject. Cancellation/timeout kills the child tree via Windows `taskkill` or a detached Unix process group, with a three-second hard-stop fallback; the default step deadline is five minutes (`src/services/mcpSetupService.ts:31`, `:37`). The audit outer deadline is separately sized for three request/process limits plus diagnostics/backoff (`src/services/mcpSetupService.ts:190`).

### Audit policy and safe retries

**Facts.** The explicit audit runs production-only, high-severity gating, with npm fetch retries disabled in favor of its own bounded policy. A valid complete vulnerability-count report, zero exit, no timeout/error, and no high/critical findings are required; empty, malformed, truncated, or unavailable reports are not success (`scripts/audit-dependencies.cjs:56`, `:63`). High/critical findings stop immediately. Transient DNS/network/timeouts/registry errors retry up to three times with 2s/4s backoff; process-start, TLS, authentication, and local-input errors do not retry (`scripts/audit-dependencies.cjs:74`, `:113`). Registry/ping diagnostics use existing npm settings, redact sensitive values, and never turn connectivity success into an audit pass or disable TLS/auditing (`scripts/audit-dependencies.cjs:90`).

### Publication, errors, and retry limits

**Facts.** After all gates, setup rereads config and refuses publication if its text changed. JSONC edits replace only the entire `vibeknowledge` entry under VS Code `servers` or Cursor `mcpServers`, preserving other entries/comments/settings. VS Code adds `type:"stdio"`; both record the absolute Node command and `[installed index.js, --workspace, canonical workspace, --rag-mode, none]` (`src/services/mcpSetupService.ts:122`, `:200`). It makes a timestamped exclusive backup of nonempty existing config, writes an exclusive same-directory temporary file, then renames it into place. Failed attempts remove only their unique staging directory; previous installations remain, including after successful reconfiguration (`src/services/mcpSetupService.ts:203`).

The configured server later reads the explicit workspace/disabled-RAG arguments, opens its database, registers graph services/tools/resources, and connects stdio. Setup does not itself leave the client server running or generate graphs; the success UI asks the user to trust and start/restart it (`packages/mcp-server/src/config.ts:92`; `packages/mcp-server/src/index.ts:13`; `packages/mcp-server/src/server.ts:29`; `packages/mcp-server/src/rag/ragEngineFactory.ts:19`; `src/commands/mcpSetupCommands.ts:82`).

- **Safe retry:** repair invalid config or concurrent changes, choose supported Node/npm, resolve registry/CA/access problems, or obtain a bundle/platform with working SQLite, then rerun. Each attempt uses fresh staging and preserves previous installs/config until publication. Existing custom fields inside `vibeknowledge` itself are deliberately replaced, not merged (`src/services/mcpSetupService.ts:132`, `:173`, `:202`).
- **Not a full rollback:** the global workspace selection is saved before setup, and missing database initialization precedes health checking; they can persist after failure/cancellation. Backups can also remain after a failed publication (`src/commands/mcpSetupCommands.ts:52`, `:73`; `src/services/mcpSetupService.ts:197`, `:205`). Old successful installs accumulate by design.
- **Inference—remaining race window:** the config comparison is not a lock/compare-and-swap. Another window/client can edit after comparison but before rename; cancellation arriving after the last abort check can likewise still publish. The UI guard covers only this command registration (`src/services/mcpSetupService.ts:200`; `src/commands/mcpSetupCommands.ts:10`).
- **Inference—error wording can overpromise preservation:** the UI catch always says previous config was preserved (`src/commands/mcpSetupCommands.ts:88`). But errors after successful rename—temporary cleanup before `published = true`, or the later “View configuration” action—can report failure after config changed. In the former case staging cleanup could remove the now-referenced install (`src/services/mcpSetupService.ts:207`; `src/commands/mcpSetupCommands.ts:87`). These are narrow failure windows, not observed outcomes.

**Test evidence, not test execution.** Setup tests assert JSONC preservation, version/path behavior, ordering, install/audit/health failure cleanup, concurrent-edit refusal, and cancellation (`tests/mcpSetup.test.ts:9`, `:34`, `:82`, `:110`, `:140`, `:150`, `:174`). UI tests cover registration without database/workspace initialization, trust rejection, settings navigation, and audit-timeout propagation (`tests/mcpSetupCommands.test.ts:53`). Audit tests cover bounded retries, fail-closed invalid reports, TLS rejection, and redaction (`tests/dependencyAudit.test.ts:15`, `:35`, `:87`, `:125`). None establishes the absent helper's actual end-to-end health checks.
