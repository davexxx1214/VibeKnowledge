## 1. Local: debounce and disposal

**Facts.** `DebouncedStructuralGraphUpdater` defaults to **500 ms**. Each `notify` adds the path to a set and restarts the timer: the window is measured from the latest event, not the first. `flush` cancels the timer, sorts/deduplicates the accumulated paths, clears that set, and appends a callback to the `running` promise chain. Its initial `catch` lets a later batch proceed after an earlier batch rejects. ([src/services/structuralGraph/debouncedStructuralGraphUpdater.ts:12](D:/workspace/VibeKnowledge/.vscode-test/task-context-ab-9W8uP7/B/src/services/structuralGraph/debouncedStructuralGraphUpdater.ts:12), [same file:31](D:/workspace/VibeKnowledge/.vscode-test/task-context-ab-9W8uP7/B/src/services/structuralGraph/debouncedStructuralGraphUpdater.ts:31))

`dispose()` marks the instance disposed, discards paths still in the set, and clears the timer. Later notifications do nothing; later `flush()` calls return the existing `running` promise. **Already promise-queued callbacks still execute, and already running callbacks continue**: disposal neither changes that promise chain nor adds a disposed check inside its `.then`. Disposal is synchronous and does not await completion. ([same file:17](D:/workspace/VibeKnowledge/.vscode-test/task-context-ab-9W8uP7/B/src/services/structuralGraph/debouncedStructuralGraphUpdater.ts:17), [same file:31](D:/workspace/VibeKnowledge/.vscode-test/task-context-ab-9W8uP7/B/src/services/structuralGraph/debouncedStructuralGraphUpdater.ts:31), [same file:49](D:/workspace/VibeKnowledge/.vscode-test/task-context-ab-9W8uP7/B/src/services/structuralGraph/debouncedStructuralGraphUpdater.ts:49))
