# Task-context pilot r1: no demonstrated win

One fresh matched pair, three read-only development tasks, identical frozen
VibeKnowledge source, model and effort. This pilot cannot meet the final gate.

| Metric | A: source only | B: selective context Skill |
| --- | ---: | ---: |
| Tool-observed text tokens | 58,488 | 52,199 |
| Uncached input + output | 92,867 | 95,700 |
| Cached input | 1,133,056 | 1,054,464 |
| Output tokens | 10,855 | 11,891 |
| Graph calls | 0 | 2 |
| Critical facts, literal independent grading | 24/24 | 23/24 |

Observed text fell 10.8%, but uncached input plus output increased 3.1%. Even
under equal-quality grading, this does not meet the predefined efficiency gate.
The baseline had no required omissions, so a completeness improvement was not
demonstrated either. No monetary savings or general accuracy claim follows.

The grader flagged B's statement that CLI `path` reads the raw structural graph;
the actual raw command is `structural-path`, while `path` uses the curated graph.
Literal interpretation produces one major error. It may be shorthand in context,
so the severity is audit-sensitive, not strong evidence of a systematic quality
regression. Either interpretation leaves the overall no-win conclusion unchanged.

Both agents still read substantial source to establish feature behavior. A graph
slice saved some navigation but did not supply a reviewed feature explanation.
The next candidate adds source-backed feature briefs, generated by an independent
author without task prompts, rubrics, prior reports or outcomes. Generation cost
will be reported separately; subsequent task agents will get no expected answers.
The protocol's tasks, gates and independent grading remain unchanged.

See metrics.json for numerical telemetry, per-task reads and tokenizer details;
grades.md / grades.json retain the independent rubric assessment. Graph extraction
took 5,453 ms for 156 indexed files. These were warm artifact queries, not a
measurement of first-time graph generation plus task completion.
