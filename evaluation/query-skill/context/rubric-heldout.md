## Grading rules

- Score each task separately. `C` = critical required fact; `S` = supplemental fact. Supplemental coverage cannot compensate for missing critical coverage.
- Per item: `1` for a correct causal explanation with traceable evidence, `0.5` for a materially incomplete explanation or missing evidence, `0` for omission, error, or an internal contradiction. Equivalent wording and alternative valid anchors count; do not require every listed anchor.
- Require relationships, not file inventories. No credit for generic warnings, answer length, speculative redesign, or unrelated test lists. Proposed changes/tests must be distinguished from current behavior/existing tests. Read-only answers need not execute tests.
- Record major false claims separately; any such claim precludes a fully correct/safe verdict. An omission is not itself a false claim. Supplemental nuances are optional, but categorical assertions contradicting them remain false.
- Report critical coverage, supplemental coverage, major false claims with contradictory evidence, and at most two sentences on the most important missing causal link.

## Task H1 — Entity-description edits and reset: storage, scope, invalidation, consumers

Critical: 8 items. Supplemental: 2 items.

1. **C1 — UI-to-service route.** The edit/reset commands delegate to `EntityCommands`, which resolves an entity ID and calls `KnowledgeGraphService.updateDescription` / `resetGeneratedDescription`, then the Agent graph service. Edit can pick an entity; canceling input (`undefined`) does not write, while an empty string is a submitted description. Reset requires a resolved Agent-origin entity. Evidence: `src/extension.ts:548`, `src/ui/commands/entityCommands.ts:224`, `src/ui/commands/entityCommands.ts:242`, `src/ui/commands/entityCommands.ts:267`, `src/services/knowledgeGraphService.ts:261`.
2. **C2 — Durable overlay, not generated-file editing.** `AgentGraphService` resolves the selected occurrence to its stable entity key, then `AgentEntityOverrideService` upserts/deletes `agent_entity_overrides` and calls `DatabaseService.save()`. The workspace `.vscode/.knowledge/graph.sqlite` stores manual prose; generated `agent-graph.json` is not rewritten by this route. Evidence: `src/services/agentGraph/agentGraphService.ts:144`, `src/services/agentGraph/agentEntityOverrideService.ts:47`, `src/services/agentGraph/agentEntityOverrideService.ts:61`, `src/services/database.ts:19`, `src/services/database.ts:120`, `src/services/database.ts:165`.
3. **C3 — Identity scope and reset semantics.** UI IDs are group-specific, but the override is keyed by the stable entity key, so it applies to all occurrences of that symbol in this workspace and survives manifest regeneration. Reset deletes the override and reveals each group's latest generated prose, not the original edit-time text and not necessarily one identical description across groups. Empty manual prose remains an override because presence is tested against `undefined`. Evidence: `src/services/agentGraph/agentGraphService.ts:143`, `src/services/agentGraph/agentGraphService.ts:158`, `src/services/agentGraph/agentGraphService.ts:537`; regression: `src/services/agentGraph/agentGraphService.test.ts:393`.
4. **C4 — Why explicit invalidation matters.** Set/reset calls `refresh()`, clearing `cachedSignature` and reloading/reapplying overrides. Normal graph cache validity uses manifest `mtimeMs:size`, not database changes, so changing only the SQL overlay would otherwise leave the extension snapshot cached. Do not assume an arbitrary external database edit has the same refresh path. Evidence: `src/services/agentGraph/agentGraphService.ts:108`, `src/services/agentGraph/agentGraphService.ts:153`, `src/services/agentGraph/agentGraphService.ts:165`, `src/services/agentGraph/agentGraphService.ts:232`.
5. **C5 — UI consumers and push/pull distinction.** After the command returns normally, the extension refreshes the tree, current GraphView, and CodeLens. Tree refresh reloads the shared graph and emits an event; GraphView sends graph data including descriptions; CodeLens emits its invalidation event and rebuilds from the shared service. Hover reads the shared service on a later request; there is no explicit hover-refresh call here. Evidence: `src/extension.ts:553`, `src/extension.ts:567`, `src/providers/treeDataProvider.ts:172`, `src/ui/webview/graphView.ts:124`, `src/ui/webview/graphView.ts:263`, `src/ui/webview/graphView.ts:458`, `src/providers/codeLensProvider.ts:28`, `src/providers/codeLensProvider.ts:73`, `src/providers/hoverProvider.ts:25`. Full credit needs the main three invalidations and the consumer handoff, not a recital of every UI method.
6. **C6 — MCP consumers also apply the overlay.** MCP merged entity search/overview obtains the SQL override map and applies it to Agent entities; graph-query engine creation likewise supplies that map. Manual prose can therefore affect returned descriptions and description-based search without replacing the Agent structural source. This is a read-side merge, not a push notification from the edit command or regeneration of structural relations. Evidence: `packages/mcp-server/src/mergedGraph.ts:26`, `packages/mcp-server/src/mergedGraph.ts:60`, `packages/mcp-server/src/mergedGraph.ts:110`, `packages/mcp-server/src/database.ts:379`, `packages/mcp-server/src/agentGraphStore.ts:329`, `packages/mcp-server/src/agentGraphStore.ts:565`, `packages/mcp-server/src/tools/registerGraphQueryTools.ts:251`.
7. **C7 — Important failure boundaries.** A missing/unresolvable entity or absent override store can return `null`; invalid manifests become an empty snapshot with `lastError`, not a partially usable graph. A database save error is thrown to command error handling; save is a direct export/write, so do not promise atomic persistence or rollback of the already-mutated in-memory SQL state. Tie at least two concrete cases to their effect on visible/persisted state. Evidence: `src/services/agentGraph/agentGraphService.ts:148`, `src/services/agentGraph/agentGraphService.ts:232`, `src/ui/commands/entityCommands.ts:256`, `src/services/database.ts:165`, `src/extension.ts:557`.
8. **C8 — Regression coverage mapped to the contract.** Identify service edit/reset delegation (`src/services/knowledgeGraphService.test.ts:131`), cross-group override persistence and latest-prose reset (`src/services/agentGraph/agentGraphService.test.ts:393`), and a consumer check such as MCP overlay/search (`packages/mcp-server/tests/mergedGraph.test.ts:77`) or CodeLens description rendering (`src/providers/knowledgeCodeLensModel.test.ts:9`). Missing/invalid manifest tests are at `src/services/agentGraph/agentGraphService.test.ts:274` and `:357`. These tests do not by themselves prove end-to-end command/UI refresh or persistence-failure rollback; proposed additions must be labeled.
9. **S1 — Canonical identity safety.** Exact-key override lookup wins; a spelling-normalized fallback is used only for one unambiguous match, and reset can delete that matching stored spelling. Path/symbol case is not indiscriminately collapsed. Evidence: `src/services/agentGraph/agentEntityOverrideService.ts:22`, `src/services/agentGraph/agentEntityOverrideService.ts:61`, `src/services/agentGraph/agentEntityOverrideService.ts:78`; tests: `src/services/agentGraph/agentEntityOverrideService.test.ts:8`, `:50`. MCP uses the corresponding exact/unambiguous overlay behavior at `packages/mcp-server/src/agentGraphStore.ts:571`.
10. **S2 — UI success is not a universal commit assertion.** Edit checks a null update result, but reset currently ignores the returned result before displaying success. Extension refresh calls also run after normal cancellation/no-op returns, not exclusively after successful writes. Evidence: `src/ui/commands/entityCommands.ts:248`, `src/ui/commands/entityCommands.ts:256`, `src/ui/commands/entityCommands.ts:273`, `src/extension.ts:553`, `src/extension.ts:567`.

Major false claims:

- Edits/reset rewrite Agent-generated JSON or structural facts, or reset regenerates a graph (C2/C3/C6).
- Overrides are stored by group-specific ID, affect only the selected group, are user-global across projects, or are lost on ordinary regeneration (C2/C3).
- Empty text means delete/reset; reset restores the historical description from when editing began (C1/C3).
- Updating SQL alone automatically invalidates the manifest-signature cache or pushes every consumer, including an already-open hover (C4/C5/C6).
- Save failures are silently treated as success, fully rolled back/atomically persisted, or invalid graphs remain partially exposed (C7).
- Canonical fallback arbitrarily selects an ambiguous override or treats case-distinct symbols as identical (S1); reset success always verifies the service result (S2).

## Task H2 — MCP setup: selection, child processes, publication, failures, retries

Critical: 9 items. Supplemental: 1 item.

1. **C1 — Registration and UI gating.** `activate()` registers MCP setup before the normal workspace/database initialization path. `knowledge.setupMcp` and the settings-menu install action reach the same installer. The installer rejects untrusted workspaces, prevents overlapping selection/runs using `selecting`/`active`, and supports cancellation through an `AbortController`. Commands being available without an open project is distinct from the user still needing to select a target. Evidence: `src/extension.ts:36`, `src/commands/mcpSetupCommands.ts:8`, `src/commands/mcpSetupCommands.ts:15`, `src/commands/mcpSetupCommands.ts:53`, `src/commands/mcpSetupCommands.ts:100`.
2. **C2 — Workspace/client selection and validation.** A configured `knowledgeGraph.mcp.workspacePath` takes precedence; otherwise users choose a local workspace folder or another folder. This is not hard-wired to the first workspace. The UI requires an absolute path, selects VS Code/Cursor from settings/app detection, previews the config target for confirmation, and saves the preference globally. The service resolves/validates the directory and validates existing JSONC before launching processes. Evidence: `src/commands/mcpSetupCommands.ts:23`, `src/commands/mcpSetupCommands.ts:39`, `src/commands/mcpSetupCommands.ts:44`, `src/commands/mcpSetupCommands.ts:52`, `src/services/mcpSetupService.ts:154`.
3. **C3 — One selected external runtime.** The selected Node is probed for version/resolved `execPath`; accepted stable versions are `>=26.1.0 <27`. The service finds an absolute npm CLI (configured or beside Node), requires npm 11+, runs npm with that resolved Node, and prepends its directory to a copied child environment. Published MCP config uses the same resolved Node, not Electron's extension-host runtime or an unrelated shell npm. Evidence: `src/services/mcpSetupService.ts:91`, `src/services/mcpSetupService.ts:98`, `src/services/mcpSetupService.ts:104`, `src/services/mcpSetupService.ts:162`, `src/services/mcpSetupService.ts:203`.
4. **C4 — Isolated, ordered preparation gates.** UI supplies `dist/mcp-server` and extension global-storage `mcp`. Each attempt creates a unique lock/runtime-derived staging directory, copies the bundle, runs locked production `npm ci --audit --ignore-scripts`, then the explicit audit helper, ensures a missing database, and runs the native SQLite/MCP health check before publishing config. Dependencies are not installed into the business workspace, and this does not regenerate graphs. Evidence: `src/commands/mcpSetupCommands.ts:64`, `src/commands/mcpSetupCommands.ts:73`, `src/commands/mcpSetupCommands.ts:85`, `src/services/mcpSetupService.ts:171`, `src/services/mcpSetupService.ts:179`, `src/services/mcpSetupService.ts:197`.
5. **C5 — Child-process/error boundary.** `runProcess` spawns command plus argument arrays with `shell:false` and hidden Windows windows; paths/metacharacters stay arguments. It rejects process errors/nonzero exits and cancellation/timeouts, bounds/redacts diagnostic output, and tries to terminate child trees/process groups with a hard-stop fallback. Cancellation is propagated from progress/disposal and checked between setup stages. Evidence: `src/services/mcpSetupService.ts:31`, `src/services/mcpSetupService.ts:37`, `src/services/mcpSetupService.ts:48`, `src/services/mcpSetupService.ts:65`, `src/services/mcpSetupService.ts:82`, `src/commands/mcpSetupCommands.ts:13`, `src/commands/mcpSetupCommands.ts:61`, `src/services/mcpSetupService.ts:186`. Exact timeout arithmetic is not required.
6. **C6 — Scoped config publication.** VS Code uses `.vscode/mcp.json` / `servers.vibeknowledge`; Cursor uses `.cursor/mcp.json` / `mcpServers.vibeknowledge`. JSONC edits preserve unrelated entries/comments and set Node plus bundled entry, selected workspace, and RAG-none arguments. After preparation, a reread rejects observed concurrent config changes; an existing nonempty file is backed up and the new config is written through a unique temp file and rename. Evidence: `src/services/mcpSetupService.ts:118`, `src/services/mcpSetupService.ts:122`, `src/services/mcpSetupService.ts:201`.
7. **C7 — Safe whole-setup retries and completion meaning.** Tested install/audit/health failures stop before config publication; the failed attempt's staging directory is removed while earlier installations remain. The UI logs errors, offers settings, and clears run guards in `finally`, permitting a fresh corrected retry. A successful setup still asks the user to trust/start/restart MCP in the client; it is not automatic launch. Evidence: `src/services/mcpSetupService.ts:213`, `src/services/mcpSetupService.ts:216`, `src/commands/mcpSetupCommands.ts:82`, `src/commands/mcpSetupCommands.ts:88`, `src/commands/mcpSetupCommands.ts:97`.
8. **C8 — Audit retries are bounded and fail closed.** High/critical vulnerabilities and unavailable/invalid audit reports block setup. The helper may retry transient availability failures up to three attempts with backoff, but does not retry a vulnerability into success or bypass TLS/auditing; certificate/auth/local-input failures are not blindly retried. A successful connectivity diagnostic is not a security verdict. Distinguish this inner audit retry from a fresh whole-setup attempt. Evidence: `scripts/audit-dependencies.cjs:3`, `scripts/audit-dependencies.cjs:63`, `scripts/audit-dependencies.cjs:74`, `scripts/audit-dependencies.cjs:90`, `scripts/audit-dependencies.cjs:113`; service gate: `src/services/mcpSetupService.ts:187`.
9. **C9 — Regression tests matched to risk.** Map UI availability/trust/timeout forwarding to `tests/mcpSetupCommands.test.ts:53`, `:58`, `:72`; runtime/config/process boundaries to `tests/mcpSetup.test.ts:9`, `:34`, `:37`, `:82`, `:167`; and failed staging cleanup/concurrent edits/cancellation to `tests/mcpSetup.test.ts:110`, `:140`, `:150`, `:174`. Audit distinctions are tested at `tests/dependencyAudit.test.ts:23`, `:28`, `:35`, `:87`, `:106`. Full credit requires examples tied to preparation, publication failure, and safe retry—not every named test. Mocked setup/health results do not prove a live external client connection.
10. **S1 — Scope of preservation guarantees.** Setup is not one transaction over every side effect. The workspace preference is saved before setup; database initialization occurs before health checking; backups/staging/temporary artifacts have their own lifetimes. The config reread is not a cross-process lock, and there is no universal rollback after config rename. Thus “preparation failure preserves prior config” is supported, while “every possible failure leaves the entire system unchanged” is not. Evidence: `src/commands/mcpSetupCommands.ts:52`, `src/services/mcpSetupService.ts:197`, `src/services/mcpSetupService.ts:201`, `src/services/mcpSetupService.ts:205`, `src/services/mcpSetupService.ts:213`.

Major false claims:

- MCP command registration requires database initialization/an already-open workspace; setup always targets workspace folder zero or ignores configured workspace (C1/C2).
- Electron/any Node version is used, npm is independently shell-resolved, or selected runtime paths are interpolated into command strings (C3/C5).
- `npm install`/build scripts run in the business project, dependency lifecycle scripts are required, or setup generates the graph/installs the query Skill (C4).
- Config is published before audit/health checks, other servers are discarded, Cursor and VS Code share the same config key, or observed concurrent edits are overwritten (C6).
- Failed retry deletes previous installations, failed audit/network checks are success, retries are unlimited, TLS/audit is disabled to recover, or npm ping alone proves a clean audit (C7/C8).
- Cancellation leaves processes intentionally running; setup success automatically starts/trusts the user's MCP client; or mocked tests prove live connectivity (C5/C7/C9).
- Every failure guarantees full rollback/no side effects, or the reread-and-rename sequence is a cross-process transactional lock (S1).
