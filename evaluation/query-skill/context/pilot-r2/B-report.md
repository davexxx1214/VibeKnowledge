# Structural refresh and query Skill installation

Read-only analysis of this workspace. Source and tests were inspected through the observer; tests, builds and installations were not run. The installed query Skill routed the local question to source and the two broader questions to focused feature briefs, followed by source verification. “Fact” describes inspected implementation; “Inference” describes its consequences or proposed regression coverage. Paths below are repository-relative.

## 1. Local: DebouncedStructuralGraphUpdater

- **Fact — default and scheduling:** the constructor defaults to **500 ms**. Each `notify()` adds to a `Set` and restarts the timer, so the delay runs from the latest notification, not the first. `flush()` clears the timer, sorts/deduplicates the accumulated paths and captures that batch in a promise chain. It serializes callbacks and catches a previous batch's rejection before starting the next; it does not retry the failed batch. (`src/services/structuralGraph/debouncedStructuralGraphUpdater.ts:12-46`.)
- **Fact — disposal:** `dispose()` sets `disposed`, clears accumulated paths and cancels the timer. Subsequent `notify()` is ignored and subsequent `flush()` returns the existing `running` promise. Crucially, callbacks **already queued by `flush()` still execute**, and an already running callback continues: disposal neither changes the promise chain nor adds a disposed check inside its `.then(() => callback(paths))`. “Queued” paths awaiting a timer are discarded; already captured callback batches are not. (`src/services/structuralGraph/debouncedStructuralGraphUpdater.ts:17-55`.)
- **Tests:** the coalescing/reset/sorted-path test uses an explicit 100 ms delay, not the default (`src/services/structuralGraph/debouncedStructuralGraphUpdater.test.ts:9-27`); the serialization test queues two flushes and waits for their resolvers (`:29-53`). Both dispose only after work completes. **Inference — coverage to add before changing semantics:** default-delay timing, dispose-before-timer, dispose with a queued-but-not-started callback, dispose during an active callback, and rejection followed by another batch are not asserted by these two tests.

## 2. Refresh: event → scheduler → generator → consumers

### Registration and execution

1. **Fact:** activation uses `workspaceFolders[0]` and constructs separate Agent, Knowledge, structural and curated graph services. The structural updater callback checks that `structural-graph.json` already exists, calls `generate()` without path/scope options, logs statistics and catches failures; the extension explicitly passes 500 ms. Thus background maintenance does not bootstrap a missing graph. (`src/extension.ts:48-58`, `:174-204`; `src/services/structuralGraph/structuralGraphService.ts:59-61`.)
2. **Fact:** first-root watchers register create/change/delete listeners for `**/*.{ts,tsx,js,jsx,html,htm}` and `**/{tsconfig,jsconfig}*.json`. Paths are normalized, then parent-relative paths and `node_modules/dist/out/build/coverage/.git/.vscode` segments are rejected. Accepted paths go to `notify()`. Watchers, listeners and updater enter `context.subscriptions`. (`src/extension.ts:205-240`.)
3. **Fact:** the service calls the shared generation Skill's `updateStructuralGraph`, passing workspace, optional extraction settings, `.vscode/.knowledge/structural-graph.json` and `.vscode/.knowledge/cache/structural`; it stores statistics only after that call returns. (`src/services/structuralGraph/structuralGraphService.ts:3-9`, `:25-44`, `:82-98`.) The extractor scans supported files, combines them with compiler configuration, builds a TypeScript program, uses a configuration hash/cache, determines changed/affected files and runs its second pass for the affected set. (`resources/skills/vibeknowledge-dependency-graph/scripts/structural-extractor.mjs:134-210`.) **Inference:** changing debounce or watcher filters changes when refresh runs, not its extraction scope: event paths are only used for logging. “Background” is scheduling here, not a worker thread; the called generation API is synchronous.

### Persistence, failure and staleness boundaries

- **Fact:** old-graph/cache corruption, protected changed-file parse failures and suspicious shrink can stop replacement. Validation and replacement checks precede writing; missing or configuration-incompatible cache can rebuild normally, whereas malformed cache requests recovery. (`resources/skills/vibeknowledge-dependency-graph/scripts/structural-extractor.mjs:119-125`, `:204-229`, `:1586-1619`, `:2226-2296`.) The background callback logs and stops; it neither forces recovery nor schedules a retry. The explicit `knowledge.generateStructuralGraph` command instead offers a modal force-rebuild choice for recognized recovery errors. (`src/extension.ts:184-203`, `:339-370`.)
- **Fact:** cache entries, a previous graph when structural facts differ, current graph, and cache index are separate writes, in that order. Each atomic text write uses a temporary file and rename. (`resources/skills/vibeknowledge-dependency-graph/scripts/structural-extractor.mjs:2189-2223`, `:2362-2372`.) **Inference:** the background warning's blanket “previous graph was preserved” wording is stronger than the implementation for arbitrary I/O failures: a cache-index failure can happen after the current graph was replaced. This is atomic per file, not a transaction across all artifacts.
- **Inference:** a missed/excluded event, no existing graph, a safety rejection, or continuous notifications can leave the snapshot behind source. Disposing the updater does not cancel batches already chained. Serialization applies to this updater's callbacks, not every generator invocation or external process. These follow from the watcher filter, existence guard and updater implementation above.

### Consumers are intentionally separate

- **Fact:** GraphView structural overview, path, entity neighbors, aggregate drill-down and code navigation read the structural service when requested; the service reads/validates the file rather than caching a graph. (`src/ui/webview/graphView.ts:219-241`, `:324-416`, `:687-701`; `src/services/structuralGraph/structuralGraphService.ts:63-75`, `:101-111`.) Query CLI `context`, `impact`, `structural-path` and `structure` also read the existing structural snapshot; diff reads the previous snapshot. (`packages/mcp-server/src/queryCli.ts:70-95`; `packages/mcp-server/src/structuralGraphStore.ts:83-131`.)
- **Fact:** background structural success does **not** curate Agent groups or notify editor providers. The explicit curate flow generates structure and then passes it to `CuratedGraphService.curate()`, which merges/validates a group and writes `agent-graph.json`. (`src/extension.ts:184-203`, `:486-501`; `src/services/structuralGraph/curatedGraphService.ts:34-59`.) **Inference:** updated structural drill-downs can coexist with stale curated labels/relationships; an already displayed structural slice receives no automatic replacement from this callback.
- **Fact:** a different watcher observes `agent-graph.json` and refreshes tree, open GraphView and CodeLens. Tree refresh invalidates/reloads AgentGraphService through KnowledgeGraphService and emits its event; CodeLens refresh merely fires invalidation for the next query. GraphView refresh posts current Knowledge groups only if a panel exists. (`src/extension.ts:265-282`; `src/providers/treeDataProvider.ts:170-175`; `src/services/knowledgeGraphService.ts:56-68`; `src/providers/codeLensProvider.ts:28-33`, `:73-75`; `src/ui/webview/graphView.ts:124-126`, `:263-273`, `:457-469`.) The `knowledge.refresh` command refreshes tree and CodeLens, not generation or GraphView; webview “refresh” resends graph data without explicitly invalidating the Agent cache. (`src/extension.ts:749-756`; `src/ui/webview/graphView.ts:219-222`.)
- **Fact:** AgentGraphService caches by mtime and size; explicit refresh clears the signature. Missing input yields an empty snapshot without an error; invalid/read-failing input also yields empty, but records an error. Snapshot reconstruction reapplies human descriptions. (`src/services/agentGraph/agentGraphService.ts:108-114`, `:232-260`, `:540-574`.) **Inference:** unchanged signatures without explicit invalidation can hide replacement content. This empty-on-invalid reader policy is different from structural generation's preserve-old-output safety policy.

### Regression tests to retain and extend

## 3. Install: changing the query Skill directory

### Registration and path ownership

**Fact:** `knowledge.installQuerySkill` is contributed separately from `knowledge.installDependencyGraphSkill`, with an Explorer title action. Its real handler constructs `AgentSkillService(context.extensionPath, QUERY_SKILL_NAME)` and uses the activation-time first workspace root. Without a workspace, both are warning placeholders. (`package.json:164-173`, `:223-232`; `src/extension.ts:48-58`, `:843-879`, `:986-998`.)

| Layer | Query Skill | Generation Skill |
| --- | --- | --- |
| Authoring/build input | `resources/skills/vibeknowledge-query` plus `packages/mcp-server/src/queryCliEntry.ts` | `resources/skills/vibeknowledge-dependency-graph` |
| Extension install source | `<extension>/dist/skills/vibeknowledge-query` | `<extension>/resources/skills/vibeknowledge-dependency-graph` |
| Current project target | `<workspace>/.agents/skills/vibeknowledge-query` | `<workspace>/.agents/skills/vibeknowledge-dependency-graph` |

Sources: `scripts/build-query-skill.cjs:5-10`; `src/services/agentSkillService.ts:4-33`.

- **Fact:** `getInstallDirectory()` is shared by both names; `isInstalled()` checks only target-directory existence. The handler asks Update/Cancel when that directory exists, calls `install()`, then optionally opens its returned `SKILL.md`. Source `SKILL.md` is required; the query source additionally requires `scripts/query.cjs`. Recursive copying skips non-file/non-directory entries, overwrites only with explicit permission and leaves extra destination files in place. (`src/services/agentSkillService.ts:23-81`; `src/extension.ts:849-877`.)
- **Inference — change boundary:** a query-only relocation must branch on the Skill name or separate destination policy; blindly changing the shared helper moves generation installation too. Decide whether old-location installs count as installed, migrate, or coexist: current detection cannot find them after a path change. All open-file behavior should keep using the service's returned path. Direct copy has no transaction/rollback, so retain explicit partial-install recovery semantics.
- **Fact:** English and Chinese query success messages hard-code `.agents/skills`; generation messages independently hard-code it too. (`src/i18n/en.ts:222-239`; `src/i18n/zh.ts:223-240`.) **Inference:** update only the intended query text for a query-only relocation, and test discovery in the intended Agent host; filesystem copying does not establish that a host discovers a new directory.

### Bundling and packaging

**Fact:** prepublish runs production compile. `esbuild.js` creates the extension bundle and invokes separate MCP/query asset builds; query output is `dist/skills/vibeknowledge-query`. The query builder copies instruction assets, bundles the CLI as Node 26 CommonJS, resolves root `zod`, rejects bundled native SQLite/MCP SDK/Google dependencies, and copies project/Zod licenses. (`package.json:454-463`; `esbuild.js:11-25`, `:28-55`; `scripts/build-query-skill.cjs:5-24`.) `.vscodeignore` excludes `src`, `scripts`, `packages`, `node_modules` and raw query resources, but not `dist/skills` or generation resources. (`.vscodeignore:4-14`.) **Inference:** changing the project target alone need not relocate the extension's bundle; changing the bundle source requires coordinated builder and service edits and package verification. The inspected packaging rules establish intended contents, not an actually inspected VSIX.

**Fact:** CLI execution enforces Node >=26.1 <27, resolves workspace from the supplied argument or cwd, and reads existing graph artifacts; it does not derive graph location from the Skill installation directory. Missing/invalid artifacts fail; human overrides use read-only built-in SQLite. (`packages/mcp-server/src/queryCli.ts:47-72`, `:97-109`, `:157-167`; `packages/mcp-server/src/structuralGraphStore.ts:88-131`.) **Inference:** preserve the internal `scripts/query.cjs` relative layout and workspace selection when relocating; installation does not populate project graphs.

### Not MCP setup or graph generation

**Fact:** MCP setup is registered separately before normal graph initialization (`src/extension.ts:31-38`). It checks workspace trust, permits selecting/configuring a different workspace, copies from `<extension>/dist/mcp-server` into global storage, installs locked dependencies, audits and health-checks, optionally initializes missing SQLite, and finally publishes `.cursor/mcp.json` or `.vscode/mcp.json` with backup/concurrency protection. (`src/commands/mcpSetupCommands.ts:15-79`, `:100-109`; `src/services/mcpSetupService.ts:147-218`.) Query Skill installation only copies assets and opens instructions; it invokes none of those operations (`src/services/agentSkillService.ts:40-55`; `src/extension.ts:843-879`). Its CLI sharing a source package with MCP is code reuse, not a requirement to install/start MCP.

**Fact:** neither Skill installation invokes generation. Structural generation calls the shared extractor and writes structural/cache sidecars; explicit curation additionally writes the Agent graph, as traced in section 2. Installing the generation Skill is also only copying its assets, not running them.

### Regression tests

- `src/services/agentSkillService.test.ts:42-63`: independent query installation, runtime copy, duplicate prevention, missing query runtime and unknown-name rejection. `:64-82` explicitly fixes the generation destination to `.agents/skills`; `:85-120` covers explicit overwrite, partial installation recovery and missing source assets. **Inference:** query destination assertions currently derive the runtime path from the service, so add an exact expected query path and old-location policy test rather than relying only on that self-referential check.
- `tests/querySkill.test.ts:22-46`: build/copy portability without `node_modules`, spaces/Unicode, forbidden dependency inputs and licenses. `:48-98`: read-only queries, bad arguments, missing/corrupt artifacts and unchanged SQLite bytes. Preserve these when moving a portable bundle; they do not test VS Code command prompts or actual Agent-host discovery.
- Separate MCP regression candidates are identifiable by their tests: install/audit/handshake gating and concurrent edits/cancellation (`tests/mcpSetup.test.ts:82`, `:140`, `:150`), plus no-workspace registration/trust gating (`tests/mcpSetupCommands.test.ts:53`, `:58`). These are distinct from query Skill destination tests; only their test names were inspected here.
