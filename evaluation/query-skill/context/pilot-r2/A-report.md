# Structural refresh and query Skill installation

Source-only inspection; no tests, builds, installations, or graph generation were run. Source paths below are relative to this repository; line numbers refer to the inspected checkout. **Fact** describes implementation/tests; **Inference** describes a consequence or proposed regression coverage.

## 1. Local: DebouncedStructuralGraphUpdater

- **Fact — delay:** The constructor default is **500 ms** (`src/services/structuralGraph/debouncedStructuralGraphUpdater.ts:12`). Each `notify()` adds to a `Set`, cancels the current timer, and starts a fresh delay: this is a trailing debounce, not a fixed polling interval (`src/services/structuralGraph/debouncedStructuralGraphUpdater.ts:17`). The extension independently passes an explicit `500`, so changing only the constructor default would not change background refresh timing (`src/extension.ts:184`, `src/extension.ts:203`).
- **Fact — dispatch:** `flush()` cancels the timer, sorts/deduplicates the accumulated paths, clears them, and appends the callback to `running`. Catching the predecessor rejection lets a later batch proceed; the current callback's rejection still belongs to the returned promise (`src/services/structuralGraph/debouncedStructuralGraphUpdater.ts:31`).
- **Fact — disposal:** `dispose()` sets the flag, clears unflushed paths, and cancels the timer. Later `notify()` does nothing; later `flush()` returns the existing `running` promise (`src/services/structuralGraph/debouncedStructuralGraphUpdater.ts:17`, `src/services/structuralGraph/debouncedStructuralGraphUpdater.ts:31`, `src/services/structuralGraph/debouncedStructuralGraphUpdater.ts:49`).
- **Inference — queued/running callbacks survive:** Paths already captured by `flush()` are in a promise closure, not the cleared `Set`. The `.then(() => this.callback(paths))` has no disposal check, and disposal neither replaces the chain nor supplies an abort signal. Thus disposal does **not** cancel callbacks already queued behind another callback, nor stop one already running; it does not await completion (`src/services/structuralGraph/debouncedStructuralGraphUpdater.ts:39`, `src/services/structuralGraph/debouncedStructuralGraphUpdater.ts:49`).
- **Tests:** `src/services/structuralGraph/debouncedStructuralGraphUpdater.test.ts:9` verifies duplicate coalescing, sorted paths, and resetting a custom 100 ms window. `src/services/structuralGraph/debouncedStructuralGraphUpdater.test.ts:29` verifies serialization of two explicitly flushed batches during an active callback. These tests dispose only after completion; they do not assert the default delay, pending-timer disposal, already-enqueued callback disposal, or rejection recovery. Those are distinct regression cases if lifecycle semantics change.

## 2. Refresh: event → schedule → generation → consumers

### Execution chain

1. **Fact — registration:** Activation requires a workspace, takes the first folder, and constructs the structural service/updater after service initialization (`src/extension.ts:48`, `src/extension.ts:174`). Two first-folder watchers cover `**/*.{ts,tsx,js,jsx,html,htm}` and `**/{tsconfig,jsconfig}*.json`. Create/change/delete events share a handler that normalizes relative paths and excludes parent-relative paths and `node_modules`, `dist`, `out`, `build`, `coverage`, `.git`, `.vscode`; updater, watchers, and event subscriptions enter `context.subscriptions` (`src/extension.ts:205`, `src/extension.ts:217`, `src/extension.ts:231`).
2. **Fact — scheduling:** The 500 ms serialized updater above calls a callback that first checks `hasGraph()`. Missing output means a no-op: background events do not bootstrap a graph. Otherwise it calls synchronous `generate()` with no options. `changedPaths` only contributes its length to logging; it is not the incremental extraction input. The callback catches generation errors and warns, without requeuing or forcing (`src/extension.ts:184`).
3. **Fact — service boundary:** `StructuralGraphService` uses workspace `.vscode/.knowledge/structural-graph.json`, `.previous.json`, and `cache/structural`. `hasGraph()` means file existence, not valid/fresh data. `generate()` delegates to the shared `resources/skills/vibeknowledge-dependency-graph/scripts/structural-extractor.mjs` implementation and records statistics only after success (`src/services/structuralGraph/structuralGraphService.ts:25`, `src/services/structuralGraph/structuralGraphService.ts:59`, `src/services/structuralGraph/structuralGraphService.ts:82`).
4. **Fact — incremental generation:** `updateStructuralGraph()` reads/validates the old graph, extracts, checks safe replacement, then writes (`resources/skills/vibeknowledge-dependency-graph/scripts/structural-extractor.mjs:103`). Extraction defaults to scope `.`, loads compiler configuration, scans TS/TSX/JS/JSX, discovers HTML entrypoints, computes a configuration fingerprint, and constructs a TypeScript program (`resources/skills/vibeknowledge-dependency-graph/scripts/structural-extractor.mjs:138`). Incompatible cache version/scope/configuration rebuilds instead of reusing entries (`resources/skills/vibeknowledge-dependency-graph/scripts/structural-extractor.mjs:1586`). Changed/deleted files and changed summaries seed the transitive reverse-dependency closure, using both old and current dependencies; the second pass runs on that closure (`resources/skills/vibeknowledge-dependency-graph/scripts/structural-extractor.mjs:1990`, `resources/skills/vibeknowledge-dependency-graph/scripts/structural-extractor.mjs:203`). This is a fresh scan with cached contributions, not a patch restricted to notified filenames.
5. **Fact — consumers are separate layers:** The Webview receives the structural service (`src/extension.ts:242`) and reads current disk data when opening structural overviews, paths, neighbors, or aggregates (`src/ui/webview/graphView.ts:324`, `src/ui/webview/graphView.ts:340`, `src/ui/webview/graphView.ts:365`, `src/ui/webview/graphView.ts:407`). MCP analysis tools likewise read through a read-only store on each request; diff additionally reads the previous snapshot (`packages/mcp-server/src/structuralGraphStore.ts:88`, `packages/mcp-server/src/tools/registerStructuralAnalysisTools.ts:46`, `packages/mcp-server/src/tools/registerStructuralAnalysisTools.ts:95`). The query CLI also consumes these snapshots (`packages/mcp-server/src/queryCli.ts:70`).
6. **Fact — curated graph is not automatically regenerated:** Product-level knowledge data is AgentGraphService-backed (`src/services/knowledgeGraphService.ts:48`). The explicit curate command generates structure, calls `CuratedGraphService.curate()`, and refreshes Agent/tree/Webview/CodeLens (`src/extension.ts:486`, `src/extension.ts:522`). Curation replaces one merged group in `agent-graph.json`, not `structural-graph.json` (`src/services/structuralGraph/curatedGraphService.ts:34`, `src/services/structuralGraph/curatedGraphService.ts:47`). The separate `agent-graph.json` watcher refreshes the views (`src/extension.ts:265`). Background structural refresh does none of those actions (`src/extension.ts:184`).

### Failure and staleness boundaries

- **Fact:** Corrupt graph/cache, a previously valid changed file that no longer parses, and abnormal shrink can reject replacement. Force bypasses recovery checks; normal background refresh never sets it (`resources/skills/vibeknowledge-dependency-graph/scripts/structural-extractor.mjs:1586`, `resources/skills/vibeknowledge-dependency-graph/scripts/structural-extractor.mjs:2055`, `resources/skills/vibeknowledge-dependency-graph/scripts/structural-extractor.mjs:2226`). The manual generate command offers an explicit modal force-rebuild choice (`src/extension.ts:339`). **Inference:** failures can leave intentionally stale snapshots indefinitely until another event or manual action; failed batches are not retried automatically.
- **Fact:** Schema validation occurs before writes. Individual files are written to temporary paths and renamed. The sequence is cache entries → previous graph (if entity/relation facts differ) → current graph → cache index (`resources/skills/vibeknowledge-dependency-graph/scripts/structural-extractor.mjs:2189`, `resources/skills/vibeknowledge-dependency-graph/scripts/structural-extractor.mjs:2362`). **Inference:** this is not a multi-file transaction. For example, a cache-index write failure can occur after the current graph was replaced, so the callback's blanket “previous graph was preserved” warning is stronger than the guarantee for arbitrary I/O failures. There is also no cross-process writer lock in this path.
- **Inference:** Debounce extends under sustained events, extraction runs synchronously on the extension host, and activation does not immediately refresh an existing graph. Therefore “500 ms” is a quiet-window delay, not an end-to-end freshness guarantee. Only registered first-folder source/config events trigger work; changes solely to other inputs such as package metadata are not directly watched (`src/extension.ts:184`, `src/extension.ts:205`; extractor program construction at `resources/skills/vibeknowledge-dependency-graph/scripts/structural-extractor.mjs:179`).
- **Inference:** An already displayed structural slice or curated group can remain old after successful background generation. A later structural request reads new disk data, but the background callback does not push a new slice or re-curate; a saved curated structural path may no longer match current relations (`src/extension.ts:184`, `src/ui/webview/graphView.ts:345`).
- **Fact:** Ordinary service/store reads validate JSON/schema, not live source hashes (`src/services/structuralGraph/structuralGraphService.ts:101`, `packages/mcp-server/src/structuralGraphStore.ts:116`). The CLI's `context` command is a qualified exception: it hashes indexed files, warns about stale/unavailable files, withholds changed-file snippets, and explicitly does not certify new files/configuration/runtime behavior (`packages/mcp-server/src/taskContext.ts:39`, `packages/mcp-server/src/taskContext.ts:139`). Neither a valid snapshot nor a successful query proves complete live-source coverage.

## 3. Install: query Skill directory change

### Registration and path contract

- **Fact:** `package.json:170` contributes `knowledge.installQuerySkill`; `package.json:229` places it in the explorer navigation. Activation registers it with `new AgentSkillService(context.extensionPath, QUERY_SKILL_NAME)` alongside the independently installable generation Skill (`src/extension.ts:843`). Both target the first workspace folder selected at activation (`src/extension.ts:57`). No-workspace activation registers warning placeholders, including this command (`src/extension.ts:48`, `src/extension.ts:986`, `src/extension.ts:992`).
- **Fact:** Query source assets live under `resources/skills/vibeknowledge-query`, but the installer reads the **built bundle** at `<extensionPath>/dist/skills/vibeknowledge-query`. Generation Skill installation instead reads `<extensionPath>/resources/skills/vibeknowledge-dependency-graph` (`scripts/build-query-skill.cjs:5`, `src/services/agentSkillService.ts:11`). The common destination is `<workspaceRoot>/.agents/skills/<skillName>`; the returned/opened document is its `SKILL.md` (`src/services/agentSkillService.ts:23`).
- **Fact:** Installation requires source `SKILL.md` and, for query, `scripts/query.cjs`. Destination-directory existence counts as installed, including partial installations. The command asks before overwrite; the service recursively copies files and skips non-file/non-directory entries (`src/services/agentSkillService.ts:36`, `src/services/agentSkillService.ts:40`, `src/services/agentSkillService.ts:58`; UI at `src/extension.ts:852`).
- **Inference — change surface:** Altering the shared destination helper unconditionally moves **both** Skills, and also changes existence detection and the opened path. Old locations would not be discovered/migrated automatically. Overwrite merges copied files; it does not remove obsolete target-only files, stage an atomic directory replacement, or roll back a partial copy. Decide query-only versus shared relocation and old-install handling before changing it. The success text also hardcodes `.agents/skills` in both languages (`src/i18n/en.ts:227`, `src/i18n/zh.ts:228`).

### Bundling and VSIX packaging

- **Fact:** Prepublish runs production compile; compile typechecks and runs `esbuild.js` (`package.json:454`). The build creates `dist/extension.js` and invokes separate MCP and query-Skill builders (`esbuild.js:11`, `esbuild.js:28`). The query builder copies source assets and bundles `packages/mcp-server/src/queryCliEntry.ts` into `scripts/query.cjs` as minified CommonJS targeting Node 26. It uses root `zod`, rejects server/native/Google dependency inputs, and copies project/Zod licenses (`scripts/build-query-skill.cjs:5`).
- **Fact:** VSIX exclusions remove raw query-Skill resources, `packages`, root `node_modules`, and build scripts, but do not exclude the built `dist/skills` query bundle (`.vscodeignore:8`). **Inference:** changing the installed destination alone does not require moving the build source/output; confusing the two would break packaged installs even if a source checkout appears usable. Rebuild and inspect/test the packaged artifact when changing the bundling contract.
- **Fact:** Runtime workspace selection is `--workspace` or `process.cwd()`, not the Skill installation directory (`packages/mcp-server/src/queryCli.ts:62`). It requires Node >=26.1 and <27 for execution (`packages/mcp-server/src/queryCli.ts:157`). Missing graphs produce explicit errors; query commands do not bootstrap graphs. Curated queries read `agent-graph.json`; structural/context commands read `structural-graph.json`; optional description overrides use built-in read-only SQLite (`packages/mcp-server/src/queryCli.ts:47`, `packages/mcp-server/src/queryCli.ts:70`, `packages/mcp-server/src/queryCli.ts:97`).

### Do not conflate these flows

- **Query Skill installation** is local copying of a self-contained query bundle. Reusing MCP-package query source does not mean installing or starting an MCP server (`scripts/build-query-skill.cjs:8`, `src/services/agentSkillService.ts:54`).
- **MCP setup** is registered before workspace/database initialization (`src/extension.ts:38`). Its separate command checks trust, allows workspace/client selection, uses `<extensionPath>/dist/mcp-server` and extension-global storage `/mcp`, and writes project `.vscode/mcp.json` or `.cursor/mcp.json` (`src/commands/mcpSetupCommands.ts:15`, `:64`, `:100`). The service makes an isolated versioned directory, installs locked production dependencies with scripts disabled, audits, initializes a missing database, health-checks, and only then backs up/publishes configuration (`src/services/mcpSetupService.ts:148`). Its builder emits unbundled ESM plus package/lock/helper files, unlike the query CJS bundle (`scripts/build-mcp-runtime.cjs:18`). None of these paths are the Skill destination.
- **Graph generation/curation** is the extractor/service/manual-command pipeline in section 2, writing workspace `.vscode/.knowledge` artifacts. Installing either Skill does not execute that pipeline; query installation does not imply graph freshness or existence (`src/extension.ts:339`, `src/extension.ts:486`, `src/extension.ts:866`).
