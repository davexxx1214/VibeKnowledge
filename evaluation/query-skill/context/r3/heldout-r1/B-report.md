The installed `vibeknowledge-query` Skill was used to locate the two feature briefs, followed by targeted source and test inspection. All source/query observations used the supplied observer. No source was changed, no graph was generated, and no tests, builds, network requests, or live browser/editor checks were performed. ## 1. Visualization

### Command, host, and browser contract

**Fact.** `knowledge.visualizeGraph` is contributed as **Knowledge: Visualize Graph**, also available in the Knowledge Graph Explorer title toolbar. Its extension callback invokes `GraphView.createOrShow(context.extensionUri)` and catches opening errors with a VS Code error notification. Activation injects both `KnowledgeGraphService` and `StructuralGraphService` into GraphView. Sources: `package.json:57`, `package.json:244`, `src/extension.ts:242`, `src/extension.ts:642`.

`GraphView.currentPanel` is a singleton. Creating it enables scripts and retains context while hidden. Calling the command again reveals the existing panel; if its translated title is unchanged it sends graph data without replacing HTML, otherwise `_update()` replaces HTML. Disposal clears the singleton and its registered listeners. The browser's load handler initializes D3 then sends `ready`; the host answers with the current performance preference and ordinary graph groups. The refresh button sends `refresh`, which uses the same ordinary-data path. Sources: `src/ui/webview/graphView.ts:157`, `src/ui/webview/graphView.ts:186`, `src/ui/webview/graphView.ts:199`, `src/ui/webview/graphView.ts:205`, `src/ui/webview/graphView.ts:263`, `src/ui/webview/graphView.ts:1205`, `src/ui/webview/graphView.ts:2086`.

The declared D3/VS Code ranges are not evidence of an installed version or runtime compatibility. A helper-only test does not exercise loading D3 under that CSP. ### Ordinary groups and the advanced structural view

**Fact.** Ordinary visualization uses `KnowledgeGraphService.getGroups()`, not its deduplicated `getSnapshot()`. Independent framework/module/feature groups retain repeated symbols and group-specific identities. GraphView carries each group's key, order, name, kind, description and scope; its node view models include observations and a structural key, and its edge view models include provenance/confidence/evidence and optional structural paths. These are curated groups from the Agent sidecar, not the complete raw structural graph. Sources: `src/services/knowledgeGraphService.ts:67`, `src/services/knowledgeGraphService.ts:147`, `src/services/agentGraph/agentGraphService.ts:87`, `src/ui/webview/graphView.ts:456`.

The browser sorts groups by `order`, then name. Sidebar buttons show the name, localized kind and entity/relation counts; clicking renders only that group. Incoming ordinary data retains the selected key if it still exists, otherwise chooses the first sorted group. Empty incoming groups stop work, clear the layout cache and geometry, and show an empty state. Selecting a group with zero entities separately shows the empty state without globally clearing every cached group. Sources: `src/ui/webview/graphView.ts:1372`, `src/ui/webview/graphView.ts:1423`, `src/ui/webview/graphView.ts:1449`, `src/ui/webview/graphView.ts:1495`.

The advanced selector offers boundary, community and file levels; changing its value alone does not issue a request. Clicking the structural button sends `requestStructuralOverview` with that level. The host reads and validates `structural-graph.json` through `StructuralGraphService`, aggregates it with a limit of 80 nodes, and posts a `structuralGroup`. The browser removes every prior `__structural_` group, adds the new one, sorts, selects it, and shows a status message. This is an on-demand temporary view, not a persisted modification to ordinary groups. Aggregate overview keys are level-based; raw drilldown keys include `Date.now()`, so a fresh drilldown is not assigned a stable reusable group key. Sources: `src/ui/webview/graphView.ts:1101`, `src/ui/webview/graphView.ts:2091`, `src/ui/webview/graphView.ts:324`, `src/services/structuralGraph/structuralGraphService.ts:63`, `src/services/structuralGraph/structuralGraphService.ts:101`, `src/ui/webview/graphView.ts:518`, `src/ui/webview/graphView.ts:576`, `src/ui/webview/graphView.ts:1401`.

Node/edge interactions rely on that distinction:

- Hover shows node information and highlights immediate neighbors. Ordinary-node double-click sends its group-specific entity ID for source navigation. Shift-double-click, or right-click on a curated node with a structural key, requests structural neighbors. Aggregate double-click requests its raw file slice; raw structural-node double-click resolves and opens its source. Sources: `src/ui/webview/graphView.ts:1729`, `src/ui/webview/graphView.ts:1761`, `src/ui/webview/graphView.ts:1791`.
- A relationship or its label only drills down when its `structuralPath` is a nonempty array. The host matches the supplied hops against current structural relations by source, target, verb and source location, then renders their endpoints. A stale unmatched path can therefore yield an empty slice rather than an explicit missing-path error. Sources: `src/ui/webview/graphView.ts:1599`, `src/ui/webview/graphView.ts:1685`, `src/ui/webview/graphView.ts:340`, `src/ui/webview/graphView.ts:627`.
- Neighbor expansion is bidirectional at depth 1, deduplicates edges, then caps at 120 relations and 80 entities and removes dangling endpoints. Aggregate-node drilldown uses supplied files when present, otherwise file/boundary matching, then caps at 80 entities and 120 internal relations. These are bounded slices, not complete impact reports. Sources: `src/ui/webview/graphView.ts:365`, `src/ui/webview/graphView.ts:407`.
- Aggregation counts inter-group dependency edges, omits within-group edges and keeps only eight sample raw relations per aggregate edge. Consequently double-clicking an aggregate relationship need not display every relationship represented by its count. Aggregate-node drilldown instead shows relations internal to its selected files. Sources: `resources/skills/vibeknowledge-dependency-graph/scripts/structural-analysis.mjs:390`, especially `:416` and `:429`; `src/ui/webview/graphView.ts:543`, `src/ui/webview/graphView.ts:433`.

Navigation resolves paths against `workspaceFolders[0]`, converts one-based source lines to zero-based editor ranges, and does not open external entities as files. Missing curated IDs/workspaces return without navigation; opening errors are shown. Structural navigation rereads/resolves the structural graph and reports structural errors. Group-specific entity IDs, structural keys, source locations and endpoint consistency must remain intact when changing view models. Sources: `src/ui/webview/graphView.ts:648`, `src/ui/webview/graphView.ts:687`, `src/ui/webview/graphView.ts:705`.

One additional selected-group consumer is the music action: the browser sends `selectedGroupKey`, but the host resolves it only among ordinary curated groups, falling back to the first. **Inference:** selecting a temporary structural view does not make the music action use that raw view. This is a coupling to preserve or explicitly redefine, not a reason to investigate playback internals here. Sources: `src/ui/webview/graphView.ts:2115`, `src/ui/webview/graphView.ts:279`.

### Performance preference and actual behavior

**Fact.** The setting `knowledgeGraph.visualization.performanceMode` defaults to `low`, accepts `low`/`high`, and has machine scope. The page applies a user choice immediately, disables the selector, then sends `setPerformanceMode`. The host rejects invalid values and updates `ConfigurationTarget.Global`. Both completion and failure resend the actual configuration value; a failure also shows an error. Browser receipt applies that value and reenables the selector. Settings changes take the same host-to-page synchronization path. The page rerenders the selected group only if the normalized mode changes; it does not request different graph data. Sources: `package.json:325`, `src/ui/webview/graphView.ts:150`, `src/ui/webview/graphView.ts:300`, `src/ui/webview/graphView.ts:1280`, `src/ui/webview/graphView.ts:2077`, `src/ui/webview/graphView.ts:2176`.

| Behavior | Low | High |
| --- | --- | --- |
| Layout | Stops the automatic simulation and performs manual ticks in animation-frame batches. Each batch targets about 6 ms between tick checks; completion occurs at cooling, 120 ticks, or 600 ms accumulated compute/render time. | Uses interactive force simulation, except a cached settled layout or hidden document keeps it stopped. |
| Drag | Stops pending layout and physics, moves only the dragged node, zeroes its velocity, redraws that node and incident edges/labels, then saves geometry. | Reheats/restarts physics on drag start; drag fixes coordinates until release, which lowers the target alpha and saves. |
| Animation | No particles, flowing-link class, glow, label halo/shadow, animated hover or animated fit; CSS disables animations/transitions. | Link particles share one animation-frame loop throttled to 30 fps, with path-length caching after settling; flow/glow/hover transitions and a 750 ms fit transition are enabled. |
| Initial fit | Fits after static layout completes only if auto-fit remains allowed. | Schedules a 1-second delayed fit only if auto-fit remains allowed. |

Sources: `src/ui/webview/graphPerformanceScript.ts:46`, `src/ui/webview/graphPerformanceScript.ts:91`, `src/ui/webview/graphView.ts:1080`, `src/ui/webview/graphView.ts:1572`, `src/ui/webview/graphView.ts:1591`, `src/ui/webview/graphView.ts:1617`, `src/ui/webview/graphView.ts:1668`, `src/ui/webview/graphView.ts:1721`, `src/ui/webview/graphView.ts:1823`, `src/ui/webview/graphView.ts:1922`, `src/ui/webview/graphView.ts:1931`, `src/ui/webview/graphView.ts:1950`, `src/ui/webview/graphView.ts:2053`.

**Important limits/inferences.** The static budget is not a hard frame deadline: a single expensive tick cannot be preempted, and the 600 ms count excludes time spent paused. Recreating a layout creates a fresh budget counter while restoring alpha. Low mode still synchronously prepares nodes, links and SVG; ordinary groups have no equivalent 80-node rendering cap. The layout-cache node limit is a storage bound, not a rendering cap. Thus “low” means bounded/yielding layout plus reduced decoration, not guaranteed responsiveness for every graph. Because both modes reuse a settled cache, switching low to high does not necessarily restart physics; effects can start over a stationary layout until a drag/resize reheats it. Sources: `src/ui/webview/graphPerformanceScript.ts:8`, `src/ui/webview/graphPerformanceScript.ts:48`, `src/ui/webview/graphView.ts:1479`, `src/ui/webview/graphView.ts:1556`, `src/ui/webview/graphView.ts:1933`.

### What is remembered, and for how long

There are three distinct state stores, not a single saved “view”: the selected key in VS Code webview state, geometry/settling state in a browser-memory cache, and performance mode in global configuration.

| Transition/state | Current implementation and consequence |
| --- | --- |
| Ordinary group switch or mode rerender | Saves the outgoing layout, stops old layout/simulation/particles/transitions and timers, then restores the incoming group's cached geometry and zoom if topology matches. Pending alpha and auto-fit intent survive, so quick switches need not freeze an unfinished layout. |
| Cache validity/eviction | Keyed by group key; signature uses sorted node IDs and edge source/target/verb triples. Stores only copied x/y coordinates, zoom x/y/k, settled flag, alpha and auto-fit—not descriptions, evidence, velocities or pinned positions. Prose updates use fresh payloads while reusing geometry. Default LRU bounds are eight groups and 2,000 total nodes; oversized links/nodes or nonfinite coordinates are not cached. Evicted/changed-topology views start afresh. |
| Selection | Initialization reads `vscode.getState()?.selectedGroupKey`; each valid selection calls `vscode.setState({ selectedGroupKey })`. There is no geometry or advanced selector value in that persisted object. |
| Revealing an existing panel via the command | Same-title HTML remains alive, but curated `graphData` is resent. An ordinary selected key can be retained and its cache reused. A selected temporary structural group disappears from the new group list, so selection falls back to the first ordinary group. Merely making a hidden retained page visible does not itself replace its group list. |
| Hiding/showing the document | Hiding disables CSS animations, pauses static layout, stops simulation/particles, interrupts transitions, clears fit/resize timers, and saves layout. Becoming visible resumes unfinished static work, or high-mode physics only if alpha is above its minimum, plus the high-mode particle loop. DOM, current groups and in-memory cache remain in the retained page. |
| HTML replacement or panel close/new creation | HTML replacement rebuilds browser memory; only whatever selected key remains available through webview state can be reused. Actual panel disposal clears the host singleton and new creation allocates a new webview; the inspected code has no cross-panel layout/selection restore store. Do not claim close/reopen retains the prior view. Global performance preference is explicitly reloaded and survives. |
| Empty data | Clears current selection in memory and the whole cache, but does not call `setState` to clear an earlier persisted key. Live next-data selection therefore starts from the first group, while later state restoration can encounter an old key and must validate it. |

Sources: `src/ui/webview/graphView.ts:157`, `src/ui/webview/graphView.ts:186`, `src/ui/webview/graphView.ts:1137`, `src/ui/webview/graphView.ts:1254`, `src/ui/webview/graphView.ts:1372`, `src/ui/webview/graphView.ts:1401`, `src/ui/webview/graphView.ts:1449`, `src/ui/webview/graphView.ts:1479`, `src/ui/webview/graphView.ts:1556`; `src/ui/webview/graphPerformanceScript.ts:7`.

User-originated zoom/pan and drag disable auto-fit; explicit fit remains available. Resize is debounced 120 ms, updates viewport and center force, fits in low mode and reheats high mode only while visible. **Inference/risk:** zoom is not unconditionally immutable across resize. Also, hiding clears a pending high-mode fit timeout, but the visibility-resume handler does not reschedule it; the saved `autoFit` flag alone does not recreate that timer. Before unload, simulation/static work, particles and fit/resize timers are stopped, not serialized. Sources: `src/ui/webview/graphView.ts:1210`, `src/ui/webview/graphView.ts:1254`, `src/ui/webview/graphView.ts:1272`, `src/ui/webview/graphView.ts:1360`, `src/ui/webview/graphView.ts:1933`, `src/ui/webview/graphView.ts:1957`.

## 2. Generate Copilot Instructions

### UI command through file completion

**Fact.** `knowledge.generateCopilotInstructions` is contributed as **Knowledge: Generate Copilot Instructions**. The registered async extension callback logs, awaits `EntityCommands.generateCopilotInstructions()`, and has a final escaped-error notification. Activation constructs EntityCommands with entity, relation, observation and knowledge-graph services; EntityCommands constructs its `AIIntegrationService` from the first three. Sources: `package.json:85`, `src/extension.ts:245`, `src/extension.ts:679`, `src/ui/commands/entityCommands.ts:23`.

The command takes no user-selected destination, editor selection or graph group. It targets `workspaceFolders[0]`; no workspace produces a localized error and returns. Before writing, `getGraphData()` obtains the knowledge service's aggregate snapshot and gathers every snapshot entity's observations into `{entityId, entityName, content}`, adding `sourceType: 'knowledge'`. The snapshot deduplicates entities across groups, remaps edge endpoints, and drops missing/self/duplicate relations. Sources: `src/ui/commands/entityCommands.ts:43`, `src/services/knowledgeGraphService.ts:67`, `src/ui/commands/entityCommands.ts:1255`.

`AIIntegrationService.generateCopilotInstructions(workspaceRoot, _graphData?)` joins `.github`, creates it recursively when absent, builds content, writes `.github/copilot-instructions.md` synchronously as UTF-8, and resolves with its path. Although the method is async, these filesystem operations are synchronous. The active content call is `buildCopilotInstructionsContent()` → `buildAgentKnowledgeRouterContent('en', '# VibeKnowledge Agent Instructions')`. Sources: `src/services/aiIntegrationService.ts:71`, `src/services/aiIntegrationService.ts:404`.

After writing, the UI shows a success notification offering **Open file** or **Show in folder**. Open uses `openTextDocument` then `showTextDocument`; reveal uses `revealFileInOS`. Dismissing the notification leaves the generated file in place and opens nothing. There is no single-file progress/cancel workflow. **Verified presentation mismatch:** the command supplies `.github/<basename>` to the success formatter, while both English and Chinese formatters prepend `.github/` themselves. The notification therefore can show `.github/.github/copilot-instructions.md`; the filesystem destination and open/reveal actions still use the correct path returned by the service. Sources: `src/ui/commands/entityCommands.ts:1269`, `src/i18n/en.ts:291`, `src/i18n/zh.ts:292`.

### Existing destination and failure semantics

**Fact.** The writer checks whether `.github` exists, not whether `copilot-instructions.md` exists. `writeFileSync` replaces the file content: there is no read/merge, overwrite prompt, backup, temporary-file rename or rollback in this path. Existing hand-written project guidance can be lost on successful regeneration. It is not a transactional or atomic multi-file operation. Sources: `src/services/aiIntegrationService.ts:71`, `src/services/aiIntegrationService.ts:58`, `src/services/aiIntegrationService.ts:89`.

Filesystem errors propagate as rejection from the async service. The EntityCommands `try` covers graph collection, generation, the success prompt, opening the document and revealing it; it catches errors and shows a localized “Failed to generate…” message without rethrowing them. The outer extension catch is a backstop for failures escaping that handler, not normally a second notification for an already-handled write error. If open/reveal fails after writing, the file remains successfully generated even though the user then sees a generation-labeled error. Sources: `src/ui/commands/entityCommands.ts:1262`, `src/ui/commands/entityCommands.ts:1276`, `src/ui/commands/entityCommands.ts:1282`, `src/extension.ts:680`.

**Inferences/risk boundaries.** Directory creation can succeed before a later content/write failure, leaving `.github` behind. A failed direct write is not guaranteed to preserve original file bytes. In either bulk route, failure of the first Cursor write prevents Copilot generation; failure of Copilot leaves the earlier Cursor write in place. There is no rollback of that earlier side effect and no all-files success prompt on that failure path. The service bulk wrapper rejects rather than returning the partially accumulated array. These follow from the operation ordering and lack of compensation; no failure was injected during this analysis. Sources: `src/services/aiIntegrationService.ts:71`, `src/services/aiIntegrationService.ts:89`, `src/ui/commands/entityCommands.ts:1297`, `src/ui/commands/entityCommands.ts:1332`.

### Intended use versus actions actually performed

The generated repository instruction file tells a future coding assistant to use the Knowledge Graph as an on-demand dependency navigator. Its English router says to use focused VibeKnowledge MCP `query_graph` requests with appropriate `tokenBudget` for architecture/unfamiliar/cross-file/dependency/impact work; expand with `get_entity`, `get_neighbors` or `shortest_path`; request `includeEvidence=true` only for auditing; and, when MCP is unavailable/unhelpful, consult `.vscode/.knowledge/agent-context/index.md` plus one best-matching group. It discourages loading the complete `knowledge-graph.md` audit by default, permits skipping the graph for small known-file work, requires current-source verification, and forbids direct editing of `graph.sqlite`. Source: `src/services/aiIntegrationService.ts:432`.

Those statements are **generated instructions**, not actions the generator performs. Its inspected implementation writes text only: it does not call MCP, configure/install a server, generate/query/validate the graph, create or check the referenced index/group views, inspect the complete audit, refresh SQLite, invoke Copilot, or verify that Copilot discovers or follows the file. **Inference:** a successful generation is a file-write success, not evidence that the downstream knowledge workflow works or that the output reflects this project's architecture. Sources: `src/services/aiIntegrationService.ts:71`, `src/services/aiIntegrationService.ts:404`, `src/ui/commands/entityCommands.ts:1262`.
