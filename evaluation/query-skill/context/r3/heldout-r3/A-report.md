### 性能选择：保存的偏好与运行行为

实现事实：`knowledgeGraph.visualization.performanceMode` 是 machine scope、默认 `low`、仅支持 `low/high`。页面改变选项后立即应用并重画当前组，随后禁用选择器并向宿主发保存请求；宿主只接受这两个值，用 `ConfigurationTarget.Global` 更新。成功或失败均在 finally 回传实际配置值；失败另外提示错误。页面收到回传后重新启用选择器，因此失败时会按真实配置回退。Settings 修改也通过配置监听推送。参见 [package.json:325](D:/workspace/VibeKnowledge/.vscode-test/feature-r3-heldout-3-iLftHL/A/package.json:325)、[graphView.ts:150](D:/workspace/VibeKnowledge/.vscode-test/feature-r3-heldout-3-iLftHL/A/src/ui/webview/graphView.ts:150)、[graphView.ts:300](D:/workspace/VibeKnowledge/.vscode-test/feature-r3-heldout-3-iLftHL/A/src/ui/webview/graphView.ts:300)、[graphView.ts:1283](D:/workspace/VibeKnowledge/.vscode-test/feature-r3-heldout-3-iLftHL/A/src/ui/webview/graphView.ts:1283)、[graphView.ts:2077](D:/workspace/VibeKnowledge/.vscode-test/feature-r3-heldout-3-iLftHL/A/src/ui/webview/graphView.ts:2077)、[graphView.ts:2176](D:/workspace/VibeKnowledge/.vscode-test/feature-r3-heldout-3-iLftHL/A/src/ui/webview/graphView.ts:2176)。

高模式使用常规 D3 forceSimulation（link、charge、center、collide），拖动时重热，fit 使用 750ms 过渡；初次允许自动 fit 时设置 1 秒定时器。粒子由当前组唯一 RAF 循环驱动，限制约 30fps；仿真结束缓存路径长度，几何变化会使长度缓存失效。高模式并不意味着永远运行力仿真：命中已稳定布局会停止仿真，低→高切换也可保留稳定位置，只恢复视觉效果；之后高模式拖动或可见时 resize 可重新启动物理运动。窗口 resize 防抖 120ms，低模式 fit，高模式 alpha(0.15).restart()。参见 [graphView.ts:1210](D:/workspace/VibeKnowledge/.vscode-test/feature-r3-heldout-3-iLftHL/A/src/ui/webview/graphView.ts:1210)、[graphView.ts:1556](D:/workspace/VibeKnowledge/.vscode-test/feature-r3-heldout-3-iLftHL/A/src/ui/webview/graphView.ts:1556)、[graphView.ts:1630](D:/workspace/VibeKnowledge/.vscode-test/feature-r3-heldout-3-iLftHL/A/src/ui/webview/graphView.ts:1630)、[graphView.ts:1922](D:/workspace/VibeKnowledge/.vscode-test/feature-r3-heldout-3-iLftHL/A/src/ui/webview/graphView.ts:1922)、[graphView.ts:1940](D:/workspace/VibeKnowledge/.vscode-test/feature-r3-heldout-3-iLftHL/A/src/ui/webview/graphView.ts:1940)、[graphView.ts:2053](D:/workspace/VibeKnowledge/.vscode-test/feature-r3-heldout-3-iLftHL/A/src/ui/webview/graphView.ts:2053)。

### 状态究竟存在哪里、何时保留

实现事实：页面从 `vscode.getState()` 只恢复 `selectedGroupKey`。另有页面内存 `layoutCache`：按组 key 保存节点 x/y、zoom x/y/k、settled、alpha、autoFit；不保存实体描述／证据，也不保存速度或固定点。拓扑签名由排序后的节点 ID 及关系 sourceId/targetId/verb 构成，内容描述变化不失效，端点／动词／节点集合变化会失效。缓存最多 8 组、总计 2000 节点；单组超过节点或边限制、坐标非有限数则不存，按 LRU 淘汰。参见 [graphView.ts:1138](D:/workspace/VibeKnowledge/.vscode-test/feature-r3-heldout-3-iLftHL/A/src/ui/webview/graphView.ts:1138)、[graphView.ts:1453](D:/workspace/VibeKnowledge/.vscode-test/feature-r3-heldout-3-iLftHL/A/src/ui/webview/graphView.ts:1453)、[graphPerformanceScript.ts:7](D:/workspace/VibeKnowledge/.vscode-test/feature-r3-heldout-3-iLftHL/A/src/ui/webview/graphPerformanceScript.ts:7)、[graphView.ts:1574](D:/workspace/VibeKnowledge/.vscode-test/feature-r3-heldout-3-iLftHL/A/src/ui/webview/graphView.ts:1574)。

有两层“生成全部”：服务的 `generateAllAIConfigs()` 顺序调用 Cursor、Copilot 并返回路径数组；UI 的同名方法没有调用这个聚合方法，而是在不可取消的通知进度中自己按同样顺序调用两个单文件服务，并提供打开其中一个的完成动作。两者最终共用单文件生成器和 router。场景切换命令在用户选择“Generate”后又调用 UI 的 `knowledge.generateAllAIConfigs`；这会重写文件，但当前 builder 不读取场景，所以不会因此带入场景模板。修改共享 router 会同时影响单独 Copilot、单独 Cursor、两个 all 路径及场景切换后的再生成。参见 [aiIntegrationService.ts:89](D:/workspace/VibeKnowledge/.vscode-test/feature-r3-heldout-3-iLftHL/A/src/services/aiIntegrationService.ts:89)、[entityCommands.ts:1290](D:/workspace/VibeKnowledge/.vscode-test/feature-r3-heldout-3-iLftHL/A/src/ui/commands/entityCommands.ts:1290)、[scenarioCommands.ts:62](D:/workspace/VibeKnowledge/.vscode-test/feature-r3-heldout-3-iLftHL/A/src/commands/scenarioCommands.ts:62)。

生成文件的意图是给后续 AI 编程助手一份简短的按需导航规则：架构、陌生代码、跨文件依赖或影响分析优先聚焦 `query_graph` 与合适 tokenBudget；必要时以 get_entity/get_neighbors/shortest_path 扩展，审计关系才 includeEvidence；MCP 不可用或局部结果无用时读 agent-context/index.md，再只读最匹配的一组；不默认加载整份 knowledge-graph.md；小且目标明确的任务可以跳过图谱，修改／测试前回到当前源码验证；不编辑 graph.sqlite，通过产品工作流刷新生成物。参见 [aiIntegrationService.ts:432](D:/workspace/VibeKnowledge/.vscode-test/feature-r3-heldout-3-iLftHL/A/src/services/aiIntegrationService.ts:432)。

这些是输出文本对后续使用者的要求，不是生成器本身执行的动作：生成器不调用 MCP、不安装或验证 MCP、不选取分组、不生成／刷新图谱、不分析源码、不运行测试，也不确保 GitHub Copilot 已开启或实际采纳该文件。它保证的是按当前路径写出文本，而不是后续助手的行为或配置可用性。这个边界直接来自生成器和纯字符串 builder 的完整调用链。

### 覆盖、完成及错误处理

实现事实：只检查 `.github` 目录是否存在，不检查目标文件是否存在；`writeFileSync` 无 append／exclusive 标志、无读取合并、无确认或备份。因此已有 `copilot-instructions.md` 的自定义内容会被整体覆盖，重复执行不会追加。也没有通过 WorkspaceEdit 处理已有编辑器缓冲区。目录创建和写入没有临时文件＋rename／事务／回滚步骤。参见 [aiIntegrationService.ts:71](D:/workspace/VibeKnowledge/.vscode-test/feature-r3-heldout-3-iLftHL/A/src/services/aiIntegrationService.ts:71)。

风险／推断：权限、`.github` 实为文件、磁盘等错误会使 async 方法 reject；创建目录之后 builder／写入失败，目录可能已留下；直接覆盖写失败可能令旧文件截断或部分写入，代码不提供恢复保证。生成全部时 Cursor 成功后 Copilot 失败，会保留已生成／覆盖的 `.cursorrules`；Cursor 先失败则不再尝试 Copilot。两个 all 实现都是顺序 await，没有事务。因此错误提示不代表“所有文件均未改变”。依据同上及 [aiIntegrationService.ts:89](D:/workspace/VibeKnowledge/.vscode-test/feature-r3-heldout-3-iLftHL/A/src/services/aiIntegrationService.ts:89)、[entityCommands.ts:1306](D:/workspace/VibeKnowledge/.vscode-test/feature-r3-heldout-3-iLftHL/A/src/ui/commands/entityCommands.ts:1306)。

写入成功并拿到路径后，UI 显示本地化成功提示，可选 Open file（openTextDocument＋showTextDocument）或 Show in folder（revealFileInOS）。关闭提示不做额外动作，文件已经写好，不是取消生成。生成和这两个后续动作都在同一个 try/catch，所以文件成功写入之后打开／显示失败，也会出现“生成失败”样式的错误；没有撤销已生成文件。常规异常被 EntityCommands 转成提示并吞掉，扩展外层 catch 只是对未被内层处理的 reject 的兜底。参见 [entityCommands.ts:1262](D:/workspace/VibeKnowledge/.vscode-test/feature-r3-heldout-3-iLftHL/A/src/ui/commands/entityCommands.ts:1262)、[extension.ts:680](D:/workspace/VibeKnowledge/.vscode-test/feature-r3-heldout-3-iLftHL/A/src/extension.ts:680)。

成功文案有一个可直接推导的小错误：调用处传入 `.github/${basename}`，而中英文 success formatter 自己又加 `.github/`，显示可能变成 `.github/.github/copilot-instructions.md`。真实返回路径与打开路径仍只有一层 `.github`，不应按提示文案推断实际目标。参见 [entityCommands.ts:1271](D:/workspace/VibeKnowledge/.vscode-test/feature-r3-heldout-3-iLftHL/A/src/ui/commands/entityCommands.ts:1271)、[en.ts:293](D:/workspace/VibeKnowledge/.vscode-test/feature-r3-heldout-3-iLftHL/A/src/i18n/en.ts:293)、[zh.ts:294](D:/workspace/VibeKnowledge/.vscode-test/feature-r3-heldout-3-iLftHL/A/src/i18n/zh.ts:294)。
