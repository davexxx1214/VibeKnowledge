# Entity descriptions and MCP setup

Source-only analysis of this workspace. **Fact** means directly supported by implementation; **inference** identifies a consequence or risk, not a reproduced failure. Tests below were inspected, not executed. Source searches/reads used the required observer, descriptions first and setup second. No packages were installed and no source was modified.

## 1. Description edits, persistence, and consumers

### Edit/reset path and scope

- **Fact — UI entry points.** A CodeLens invokes `knowledge.editEntityDescription` with the entity ID (`src/providers/codeLensProvider.ts:42`). The command resolves an ID, entity, or tree item's entity through the current knowledge graph; if unresolved, edit offers a graph-wide picker. Cancelling the picker/input makes no write, while an empty string is accepted. Edit checks its returned entity and reports an error on null. Reset requires a resolvable Agent entity, has no fallback picker, and does **not** check the reset result before announcing success (`src/ui/commands/entityCommands.ts:225`, `src/ui/commands/entityCommands.ts:242`, `src/ui/commands/entityCommands.ts:252`, `src/ui/commands/entityCommands.ts:268`, `src/ui/commands/entityCommands.ts:279`).
- **Fact — storage is an overlay, not generated structure.** `KnowledgeGraphService.updateDescription/resetGeneratedDescription` resolve the entity and delegate to `AgentGraphService`. That service writes/deletes by `entity.key`, forces a refresh, and resolves the entity again (`src/services/knowledgeGraphService.ts:261`, `src/services/agentGraph/agentGraphService.ts:143`). The override store upserts `agent_entity_overrides(agent_key, description, updated_at)` or deletes a row, then calls `DatabaseService.save()` (`src/services/agentGraph/agentEntityOverrideService.ts:47`, `src/services/agentGraph/agentEntityOverrideService.ts:61`). SQL.js holds the database in memory and exports the whole file to `.vscode/.knowledge/graph.sqlite`; description commands do not write `agent-graph.json` (`src/services/database.ts:17`, `src/services/database.ts:118`, `src/services/database.ts:165`).
- **Fact — workspace and symbol scope.** Extension activation binds this graph and database to `workspaceFolders[0]`, regardless of the later MCP target setting (`src/extension.ts:57`, `src/extension.ts:174`). IDs include group key plus symbol key, but overrides use only symbol key. Each group's occurrence receives the override; metadata retains that group's generated prose and records `descriptionSource`. An empty override still wins because presence is tested against `undefined`, not truthiness (`src/services/agentGraph/agentGraphService.ts:541`). The aggregate de-duplicates normalized identities, keeping the first occurrence; visualization groups retain all occurrences (`src/services/knowledgeGraphService.ts:67`, `src/services/knowledgeGraphService.ts:147`). Reset therefore reveals each group's **latest** generated prose, not a stored original edit-time value. The regeneration/reset test expressly asserts two different restored descriptions (`src/services/agentGraph/agentGraphService.test.ts:393`).
- **Fact — identity matching.** Lookup prefers the exact stored key, then accepts exactly one normalized-identity match; delete uses the same preference. Set always upserts the exact supplied spelling (`src/services/agentGraph/agentEntityOverrideService.ts:22`, `src/services/agentGraph/agentEntityOverrideService.ts:47`, `src/services/agentGraph/agentEntityOverrideService.ts:78`). Normalization repairs path separators and leading `./`, preserving case, Unicode, punctuation, and the symbol suffix (`resources/skills/vibeknowledge-dependency-graph/scripts/canonicalize-entity-key.mjs:34`). Path spelling/case behavior is covered by `src/services/agentGraph/agentEntityOverrideService.test.ts:28`.

### Important failure cases and boundaries

1. **Fact/inference — disk failure is not transactional with the UI/cache.** SQL mutation precedes file save, which can throw. Thus a failed save can leave changed in-memory rows while disk and graph cache retain older state; wrappers report an error rather than refreshing. A later refresh/save can expose/persist the already-mutated row (`src/services/agentGraph/agentEntityOverrideService.ts:56`, `src/services/database.ts:165`, `src/extension.ts:553`). Whole-file synchronous overwrite is not an atomic temp-file replacement.
2. **Fact/inference — stale IDs and malformed generation.** Missing graph yields empty data; parse/load failure replaces the snapshot with empty data and records the error (`src/services/agentGraph/agentGraphService.ts:232`). Regeneration during an awaited input can invalidate the group-derived ID. Edit can return null; reset can still display success after a null result because it discards that result (`src/ui/commands/entityCommands.ts:273`). Neither operation repairs generated structure.
3. **Inference — aliases can make reset appear ineffective.** Editing a path-spelling variant can create a second row rather than migrate the first. Exact lookup wins; a reset deletes only one row, so another unique alias can become visible afterward. Multiple matching aliases with no exact match are deliberately ignored. This follows directly from exact-key upsert and exact/unique-fallback deletion (`src/services/agentGraph/agentEntityOverrideService.ts:47`, `src/services/agentGraph/agentEntityOverrideService.ts:61`, `src/services/agentGraph/agentEntityOverrideService.ts:98`). A real symbol/path identity change can also orphan an override rather than transfer it.
4. **Inference — cross-process consistency needs separate verification.** MCP re-queries overrides, but keeps a read-only native SQLite connection open, whereas the extension overwrites the complete database from SQL.js memory (`packages/mcp-server/src/database.ts:119`, `src/services/database.ts:165`). These paths have no explicit reopen/coordination protocol. Do not infer that SQL re-querying proves safe visibility during concurrent whole-file writes. Similarly, external database changes are not a signature input or automatically reloaded into extension SQL.js memory (`src/services/database.ts:37`, `src/services/agentGraph/agentGraphService.ts:242`).
5. **Fact/inference — scope and timestamps can mislead.** CodeLens resolves a document relative to its own workspace folder, while graph services use the first folder; matching relative paths in another root can therefore resolve first-root entities (`src/providers/codeLensProvider.ts:58`, `src/extension.ts:57`). Manual updates do not change entity generation timestamps; MCP merged overview also reports Agent generation time, not override update time (`src/services/agentGraph/agentGraphService.ts:562`, `packages/mcp-server/src/mergedGraph.ts:74`). A timestamp-only downstream cache would miss prose-only updates.

## 2. MCP setup: UI to processes and configuration

### Selection and ordered execution

1. **Fact — entry and gating.** `knowledge.setupMcp` is contributed to the UI; `knowledge.settings` also offers install/reconfigure. Registration occurs before graph initialization and the no-workspace early return, so setup remains usable without an initialized graph (`package.json:67`, `src/extension.ts:36`, `src/commands/mcpSetupCommands.ts:100`). It rejects untrusted workspaces and suppresses duplicate invocations while selection/installation is active (`src/commands/mcpSetupCommands.ts:15`).
2. **Fact — target is explicit, not extension checkout.** A nonempty machine-scoped `knowledgeGraph.mcp.workspacePath` is reused. Otherwise the picker offers local `file:` workspace folders plus another-folder dialog. Cancel/non-file selection returns; a relative configured path errors. Client is explicit Cursor, auto-detected Cursor by app name, otherwise VS Code. A modal identifies project, target config, downloads, and DB initialization; only acceptance saves the chosen path globally and starts cancellable progress (`src/commands/mcpSetupCommands.ts:23`, `src/commands/mcpSetupCommands.ts:39`, `src/commands/mcpSetupCommands.ts:52`, `package.json:288`). Service resolves symlinks with `realpath`, verifies a directory, and validates existing JSONC before any process/download (`src/services/mcpSetupService.ts:154`).
3. **Fact — isolated runtime and Node checks.** UI supplies the extension's `dist/mcp-server` bundle and global-storage `mcp` directory, never the business project's package directory (`src/commands/mcpSetupCommands.ts:64`). Service probes the selected external Node for version, executable, ABI, platform and architecture; accepts stable Node `>=26.1.0 <27`; resolves an absolute `npm-cli.js` beside real Node or from the setting; runs it through that same Node and rejects npm major versions below 11. It prepends Node's directory to a copied PATH while preserving inherited environment (`src/services/mcpSetupService.ts:91`, `src/services/mcpSetupService.ts:104`, `src/services/mcpSetupService.ts:162`). **Inference:** npm version parsing is a lower-bound check, not strict validation—nonnumeric output gives `NaN`, which does not satisfy `<11`.
4. **Fact — install, audit, then health.** Lock bytes plus Node/version/platform/architecture determine an identity prefix, but every attempt uses a unique `mkdtemp` directory. The bundle is copied there and `node npm-cli.js ci --omit=dev --audit --ignore-scripts` runs there. An explicit production audit follows; only afterward is a missing graph database initialized, then `node health-check.mjs <workspace>` must exit successfully within 45 seconds (`src/services/mcpSetupService.ts:171`, `src/services/mcpSetupService.ts:185`, `src/services/mcpSetupService.ts:197`). Existing databases are not recreated, and this flow does not generate the graph (`src/commands/mcpSetupCommands.ts:73`).
5. **Fact — publication and eventual server.** Immediately before publication, the service compares current config text with its initial text; mismatch aborts. JSONC editing preserves surrounding comments/settings and replaces only the entire `vibeknowledge` entry, under VS Code `servers` or Cursor `mcpServers`. The entry uses resolved Node, installed `dist/index.js`, explicit `--workspace`, and `--rag-mode none`; VS Code additionally gets `type: stdio` (`src/services/mcpSetupService.ts:122`, `src/services/mcpSetupService.ts:201`). Nonempty old config gets an exclusive timestamped backup; new content is exclusively written to a temporary file and renamed into place (`src/services/mcpSetupService.ts:205`). The user must still trust/start/restart the client entry (`src/commands/mcpSetupCommands.ts:82`). Server CLI workspace overrides environment/cwd, DB defaults beneath that workspace, and startup opens the database before starting MCP; top-level startup errors exit 1 (`packages/mcp-server/src/config.ts:92`, `packages/mcp-server/src/index.ts:6`, `packages/mcp-server/src/index.ts:63`).

### Dependency checks, errors, and safe retries

- **Fact — audit is fail-closed, with bounded transient retries.** It runs npm audit with JSON, production-only, high severity threshold, request timeout 10–120 seconds (default 60), and npm internal fetch retries disabled. Only a structurally valid report with no high/critical findings, exit 0, and no timeout/error counts as clean; moderate findings are allowed. High/critical findings fail immediately. Network/DNS/timeouts/429/5xx or invalid reports retry at most three times with 2s/4s backoff; certificate, auth, local-input and process-start failures do not retry. Registry/ping diagnostics never substitute for an audit verdict (`scripts/audit-dependencies.cjs:56`, `scripts/audit-dependencies.cjs:63`, `scripts/audit-dependencies.cjs:74`, `scripts/audit-dependencies.cjs:90`, `scripts/audit-dependencies.cjs:113`). Service permits enough overall audit time for retries/diagnostics: 270s by default, 450s at the maximum setting (`src/services/mcpSetupService.ts:188`).
- **Fact — child control.** Processes use argument arrays with `shell:false` and hidden Windows windows. Stdout is bounded to 256 KiB; logs and the 4,000-character failure tail are redacted. Nonzero exit/spawn errors reject. Abort/default five-minute step timeout terminates the Windows process tree with `taskkill`, or the Unix process group, with a three-second hard-stop fallback. UI cancellation and extension disposal trigger abort (`src/services/mcpSetupService.ts:36`, `src/commands/mcpSetupCommands.ts:13`, `src/commands/mcpSetupCommands.ts:61`).
- **Fact — ordinary failed retries preserve the previous working installation.** An unpublished attempt removes only its unique staging directory; old installs remain even after success, protecting running clients. A repeat runs a fresh install/audit/health cycle rather than trusting partial staging. UI logs errors, offers MCP settings, and clears its active/selecting guards (`src/services/mcpSetupService.ts:213`, `src/commands/mcpSetupCommands.ts:88`). Install/audit/health failure preservation, concurrent-config detection, early cancellation, and invalid-config handling are covered by mocked-process tests (`tests/mcpSetup.test.ts:110`, `tests/mcpSetup.test.ts:140`, `tests/mcpSetup.test.ts:150`, `tests/mcpSetup.test.ts:161`). Audit retry/fail-closed behavior has dedicated tests (`tests/dependencyAudit.test.ts:23`, `tests/dependencyAudit.test.ts:35`, `tests/dependencyAudit.test.ts:95`).
- **Inference — retry is not rollback of every side effect.** The globally saved target can remain after any later failure, and a newly initialized DB can remain after failed health/publication. Successful reruns retain previous installs and replace any custom fields inside the prior `vibeknowledge` entry; backups preserve nonempty original config. Recheck the saved project/client and settings before retrying. Repair runtime/npm/config/certificate/auth problems; adjust timeout or retry transient network failures without disabling audit/TLS (`src/commands/mcpSetupCommands.ts:52`, `src/services/mcpSetupService.ts:132`, `src/services/mcpSetupService.ts:197`, `scripts/audit-dependencies.cjs:106`).
- **Inference — narrow commit windows weaken the blanket error message.** The optimistic config comparison is not a lock: an edit afterward can still be overwritten. Abort is last checked before comparison/publication, so late cancellation may not prevent the rename. If rename succeeds but temporary-file cleanup throws, `published` is still false and outer cleanup can delete the newly referenced install. Thus the UI's universal “previous configuration was preserved” is stronger than this sequence guarantees; inspect actual config/backup after publication-stage errors (`src/services/mcpSetupService.ts:200`, `src/services/mcpSetupService.ts:207`, `src/services/mcpSetupService.ts:213`, `src/commands/mcpSetupCommands.ts:92`). These are code-path risks, not reproduced failures.
