# Description editing and MCP setup

Read-only source analysis, completed in the requested order. **Fact** means directly observed code; **Inference** means a consequence or risk derived from that code. Tests were inspected, not executed. No packages were installed and no extension source/configuration was changed.

## 1. Entity descriptions

### Edit/reset → persistence

- **Fact — entry and resolution.** The contributed edit/reset commands appear in the explorer context menu; CodeLens invokes edit with an entity ID (`package.json:40-46`, `package.json:200-209`, `src/providers/codeLensProvider.ts:42-47`). Edit accepts a tree item's entity, an ID-bearing object, or a string ID. If resolution fails, it offers the aggregate entity list; its input starts with the current displayed description. `undefined` cancels, whereas `''` is saved. Reset has no picker and silently returns without a resolvable Agent entity (`src/ui/commands/entityCommands.ts:225-287`).
- **Fact — service chain.** Activation binds the first workspace folder's `DatabaseService` → `AgentEntityOverrideService` → `AgentGraphService` → `KnowledgeGraphService`, then injects the latter into commands (`src/extension.ts:57-69`, `src/extension.ts:174-180`, `src/extension.ts:245-251`). `KnowledgeGraphService.getEntity` checks the aggregate and then independent groups. Update/reset delegate to the Agent service; mutation needs a current entity and an override store (`src/services/knowledgeGraphService.ts:192-205`, `src/services/knowledgeGraphService.ts:261-284`, `src/services/agentGraph/agentGraphService.ts:143-167`).
- **Fact — storage contract.** Edits parameterize an upsert into `agent_entity_overrides(agent_key, description, updated_at)`; reset deletes the override. Both save through `DatabaseService`, whose sql.js database is loaded into memory from `<workspace>/.vscode/.knowledge/graph.sqlite` and exported with `writeFileSync`. Neither operation rewrites generated `agent-graph.json` (`src/services/agentGraph/agentEntityOverrideService.ts:47-75`, `src/services/database.ts:17-43`, `src/services/database.ts:118-129`, `src/services/database.ts:165-177`).
- **Fact — scope and precedence.** IDs include group key plus entity key, but overrides use only the stable entity key. Every group occurrence therefore receives the same human prose, while retaining its own `generatedDescription`; the override test is against `undefined`, so an empty manual description wins. Reset reveals each group's latest generated description, not an older copy. The aggregate deduplicates normalized identities, taking the first occurrence, while `getGroups()` preserves occurrences (`src/services/agentGraph/agentGraphService.ts:540-574`, `src/services/knowledgeGraphService.ts:67-84`, `src/services/knowledgeGraphService.ts:147-172`). Lookup/delete prefer exact keys, then a unique identity match. Normalization changes portable path spelling only, retaining symbol/path case and semantic punctuation (`src/services/agentGraph/agentEntityOverrideService.ts:22-44`, `src/services/agentGraph/agentEntityOverrideService.ts:61-98`, `resources/skills/vibeknowledge-dependency-graph/scripts/canonicalize-entity-key.mjs:34-45`). **Inference:** a semantic key rename can orphan an override; changing one group's prose intentionally changes the other occurrences too.

### Invalidation and consumers

- **Fact — editor invalidation.** The Agent snapshot cache normally keys only on manifest mtime/size. Edit/reset explicitly clear its signature and reload. After a handler resolves, command wrappers refresh the tree, current graph webview and CodeLens—even after cancellation/no-op. Tree refresh also forces graph-service refresh; manifest create/change/delete events run this same view-refresh path (`src/services/agentGraph/agentGraphService.ts:108-110`, `src/services/agentGraph/agentGraphService.ts:153-167`, `src/services/agentGraph/agentGraphService.ts:232-257`, `src/extension.ts:548-575`, `src/providers/treeDataProvider.ts:172-175`, `src/extension.ts:265-281`).
- **Fact — visible consumers.** Tree entity tooltips use description and explicitly label an empty value. The webview sends each group's current description; its static refresh updates only an existing panel. CodeLens compacts whitespace, limits prose to 96 characters, and falls back to the name for empty prose (`src/providers/treeDataProvider.ts:70-84`, `src/ui/webview/graphView.ts:124-126`, `src/ui/webview/graphView.ts:457-491`, `src/providers/knowledgeCodeLensModel.ts:6`, `src/providers/knowledgeCodeLensModel.ts:32-55`). Hover reads the current graph on each request; details and search results read descriptions when invoked; the injected export service gets aggregate entities from the same graph (`src/providers/hoverProvider.ts:25-45`, `src/ui/commands/entityCommands.ts:327-362`, `src/ui/commands/entityCommands.ts:414-427`, `src/ui/commands/entityCommands.ts:23-34`, `src/services/exportService.ts:684-705`). **Inference:** subsequent requests/exports reflect edits, but already-rendered hover/details, open pickers, copied text and saved exports are snapshots, not pushed updates. Empty prose is intentionally presented differently across these surfaces.
- **Fact — external consumers.** MCP entity search reads the override map for each request before filtering, so human prose affects both matching and output. Graph-query engines are built from fresh overrides; `AgentGraphStore` rereads the manifest and applies overrides without a persistent prose cache (`packages/mcp-server/src/mergedGraph.ts:27-38`, `packages/mcp-server/src/mergedGraph.ts:110-115`, `packages/mcp-server/src/tools/registerGraphQueryTools.ts:251-259`, `packages/mcp-server/src/agentGraphStore.ts:327-350`, `packages/mcp-server/src/agentGraphStore.ts:416-434`, `packages/mcp-server/src/agentGraphStore.ts:564-588`). The portable query CLI opens SQLite read-only per invocation, tolerates missing database/table, propagates malformed-database errors, and supplies overrides to entity queries; structural/context queries take separate paths (`packages/mcp-server/src/queryCli.ts:47-59`, `packages/mcp-server/src/queryCli.ts:70-108`). Description editing itself does not invoke RAG indexing or mutate legacy `entities`/observations (`src/extension.ts:548-575`, `src/services/agentGraph/agentEntityOverrideService.ts:47-75`).

### Important failure boundaries

1. **Fact:** edit reports a nullable update as failure; reset ignores its nullable result and announces success. Exceptions reach the wrapper's error message, skipping its subsequent view refresh (`src/ui/commands/entityCommands.ts:252-276`, `src/extension.ts:552-574`). **Inference:** disappearance/regeneration during the input dialog can fail an edit; a reset race can falsely announce restoration. A load failure after a persisted mutation can also return no entity: manifest parse/override-read errors are caught and converted to an empty snapshot (`src/services/agentGraph/agentGraphService.ts:148-167`, `src/services/agentGraph/agentGraphService.ts:248-257`).
2. **Fact:** SQL mutation precedes disk save, with no transaction/rollback in the override methods. Disk save exports and rewrites the whole database (`src/services/agentGraph/agentEntityOverrideService.ts:47-75`, `src/services/database.ts:165-177`). **Inference:** a failed save can leave changed in-memory prose but old/partial disk state; a later save may persist a change whose UI reported failure. Multiple writers can overwrite each other's full-database snapshots. This is not atomic, cross-process SQLite mutation.
3. **Fact:** the editor loads SQLite at initialization and its watcher targets only the manifest. MCP holds a read-only native SQLite connection opened at startup (`src/services/database.ts:37-43`, `src/extension.ts:265-281`, `packages/mcp-server/src/index.ts:13-16`, `packages/mcp-server/src/database.ts:119-134`). **Inference:** external SQLite edits are not automatically reloaded into the editor; live MCP visibility during sql.js whole-file rewrites/concurrency requires integration validation, despite fresh SELECTs. The first-workspace graph also differs from CodeLens/hover's per-document workspace-relative paths, creating a multi-root misassociation risk (`src/providers/codeLensProvider.ts:58-70`, `src/providers/hoverProvider.ts:101-113`).
4. **Fact:** entity timestamps remain manifest-generation timestamps, and merged MCP overview reports `agent.generatedAt`, not override time (`src/services/agentGraph/agentGraphService.ts:541-563`, `packages/mcp-server/src/mergedGraph.ts:74-84`). **Inference:** clients polling those timestamps alone can miss edits/reset. Exact-first lookup/delete can also leave alternate-spelling rows behind; a remaining unique alias may reappear after reset (`src/services/agentGraph/agentEntityOverrideService.ts:22-27`, `src/services/agentGraph/agentEntityOverrideService.ts:61-98`).

**Inspected tests:** delegation (`src/services/knowledgeGraphService.test.ts:131-166`), regeneration plus cross-group reset (`src/services/agentGraph/agentGraphService.test.ts:393-430`), portable spelling and case separation (`src/services/agentGraph/agentEntityOverrideService.test.ts:28-46`), and read-only CLI override visibility/corruption failure (`tests/querySkill.test.ts:86-97`). These do not establish editor-restart durability or concurrent-process safety.

## 2. MCP setup

### UI, workspace and child-process sequence

1. **Fact — availability/selection.** `activate` registers real setup/settings commands before checking for a workspace or initializing the graph database. Setup is reachable directly or through the settings QuickPick (`src/extension.ts:36-54`, `src/commands/mcpSetupCommands.ts:100-110`). It rejects untrusted workspaces and guards overlapping selection/install calls. A configured machine-scoped `workspacePath` wins; otherwise a picker offers local workspace folders or another local directory. It requires an absolute path, auto-detects Cursor from app name unless configured, shows project/config paths in a modal confirmation, then saves the selected path globally (`src/commands/mcpSetupCommands.ts:15-53`, `package.json:288-323`). **Inference:** unlike the editor graph's first-root default, setup can target another project; subsequent retries reuse the saved selection.
2. **Fact — preflight.** The service canonicalizes the workspace with `realpath`, requires a directory, reads existing client JSONC and validates it before downloads. It probes the configured external Node using `-p` JSON output, accepts stable Node 26 with minor >=1, and subsequently uses the reported `execPath`. npm-cli.js must be an absolute existing file supplied explicitly or found near real Node; npm's reported major must not be below 11. The Node directory is prepended to an inherited environment (`src/services/mcpSetupService.ts:91-115`, `src/services/mcpSetupService.ts:148-170`). **Inference:** malformed nonnumeric npm-version output passes the numeric `<11` check; this is not strict version validation.
3. **Fact — isolated install.** UI supplies `extensionPath/dist/mcp-server` and `globalStorageUri/mcp`. Each attempt creates a unique directory named using a hash of lock bytes plus Node path/version/platform/architecture, copies the bundle, and runs that Node with npm-cli.js `ci --omit=dev --audit --ignore-scripts` there—not in the business project. Windows supplies an explicit cmd script-shell setting, but process spawning remains shell-free (`src/commands/mcpSetupCommands.ts:64-71`, `src/services/mcpSetupService.ts:171-185`). The bundle builder produces unbundled Node-26 ESM, copies lock/package/npm configuration and shared graph modules, and adds audit/health helpers; package dependencies include MCP SDK and native `better-sqlite3` (`esbuild.js:11-25`, `scripts/build-mcp-runtime.cjs:18-36`, `packages/mcp-server/package.json:44-49`).
4. **Fact — gates.** After install, a separate production audit must succeed. Only an untruncated report with all expected nonnegative integer vulnerability counts, zero high/critical findings, zero exit code, no timeout and no report error is clean. Vulnerabilities fail immediately; unavailable audit never counts as success (`src/services/mcpSetupService.ts:186-196`, `scripts/audit-dependencies.cjs:56-71`, `scripts/audit-dependencies.cjs:121-146`). Next, UI initializes `graph.sqlite` only if missing, then service runs `health-check.mjs <canonical-workspace>` with a 45-second timeout before publication (`src/commands/mcpSetupCommands.ts:73-78`, `src/services/mcpSetupService.ts:197-200`). **Observed limitation:** `packages/mcp-server/scripts/health-check.mjs` is absent in this copy (observer read returned ENOENT). Its mandatory build-copy reference is `scripts/build-mcp-runtime.cjs:35`; the actual SQLite/protocol assertions cannot be verified. A build from this copy would fail that copy step; a staged runtime lacking the helper would fail before config publication.
5. **Fact — publication and eventual launch.** JSONC editing replaces only `servers.vibeknowledge` in `.vscode/mcp.json`, or `mcpServers.vibeknowledge` in `.cursor/mcp.json`; VS Code adds `type: stdio`. It preserves surrounding fields/comments and uses the resolved Node plus staged `dist/index.js`, `--workspace <canonical-root> --rag-mode none` (`src/services/mcpSetupService.ts:118-139`). Setup does not start a durable client-managed server: UI asks the user to trust/start/restart it (`src/commands/mcpSetupCommands.ts:82-87`). At launch, explicit workspace/RAG arguments take precedence over environment/settings; the server opens the database, creates graph stores, registers tools and connects stdio (`packages/mcp-server/src/config.ts:84-109`, `packages/mcp-server/src/index.ts:13-17`, `packages/mcp-server/src/server.ts:25-43`). No graph generation is part of setup.

### Failure handling and safe retries

- **Fact — bounded processes.** `spawn` uses argument arrays, `shell:false`, hidden windows and piped output. Default step timeout is five minutes; cancellation kills the child tree via Windows `taskkill` or a non-Windows process group, with a hard-stop fallback. Stdout return storage is limited to 256 KiB; diagnostic tail to 4,000 characters; common credential patterns are redacted, although logs stream all chunks. Progress cancellation and extension disposal abort the active controller (`src/services/mcpSetupService.ts:31-88`, `src/commands/mcpSetupCommands.ts:13`, `src/commands/mcpSetupCommands.ts:57-80`). **Inference:** redaction is best-effort pattern matching, not a guarantee against every secret format/chunk boundary.
- **Fact — automatic audit retries only.** Audit requests allow 10–120 seconds (default 60), with a process limit 15 seconds longer. Retryable DNS/network/timeouts/429/5xx/missing reports get at most three attempts and 2/4-second delays. Process-start, TLS, authentication/access and local-input errors do not retry. Registry/ping diagnostics are not a security verdict; the script does not weaken TLS or auditing (`scripts/audit-dependencies.cjs:3-12`, `scripts/audit-dependencies.cjs:74-106`, `scripts/audit-dependencies.cjs:121-146`). Service encloses the helper in `3 × (request timeout + 15s) + 45s`, i.e. 270s by default and 450s at the maximum (`src/services/mcpSetupService.ts:187-195`). **Inference:** repair credentials/CA/Node/configuration or affected dependencies before rerunning; network failures can be retried without bypassing the gate.
- **Fact — preservation.** Before publication, setup compares current config text with its initial text and refuses detected edits. A nonempty original receives an exclusive timestamped `.bak`; replacement is an exclusive temporary write then rename. Failure removes only this attempt's unique directory; success and older installations remain (`src/services/mcpSetupService.ts:201-218`). **Inference:** normal install/audit/health failures preserve the working client entry, making rerun safe for that entry. Retries are fresh installs, not resume/reuse, so successful generations accumulate. The saved global workspace path and a newly initialized database can remain after failure; “previous configuration preserved” does not mean no side effects (`src/commands/mcpSetupCommands.ts:52`, `src/commands/mcpSetupCommands.ts:73-78`).
- **Inference — limits to the safety guarantee.** The text comparison and rename are not an atomic compare-and-swap: edits after the comparison can be overwritten; same-process UI serialization is not a cross-window lock. The final abort check precedes asynchronous publication, so late cancellation need not stop rename. `published` is set only after temporary cleanup; a cleanup failure after a successful rename could remove the now-referenced runtime in the outer finally. The UI's blanket “previous configuration was preserved” error also covers post-success UI/open-file failures, so inspect actual config/logs before assuming rollback (`src/services/mcpSetupService.ts:200-218`, `src/commands/mcpSetupCommands.ts:82-97`).

**Inspected tests:** JSONC preservation/client shape and Node constraints (`tests/mcpSetup.test.ts:8-43`); mocked order, isolation, backups, timeout forwarding, stage failure cleanup, concurrent-edit refusal and cancellation (`tests/mcpSetup.test.ts:73-164`); actual argument passing/process cancellation test bodies (`tests/mcpSetup.test.ts:167-179`); early registration/trust/setting forwarding (`tests/mcpSetupCommands.test.ts:53-80`); expected bundle assets (`tests/mcpRuntimeBundle.test.ts:11-29`). Mocked orchestration does not prove successful registry access, native binary loading, real client trust/start, or the absent health helper's behavior.
