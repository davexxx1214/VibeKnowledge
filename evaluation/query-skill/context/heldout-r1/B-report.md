# Description editing and MCP setup

Read-only source investigation; no tests, installs, network calls, or configuration changes were performed. Citations below are workspace-relative source paths and line numbers. **Code facts** describe inspected implementations; **inferences** describe their consequences or unverified risks. The installed query skill supplied feature briefs, followed by direct source verification.

## 1. Entity descriptions

### Edit/reset → storage → effective graph

**Code facts.** Explorer menus expose edit for `entity`/`agentEntity` and restore only for `agentEntity`; CodeLens invokes edit with the entity ID (`package.json:200–209`, `src/providers/codeLensProvider.ts:42–47`). The handler resolves a tree item's entity, an object ID, or a string ID. Edit falls back to an aggregate-entity picker, prefills the effective description, treats `undefined` as cancellation, and accepts an empty string. Restore has no picker and silently returns for an unresolved/non-Agent entity (`src/ui/commands/entityCommands.ts:224–287`).

`KnowledgeGraphService.getEntity` resolves aggregate IDs and independent-group IDs; update/reset delegate to `AgentGraphService` and reread the entity (`src/services/knowledgeGraphService.ts:192–205`, `261–284`). The Agent service requires both a current entity and override store. It upserts/deletes using the entity's stable **key**, then clears/reloads its snapshot—not the generated file (`src/services/agentGraph/agentGraphService.ts:108–115`, `143–167`).

The override store uses parameterized SQL in `agent_entity_overrides(agent_key PRIMARY KEY, description, updated_at)`. Upsert changes only that exact key; reads prefer an exact match, then a unique normalized-identity match. Delete removes the exact row or that same unique fallback; ambiguous fallback matches are not chosen (`src/services/agentGraph/agentEntityOverrideService.ts:22–98`, `src/services/database.ts:118–129`). SQL.js loads `.vscode/.knowledge/graph.sqlite` into memory; saving exports and synchronously rewrites the whole database (`src/services/database.ts:17–43`, `165–177`).

Snapshot construction overlays each group's occurrence using the stable key, despite group-specific IDs. `undefined` alone means no override; `''` remains a human override. Metadata retains `generatedDescription` and `descriptionSource`, so reset reveals each group's **latest generated prose**, not the prose that existed when editing began (`src/services/agentGraph/agentGraphService.ts:537–574`). Aggregate views deduplicate normalized identities, whereas `getGroups()` retains occurrences (`src/services/knowledgeGraphService.ts:67–84`, `147–163`). The extension creates these services/database for the **first workspace folder**, not the MCP target setting (`src/extension.ts:48–69`, `174–183`).

### Consumers and invalidation

| Consumer | How the changed prose reaches it |
| --- | --- |
| Explorer tooltip and description search | Both command wrappers refresh the tree; its refresh reloads the graph and fires tree-data change. Filtering and tooltips use effective descriptions (`src/extension.ts:548–577`; `src/providers/treeDataProvider.ts:70–78`, `172–174`, `336–347`). |
| Open graph panel, including repeated group occurrences | Wrapper calls `GraphView.refresh()`, which sends newly collected groups and effective descriptions. The client accepts `graphData` and renders the selected group's entity data (`src/ui/webview/graphView.ts:124–125`, `263–270`, `457–478`, `1287–1289`, `1449–1504`). |
| CodeLens | Wrapper fires the CodeLens change event; the provider rereads file entities. Labels compact prose, falling back to entity name for empty/whitespace-only descriptions (`src/providers/codeLensProvider.ts:28–32`, `73–74`; `src/providers/knowledgeCodeLensModel.ts:32–55`). |
| Hover, details, exports/context | Hover looks up the current graph on each request; details and exports likewise use the unified service. Existing detail output/export artifacts are not regenerated by the wrappers (`src/providers/hoverProvider.ts:25–44`; `src/ui/commands/entityCommands.ts:29–34`, `327–361`; `src/services/exportService.ts:684–705`). |
| MCP entity search / graph queries | Merged search fetches current override rows, applies them before matching descriptions, and deduplicates. Graph-query engines likewise receive overridden entities per construction (`packages/mcp-server/src/mergedGraph.ts:26–38`, `110–115`; `packages/mcp-server/src/agentGraphStore.ts:327–350`; `packages/mcp-server/src/tools/registerGraphQueryTools.ts:251–259`). |

The Agent cache normally keys only on manifest `mtimeMs:size`. Explicit mutation refresh therefore matters even though `agent-graph.json` has not changed. A watcher refreshes tree/panel/CodeLens on generated-manifest create/change/delete; cancellation and nonthrowing command no-ops also reach the wrapper refreshes (`src/services/agentGraph/agentGraphService.ts:232–258`, `src/extension.ts:265–282`, `548–577`).

### Important limits and failure cases

- **Code fact:** edit reports a null update as an error; reset ignores its nullable result and announces success. Thrown errors are caught by the command wrapper, bypassing its remaining refresh calls (`src/ui/commands/entityCommands.ts:252–275`, `src/extension.ts:552–573`).
- **Inference:** a disk-save failure can leave an in-memory SQL mutation without durable persistence or cache invalidation: mutation occurs before `save()`, and refresh occurs afterward, with no transaction around this path (`src/services/agentGraph/agentEntityOverrideService.ts:47–75`, `src/services/agentGraph/agentGraphService.ts:153–166`). Missing/invalid generated data yields empty snapshots; parse or override-read failures are cached as generation errors rather than serving the previous graph (`src/services/agentGraph/agentGraphService.ts:232–258`).
- **Inference:** renaming a stable identity can strand its old override. Editing a new spelling creates a distinct exact-key row rather than migrating an older normalized match; reset removes one row, so a surviving alias can become visible afterward. This follows from exact-key upsert and exact-first/unique-fallback lookup/delete (`src/services/agentGraph/agentEntityOverrideService.ts:22–98`).
- **Code fact/inference:** empty human prose is valid but rendered differently: Explorer says `(empty description)`, CodeLens uses the name, and hover/details omit the description section. Those are presentation fallbacks, not reset (`src/providers/treeDataProvider.ts:75–76`, `src/providers/knowledgeCodeLensModel.ts:37`, `src/providers/hoverProvider.ts:42–45`, `src/ui/commands/entityCommands.ts:338–340`).
- **Inference:** external database changes have no demonstrated live editor invalidation/reload path: the inspected watcher observes the manifest, while SQL.js loads SQLite once. MCP retains a read-only native SQLite connection while the extension rewrites the whole file, so per-request override reads are not evidence that cross-process concurrency is safe (`src/extension.ts:265–282`, `src/services/database.ts:37–43`, `171–173`, `packages/mcp-server/src/database.ts:119–134`, `380–391`).
- **Code fact:** human edits do not advance entity `updatedAt` (it comes from manifest generation), and MCP merged overview reports `agent.generatedAt` as `lastUpdatedAt`; that timestamp cannot be used as a reliable description-change signal (`src/services/agentGraph/agentGraphService.ts:541`, `562–573`, `packages/mcp-server/src/mergedGraph.ts:74–84`).

**Test evidence, inspected not run:** cross-group persistence through regeneration and latest-prose reset (`src/services/agentGraph/agentGraphService.test.ts:393–430`); portable-key/case/ambiguity behavior (`src/services/agentGraph/agentEntityOverrideService.test.ts:28–46`, `50–75`); CLI human prose, unchanged SQLite bytes, and corrupt-database failure (`tests/querySkill.test.ts:86–97`).

## 2. MCP setup

### UI and workspace selection

**Code facts.** Activation registers setup/settings before the no-workspace return and database initialization, so setup is not contingent on a functioning graph database (`src/extension.ts:36–57`). `knowledge.setupMcp` and the settings menu call the same installer. A per-registration `selecting`/`active` guard prevents overlapping UI runs; another invocation only shows the log (`src/commands/mcpSetupCommands.ts:8–20`, `100–111`).

Installation requires workspace trust. A configured `knowledgeGraph.mcp.workspacePath` takes precedence; otherwise a picker lists local workspace folders plus a folder chooser. The selected/configured path must be absolute. Client `auto` detects Cursor by app name; otherwise VS Code is used. A modal confirms the project/config paths before the target setting is saved globally (`src/commands/mcpSetupCommands.ts:23–53`). All MCP settings are machine-scoped (`package.json:288–323`). Unlike description services, setup can target a different project; the service canonicalizes it with `realpath`, requires a directory, and validates existing JSONC before downloading (`src/services/mcpSetupService.ts:154–159`).

### Child-process and publication sequence

**Code facts.** The UI passes bundled `extension/dist/mcp-server`, global extension storage `mcp`, runtime settings, an abort signal, logging, and a missing-database initializer (`src/commands/mcpSetupCommands.ts:57–79`). Then:

1. Probe the external Node for version, resolved `execPath`, ABI/platform/architecture. Accept stable Node `>=26.1.0 <27`; find absolute `npm-cli.js` explicitly or near real Node. Run npm through that same Node, require major 11+, and prepend Node's directory to inherited subprocess PATH (`src/services/mcpSetupService.ts:91–115`, `160–170`).
2. Hash lock bytes plus Node path/version/platform/architecture, create a **unique** staging directory under extension storage, copy the bundle, and run `npm ci --omit=dev --audit --ignore-scripts` there—not in the target project (`src/services/mcpSetupService.ts:171–185`). The bundle build emits Node-26 ESM and copies metadata/lock/`.npmrc`, shared modules, audit and health helpers; native dependencies are installed locally rather than shipped as another machine's `node_modules` (`scripts/build-mcp-runtime.cjs:5–36`, `packages/mcp-server/package.json:44–49`).
3. Run a separate production audit gate. A complete nontruncated valid report, zero high/critical findings, exit zero, no timeout, and no report error are required. High/critical findings fail immediately. Retryable DNS/network/service/timeout/malformed-report failures get at most three attempts with 2/4-second backoff; process-start, TLS, authorization, and local-input failures are not retried. Request timeout is validated at 10–120 seconds; each audit subprocess gets another 15 seconds, and setup provides a larger enclosing deadline (`scripts/audit-dependencies.cjs:3–12`, `56–87`, `121–146`; `src/services/mcpSetupService.ts:150–153`, `187–195`). Diagnostic npm ping is explicitly not a security verdict (`scripts/audit-dependencies.cjs:90–106`).
4. Initialize `.vscode/.knowledge/graph.sqlite` only if absent, then invoke `health-check.mjs <canonical-workspace>` with a 45-second limit. Check cancellation before publishing (`src/commands/mcpSetupCommands.ts:73–78`, `src/services/mcpSetupService.ts:196–200`). No graph generation is performed.
5. Reread config and refuse detected changes since the initial read. Use JSONC edits to replace only `servers.vibeknowledge` in `.vscode/mcp.json`, or `mcpServers.vibeknowledge` in `.cursor/mcp.json`. Preserve other fields/comments/trailing commas. The replacement entry uses resolved Node, staged `dist/index.js`, `--workspace`, and `--rag-mode none`; VS Code additionally gets `type: stdio` (`src/services/mcpSetupService.ts:118–139`, `201–203`).
6. Back up nonempty prior text using a timestamped exclusive-create `.bak`, exclusively create a unique temporary file, then rename it over config. Success retains the new and older installations. Failure removes only this attempt's staging directory (`src/services/mcpSetupService.ts:204–218`). The client must still trust and start/restart the configured server (`src/commands/mcpSetupCommands.ts:82–86`).

### Errors, retries, and boundaries

`runProcess` uses argument arrays, `shell:false`, `windowsHide:true`, ignored stdin, and captured output. Abort/timeout attempts child-tree termination (`taskkill /t /f` on Windows; process-group signals elsewhere), escalating after three seconds. Nonzero exits and process-start errors reject; stdout/error tails are bounded, and common credential patterns are redacted before logging (`src/services/mcpSetupService.ts:31–88`). UI cancellation and extension disposal abort the active controller; the catch logs the error and offers settings, and `finally` releases the run guard (`src/commands/mcpSetupCommands.ts:13`, `57–62`, `88–97`).

**Safe-retry inference:** fix Node/npm/config/platform problems or approved registry/proxy/CA connectivity, then rerun the same UI command. Do not disable audit or TLS. Each attempt revalidates current config and creates a fresh stage; old runtime paths remain usable. Failed setup is not a zero-side-effect transaction: global workspace selection, a newly initialized database, storage directory, and possibly a backup can survive failure (`src/commands/mcpSetupCommands.ts:52`, `73–78`; `src/services/mcpSetupService.ts:161`, `173`, `197–218`). Reconfiguration replaces the entire VibeKnowledge entry, including previous custom entry fields—not merely its executable (`src/services/mcpSetupService.ts:132–139`).

**Concurrency inference:** the guard is local to this UI registration, and config comparison is optimistic, not a filesystem lock/CAS. An edit after comparison but before rename can still race; cancellation after the final signal check can likewise arrive during publication. Avoid simultaneous setup/config edits (`src/commands/mcpSetupCommands.ts:10–16`, `src/services/mcpSetupService.ts:200–213`). The UI's blanket “previous configuration was preserved” message is stronger than the whole control flow: failures after successful publication, such as opening the config, also enter that catch (`src/commands/mcpSetupCommands.ts:82–95`).

**Verification limit:** direct source read confirmed `packages/mcp-server/scripts/health-check.mjs` is absent in this copy. Build code requires that exact helper (`scripts/build-mcp-runtime.cjs:35`); setup only observes its process exit (`src/services/mcpSetupService.ts:198–200`). Its claimed SQLite/protocol/tool checks and end-to-end bundle completeness cannot be verified here. A source build would fail when copying the missing helper if earlier build steps succeed; an already-packaged runtime's completeness was not established.

**Test evidence, inspected not run:** JSONC/client shapes and Node bounds (`tests/mcpSetup.test.ts:8–43`); isolated install/audit/health ordering and backup (`82–108`); stage-failure cleanup, timeouts, concurrent-edit refusal, cancellation, malformed config, real argument passing and process cancellation (`110–179`); early UI registration/trust/timeout forwarding (`tests/mcpSetupCommands.test.ts:53–80`). Most orchestration tests inject a mocked runner; bundle tests state expected helpers/assets (`tests/mcpRuntimeBundle.test.ts:11–29`) but do not establish that this copy successfully builds.
