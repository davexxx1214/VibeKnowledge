### Concrete service dependencies

- **Author/articles:** `ArticleService.findAll()` joins the string path `article.author`, filters on `article.authorId`, and also uses that column in its favorited branch ([article.service.ts:26](D:/workspace/VibeKnowledge/.vscode-test/query-skill-ab-76VCKe/A/src/article/article.service.ts:26), lines 30–46). `findFeed()` filters on `article.authorId` ([article.service.ts:66](D:/workspace/VibeKnowledge/.vscode-test/query-skill-ab-76VCKe/A/src/article/article.service.ts:66), line 77). Renaming the relation or changing join-column mapping therefore affects both relation paths and raw column strings.
- **Article creation:** `ArticleService.create()` initializes `article.comments`, saves the article, explicitly loads `relations: ['articles']` on its user query, pushes into `author.articles`, and saves the user; it does not directly assign `article.author` ([article.service.ts:170](D:/workspace/VibeKnowledge/.vscode-test/query-skill-ab-76VCKe/A/src/article/article.service.ts:170), lines 177–184). `UserService.create()` initializes `newUser.articles = []` before saving ([user.service.ts:55](D:/workspace/VibeKnowledge/.vscode-test/query-skill-ab-76VCKe/A/src/user/user.service.ts:55), lines 60–68).
- **Comments:** `addComment()` loads an article, pushes a new comment into `article.comments`, then explicitly saves the comment and article; it does not directly set `comment.article` ([article.service.ts:101](D:/workspace/VibeKnowledge/.vscode-test/query-skill-ab-76VCKe/A/src/article/article.service.ts:101)). `deleteComment()` searches/splices that collection, explicitly deletes the comment, and saves the article ([article.service.ts:114](D:/workspace/VibeKnowledge/.vscode-test/query-skill-ab-76VCKe/A/src/article/article.service.ts:114)). `findComments()` returns `article.comments` after a plain `findOne` ([article.service.ts:165](D:/workspace/VibeKnowledge/.vscode-test/query-skill-ab-76VCKe/A/src/article/article.service.ts:165)). These methods depend on the collection field and its loading behavior; changing the inverse link affects the mapping they use.
- **Favorites:** `findAll()` reads `author.favorites.map(...)` after a user lookup ([article.service.ts:43](D:/workspace/VibeKnowledge/.vscode-test/query-skill-ab-76VCKe/A/src/article/article.service.ts:43)). `favorite()` and `unFavorite()` search and push/splice `user.favorites`, save the user, and separately update/save `article.favoriteCount` ([article.service.ts:131](D:/workspace/VibeKnowledge/.vscode-test/query-skill-ab-76VCKe/A/src/article/article.service.ts:131), [article.service.ts:147](D:/workspace/VibeKnowledge/.vscode-test/query-skill-ab-76VCKe/A/src/article/article.service.ts:147)). Those user lookups do not explicitly request `favorites`, and its decorator is not eager; source therefore does not establish that the accessed collection is populated. `UserService.update()` explicitly deletes `toUpdate.favorites` before merging and saving ([user.service.ts:74](D:/workspace/VibeKnowledge/.vscode-test/query-skill-ab-76VCKe/A/src/user/user.service.ts:74)).
