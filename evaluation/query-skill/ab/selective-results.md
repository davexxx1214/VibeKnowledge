# 选择性查询 Skill：第二轮独立 A/B

日期：2026-09-04。对照 [第一轮图谱优先实验](results.md)。

**本轮仍未观察到 token 净收益。** 选择性规则生效了：B 两项任务都选择直接源码调查，图谱调用为 **0**。但 B 实际工具文本比 A 多 **39.2%**，模型累计总 token 多 **67.7%**。不能把“避免了图谱调用”直接等同于“整体更省”。

## 实验保持与变化

两侧都是全新、无历史继承的独立 Agent，模型仍为 `gpt-5.6-sol / xhigh`。任务、顺序、样例快照、Node 26.1.0、公共观察工具、Jest 配置和独立验收均与第一轮相同：

1. 为 GET /tags 实现仓库 `tag ASC` 排序，保留接口和实体数组，补无数据库的服务/控制器单测。
2. 分析 ArticleEntity、Comment、UserEntity 的 ORM 字段、关系所有权、加载/删除声明与具体服务引用。

A 是重新运行的源码检索基线，不是复用上轮数字。B 先读修改后的 Skill，再自主决定是否查询图谱；未告知任何上轮结果、预期答案或节省目标。没有限制源码文件数，也没有禁止补充必要调查。

Skill 修改为：已知文件/符号或小范围声明检查直接读源码；不明确的跨模块依赖、多跳影响或循环才考虑图谱；不再自动先执行 overview；重复已有证据时不继续查询。仅修改说明与触发描述，没有修改查询算法。

**范围限制：本轮测的是“已加载 Skill 规则后，选择是否查询”，不是“仅凭发现元数据决定不加载 Skill”。** B 的完整规则加载成本被计入，未通过假设排除。两项任务均未执行图谱算法，因此本轮也不能证明复杂场景下实际图谱查询的收益。

B 多读了 package.json、ProfileService，并做了更多搜索；其报告也覆盖了额外的返回实体形状影响。两侧核心结论均符合要求。这些是本次自主调查轨迹的差异，**不是图谱调用成本，也不能全部归因于 Skill 文案**。说明正文只解释其中 619 token 的差值。

阶段合计：标签任务 A/B 为 1,131/3,148；关系分析为 5,716/6,386。两侧耗时约 136/188 秒，仅作记录；并行调度、模型生成和缓存会影响用时。

## 结论与下一步

- 选择性规则能够让 Agent 在任务范围明确时不查询图谱；该分支已得到行为验证。
- 相对一个正常直接搜索源码的 Agent，本轮没有证明节省，不能承诺固定百分比收益。
- 不应通过删除必要验证、只挑某个 token 分项，或将不同轮次的 B 相互相减来证明优化有效。
- 两轮各只有一对 Agent，均是同一小型样例上的两项明确任务；不是统计意义上的重复试验，也没有覆盖未知依赖范围的大工程。
- 如果继续评估，应另测发现阶段“不加载 Skill”的路由，并单独设置真正需要多跳/全局图算法的任务。前者只是减少无用开销；后者才可能检验图谱本身是否替代了源码调查。不要把两者混为同一收益。

本次保留了更窄的选择性规则，但没有因负结果继续改查询算法、扩大题目或挑选有利重跑。源码、Skill 和 CLI 的 23 项相关回归检查通过。
