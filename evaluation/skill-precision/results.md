# 简报证据链与符号级上下文：针对性验证

日期：2026-09-05。范围仅为本轮两项修改；未恢复已回退的排序、事实筛选或增量会话实验。

## 结论

- **依赖定位粒度改善**：精确方法查询不再投影成整个文件的邻域；保留同文件辅助方法、它们的直接依赖、真实调用者和图谱关联测试。文件查询保持原行为。
- **未证明进一步省 token**：三条预先固定的方法查询正文合计 2,809 → 2,909 个 token，增加 **3.6%**。输出更明确，但不一定更短。
- **未证明简报准确率提升**：两个独立作者、一个独立盲评者的小样例中，新旧规范都是 **8/8**、零重大错误，各有一项轻微表述修正。

这不是完整 Agent 任务 A/B，也不是新的发布门槛通过声明。不能把较少的候选文件当作准确率、完整度或后续阅读 token 的实测收益。

## 实现边界

简报生成规范现在要求在相关情形下核对：公开入口的真实注册/可达性、跨文件生产值与消费条件、失败/清理顺序、测试的实际断言。事实仍使用原有类型和证据格式；未知前提需收窄陈述或标为推断。这些详细规则只在生成简报时加载，不加入每次查询输出。

`context --selector path#Class.method` 沿该符号的关系查询，同文件边也占一个 depth。类型、receiver、容器、文件、import/export 为终止提示，不展开整个类/文件；报告 owner/constructor 位置供共享状态核查。它不是执行流、控制流或完整调用图。`get_task_context` 复用同一实现。

测试候选仍不代表覆盖率。当前提取器对 `new Service().save()` 这类表达式可能只解析到导入类而非方法；本轮新增回归记录此限制，没有通过类成员展开捏造方法覆盖，也没有修改提取器。源文件哈希检查仍遍历全部已索引文件，未改为局部新鲜度检查。
